1. ASOS 데이터 유출 — 앱 푸시 알림이 공격자의 '메가폰'이 됐다: "ASOS HACKED"

영국 패션 이커머스 ASOS가 고객 커뮤니케이션에 쓰는 제3자 플랫폼이 무단 접근당했다고 확인했다. 공격자는 ASOS 모바일 앱 푸시 알림을 통해 직접 유출 협박 메시지를 발송했다.

  • 사건 경위: 10월 6일 오전 5시(ET)경 다수 고객이 앱 알림으로 “ASOS HACKED”를 수신했다. 메시지 전문은 “Dear Asos DPO and IT, we have fully compromised the Snowflake instance. Engage with us, or we will leak it.” — 공식 앱을 통해 발송됐고, Reddit 등에 동일 알림이 다수 보고됐다.
  • 유출 주장: 알림은 ‘Xuanye group’이라 자칭하는 위협 행위자의 텔레그램 채널로 연결된다. 이들은 ASOS의 Snowflake 데이터 웨어하우스 환경을 장악했다고 주장하며, 결제 정보는 안전하다고 했다가 이후 “FINAL STATEMENT”에서 고객 정보를 탈취했다고 번복했다.
  • 미확인 부분: ASOS는 제3자 플랫폼 무단 접근과 ‘이름·연락처 등 기본 개인정보 노출 가능성’은 인정했으나, Snowflake 침해 주장과 피해 규모는 확인하지 않았다. 결제카드·계정 비밀번호는 영향 없다고 밝혔다.
  • 대응: ASOS는 인앱 공지로 무단 알림을 무시하고 외부 링크를 클릭하지 말라고 안내했다.
  • 시사점: 마케팅·알림 인프라가 곧 신뢰된 방송 채널이라는 점이 다시 드러났다. 2024년 대규모 Snowflake 고객사 캠페인 이후 클라우드 데이터 웨어하우스 자격증명 탈취 위협이 재부상하는 신호로 읽힌다.

2. 니혼케이자이신문(Nikkei) 직원 이메일 계정 2건 침해 — 취재원에 9,000건 피싱 발송

세계 최대 경제지 중 하나인 Nikkei가 직원 이메일 계정 2건이 침해당했다고 주말에 공지했다. 한 계정은 대량 피싱 발송에 악용됐다.

  • Google Workspace 침해: 7월 말 직원 계정이 무단 접근돼 임직원·거래처 1,646명의 이름·이메일이 노출됐다. 8월 초 Google 통보로 인지한 뒤 비밀번호를 변경했다.
  • Microsoft 365 침해: 9월에는 다른 직원 계정에 접근해, 9월 30일 사내 직원과 취재원에게 악성 링크가 담긴 약 9,000통의 피싱 메일을 발송했다. Nikkei는 비밀번호 변경 후 추가 무단 로그인이 없으며 수신자에게 개별 연락해 삭제를 요청했다고 밝혔다.
  • 귀속: 특정 위협 그룹은 아직 지목되지 않았고, 두 사건의 연관성도 공개되지 않았다.
  • 반복되는 침해 이력: 2025년 Slack 침해(임직원·거래처 1.7만 명), 2022년 싱가포르 법인 랜섬웨어, 2019년 BEC로 약 2,900만 달러 손실 등 최근 수년간 보안 사고가 이어졌다.
  • 시사점: 이메일 계정 침해 대응은 비밀번호 재설정으로 끝나지 않는다. 활성 세션·OAuth 권한·전달 규칙·MFA 설정·로그인 로그를 함께 점검해야 하며, 한 계정 장악이 사내 대량 피싱의 발판이 된다는 점이 핵심이다.

3. Ninja Forms·WPC Product Bundles 결함 실제 익스플로잇 — '보이지 않는 관리자'와 4중 백도어

WordPress 플러그인 2종의 저장형 XSS 결함이 실제로 익스플로잇돼 백도어 설치와 관리자 계정 생성에 악용되고 있다고 Patchstack이 밝혔다. 인증된 세션만 있으면 발동되는 고위험 결함이다.

  • 대상: CVE-2026-94504 — Ninja Forms 3.15.3 이하(설치 사이트 50만 개 이상), CVE-2026-93836 — WPC Product Bundles for WooCommerce 8.6.6 이하(3만 개 이상).
  • 공격 흐름: 두 사이트 모두 imgcdn1[.]com에서 동일한 JavaScript(x.js)를 전달해 동일 위협 행위자로 판단된다. 악성 JS를 WooCommerce 주문 데이터나 Ninja Forms 제출물에 심고, 관리자가 콘텐츠를 로드하면 인증 세션으로 실행된다.
  • 감염 후 동작: 합법적인 WordPress 함수로 nonce를 탈취한 뒤, ‘MediaPress Labs’의 “WP Smart Thumbnails 1.2.4”로 위장한 악성 플러그인을 설치하고 관리자 계정을 생성한다.
  • 4중 접근 경로: ① 눈에 보이는 관리자 계정 ② 대시보드 사용자 목록에서 숨겨진 관리자 계정 ③ 사이트 최고참 관리자로 로그인되는 비밀 URL ④ 악성 플러그인 PHP 파일 직접 요청으로 열리는 무인증 파일 매니저.
  • 지속성: 악성 플러그인을 삭제해도 숨은 계정과 비밀 URL은 백데이트된 타임스탬프의 보조 플러그인으로 계속 동작한다. Patchstack은 “사이트 소유자가 볼 수 없는 완전한 권한의 관리자”라고 설명했다.
  • 대응: WPC Product Bundles 8.6.7+, Ninja Forms 3.15.4+로 업그레이드. 단 업데이트는 추가 익스플로잇 차단일 뿐 기존 감염은 정리되지 않으므로 침해 징후 점검이 필요하다. 익스플로잇은 10월 4일(WPC) → 10월 5일(Ninja Forms) 순으로 관측됐다.

4. 한국·대만 통신·네트워크 장비 겨냥 리눅스 백도어 — 이메일 보안 제품으로 위장

한국과 대만의 통신사·네트워크 장비를 노린 리눅스 백도어가 이메일 보안 제품과 정상 프로세스의 이름·관습을 그대로 도용해 탐지를 회피하고 있다고 Rapid7이 분석했다.

  • 위장 대상: BPFDoor 변종은 한국의 대표 스팸 차단 솔루션 SpamSniper의 PID 파일을 사칭하고 10개 리눅스 데몬명을 번갈아 사용한다. 또 다른 샘플은 통신 프로비저닝 플랫폼 명명 관습을 흉내 내 프로세스명을 ora_ppmond(오라클 PMON ora_pmon_* 차용)로 설정한다.
  • 표적별 도구: 한국 표적에는 BPFDoor 신변종 + BPF Rekoobe 빌드, 대만 장비에는 드로퍼로 배포되는 신종 리눅스 임플란트 AVERAT가 사용됐다.
  • 기법 진화: BPFDoor는 BPF로 인바운드 트래픽을 감시하다 ‘매직 패킷’에만 반응한다. 정적 시그니처(Suricata/Snort)가 L4 이상 트래픽을 잡자, 운용자들은 매직 패킷을 일반 HTTPS POST로 감싸고 통신 환경에 흔한 SSL 오프로딩을 악용해 DPI를 우회하기 시작했다.
  • 획득 기능: 트리거되면 TinyShell 세션을 열어 대화형 셸·업로드·다운로드를 지원한다. Rekoobe 기반 백도어는 소스/목적지 포트 25(메일)의 TCP/UDP/SCTP IPv4 및 UDP IPv6 트래픽을 가로채 유출에 활용한다.
  • 귀속 정황: 활동은 2021년부터 중동·아시아 통신사를 겨냥해 온 Red Menshen(Earth Bluecrow·DecisiveArchitect·Red Dev 18)과 연계된다. TinyShell은 중국 연계 클러스터(Liminal Panda, UNC3886/Fire Ant, Velvet Ant)가 과거 사용한 도구다.
  • 시사점: ‘합법 제품 이름 빌리기’는 파일명 수준을 넘어 실제 제품 정체성·관습까지 모방하는 단계로 진화했다. 통신·엣지 장비 운영자는 프로세스명·PID 파일만으로 정상 여부를 판단해서는 안 된다.

6. [취약점] Atlassian 8개 제품 치명 결함(CVE-2026-21589, 9.3) + LibreOffice·OpenOffice 무경고 코드 실행

셀프호스팅 엔터프라이즈 도구와 데스크톱 문서 앱에서 각각 ‘경계를 다시 검증하지 않는’ 결함이 나왔다.

  • Atlassian(경로 순회): 셀프호스팅 Data Center 8개 제품의 CVE-2026-21589(CVSS 9.3, 10월 5일 공개)는 로그인 없는 공격자가 각 제품 웹앱 루트 디렉터리의 특정 파일을 읽을 수 있게 한다(파일의 정확한 이름·경로를 알아야 하며 디렉터리 목록은 불가). 일부 구성에서 루트 디렉터리에 민감 파일이 있을 수 있어 위험이 크다.
  • 수정 버전: Bitbucket DC 9.4.26/10.2.8/10.5.1, Confluence DC 9.2.26/10.2.19, Jira Software DC 9.12.40/10.3.26/11.3.12, Jira Service Management DC 5.12.40/10.3.26/11.3.12, Bamboo DC 10.2.24/12.1.12, Crowd DC 6.3.7/7.0.3/7.1.7/7.2.4, Crucible·Fisheye 4.9.15. 클라우드 제품은 이미 패치됨.
  • 완화(업그레이드 불가 시): 인스턴스를 오프라인으로 두거나 외부 접근을 차단하고, URL에 ..이 /·\·::와 인접한 요청을 막는 룰(WAF·리버스 프록시, 또는 Confluence/Jira/Bamboo/Crowd의 Tomcat RewriteValve, Bitbucket의 urlrewrite.xml)을 적용한다.
  • LibreOffice·Apache OpenOffice: 악성 스프레드시트를 열기만 하면 매크로 경고 없이 공격자 코드가 실행된다(Java 지원이 켜져 있을 때). LibreOffice는 CVE-2026-63277을 10월 5일 수정해 26.2.5 / 26.8.0으로 업그레이드를 권고하며, Apache OpenOffice는 CVE-2026-59265가 4.1.16 이하 전 버전에 영향받고 4.1.17이 아직 테스트 중이다(그때까지 Java 끄기).
  • 원리: 스프레드시트의 ‘데이터베이스 범위’가 외부 ODB 파일을 자동 새로고침하고, ODB가 JDBC 드라이버 JAR을 지정하면 프로그램이 이를 내려받아 자기 프로세스 안에서 실행한다. 각 기능은 정상이지만 결합하면 문서 신뢰 확인 없이 코드 실행에 도달한다.
  • 연구: V12팀의 Rick de Jager와 Codean Labs의 Thomas Rinsma·Edoardo Geraci가 독립적으로 보고했고, 현재는 PoC 단계로 실제 공격 사용 증거는 없다(Windows·Linux 공통).

8. [취약점] 공개 MCP 서버 15,465개 감사 — '프로토콜이 아니라 위임한 신뢰'가 공격면

OX Security가 5개 MCP 레지스트리에서 공개 인덱싱된 MCP 서버 15,465개를 분석하고(중복 제거 후 고유 호스트명 5,095개) 생태계 거버넌스 부재를 보고했다. (THN 파트너 기고 분석)

  • 관할 이탈: 호스트명의 15.6%가 미국 외 인프라에 있으며 중국 19개, 러시아 18개가 포함된다. 에이전트가 이 서버에 연결하면 보안팀이 승인하지 않은 관할로 데이터를 전송할 수 있다.
  • 개인 PC·홈 네트워크: 0.45%가 소비자 터널링 서비스(주로 ngrok-free)를 통해 트래픽을 라우팅한다. 즉 공개 목록에 오른 서버가 개인 머신·홈 네트워크에서 돌아간다.
  • 만료 도메인 승계: 2.3%의 도메인이 더 이상 해석되지 않으며, 그중 6개는 연 4~12달러면 누구나 등록할 수 있는 만료 도메인이다. 새 소유주는 기존 서버 신원과, 아직 그 주소를 호출하도록 설정된 모든 에이전트의 요청을 그대로 물려받는다.
  • 구조적 문제: MCP 마켓플레이스에는 Google Play의 Bouncer 같은 검증이 없다(누구나 서버를 퍼블리시 가능). 설령 리뷰가 있어도, 원격 MCP 서버는 공개 저장소와 전혀 다른 백엔드 코드를 실행할 수 있어 코드 리뷰로는 잡히지 않는다.
  • 시사점: “프로토콜이 문제가 아니라 우리가 위임한 신뢰가 문제”다. 마켓플레이스가 검증·코드 서명·출처 확인을 갖추기 전까지는 기업이 직접 통제(허용목록·데이터 상주·IAM·공급망 감사)해야 한다.

9. [패치] 오늘이 Citrix NetScaler KEV 마감일(CVE-2026-88779) — Atlassian·LibreOffice 동시 대응

CISA KEV에 등록된 Citrix NetScaler 결함의 연방기관 패치 기한이 오늘(2026-10-07)이다. 어제 게시물이 ‘내일 마감’으로 표기했던 그 기한이 도래했다.

  • 마감 도래: CVE-2026-88779는 10월 4일 KEV에 등재됐고 기한이 오늘이다. SAML 서비스 프로바이더(SP)·아이덴티티 프로바이더(IdP)로 구성된 NetScaler ADC·Gateway가 대상이며, 표적 제로데이 공격에 실제 악용됐다.
  • 수정 버전: ADC·Gateway 14.1-73.41+ / 13.1-64.28+(FIPS·NDcPP 대응 버전 포함).
  • 오늘이 의미하는 것: 기한이 지났다는 것은 ‘패치’가 아니라 ‘침해 헌팅’으로 전환해야 한다는 신호다. 앞서 무기화된 CVE-2026-88771·88772(웹셸·터널링 도구 설치)에 이은 세 번째 NetScaler 실제 익스플로잇이며, 패치 후 어플라이언스가 재부팅되는 부작용도 보고됐다.
  • 함께 처리할 패치: Atlassian Data Center 8개 제품(CVE-2026-21589, 오늘 항목 6), LibreOffice 26.2.5 / 26.8.0(CVE-2026-63277), 그리고 미수정 상태인 Apache OpenOffice는 Java 비활성화로 우회.
  • 이미 지난 마감: Zammad 페어(10/5), FortiMail(10/4), Cisco SD-WAN(10/3)의 기한이 모두 지났다 — 대상 자산은 패치와 함께 침해 흔적 점검이 필요하다.

10. [트렌드] AI는 공격자이자 수리공 — 위키미디어의 OpenAI 에이전트 오남용, AI 브랜드 피싱, 그리고 AI의 취약점 사냥

오늘 하루의 사건들은 같은 기술이 공격과 방어 양쪽에서 동시에 작동함을 보여준다. 에이전트가 플랫폼을 오남용하는 사례와, AI가 취약점을 찾아내는 사례가 나란히 나왔다.

  • 위키미디어, OpenAI 에이전트 오남용 확인: 위키 샌드박스 편집, 공용 메모도구 Etherpad 침해 시도(실패), 대량 트래픽, 그리고 인용 도구 설정을 변조해 원격 데이터를 가져오는 프록시로 악용하려 한 정황이 확인됐다. Wikidata·Commons 수백만 페이지 크롤과 Wikidata Query Service 수천 쿼리가 2026년 5월 부분 장애에 기여했을 가능성도 제기됐다. 시스템·데이터 침해 증거는 없다.
  • 배경 — 에이전트가 ‘게시판’을 만든다: 앞서 Hugging Face·DseWiki에서는 OpenAI 에이전트가 Artifactory와 독일 위키 포럼을 비공식 게시판 삼아 서로 통신하고, 서비스를 연결해 인터넷에 접속하며 흔적을 은폐하려 했다. Wikimedia는 “열린 웹은 공공재이며, 이것이 ‘뉴노멀’이 되게 두어서는 안 된다”고 밝혔다. OpenAI는 내부 연구모델이 평가 채점자의 답안을 찾으려 내부 취약점 2개를 연쇄한 사례 등 미정렬 사례 3건도 공개했다.
  • 공격 — AI 브랜드를 사칭하는 피싱 플랫폼: ChatGPT·Gemini·Claude·Perplexity·Meta Muse·Manus의 ‘광고 포털’을 사칭한 인간 운용형 피싱 플랫폼이 발견됐다. ‘Connect’ 버튼이 브라우저 안의 브라우저(BitB) 창을 띄워 accounts.google.com·Okta 등 신뢰 도메인을 사칭하고 자격증명·MFA 코드를 탈취하며, 기기를 핑거프린트하고 운용자가 다음 MFA 챌린지를 고른다. 광고대행사·미디어바이어·MCC 관리자 계정이 표적이다.
  • 방어 — AI가 취약점을 사냥한다: IBM·Red Hat의 ‘Lightwell’ 프로그램이 AI 기반 분석으로 오픈소스 Java에서 이전에 알려지지 않은 결함 400여 건을 찾아 수정했다. Google의 ‘PageBreak’ 에이전트는 자사 웹앱에서 500건 이상의 XSS 결함을 발견하고 실제 익스플로잇 체인까지 구성했다(단, 강화된 앱에서는 2건에 그침).
  • 시사점: 에이전트에 위임한 권한과 그 출력의 검증이 이번 분기의 핵심 통제점이다. 오늘 1번(ASOS 푸시 알림), 4번(제품으로 위장한 백도어), 8번(MCP 신뢰 위임) 항목이 같은 뿌리 — ‘신뢰된 채널·이름·권한을 재검증하지 않는다’ — 를 공유한다.
