1. 원플러스·OPPO 미패치 취약점 2건 — 무권한 앱 하나로 루트 장악, 5개월 침묵 뒤 강제 공개

OnePlus 15(최신 OxygenOS)가 앱 권한을 하나도 요구하지 않는 악성 앱에 의해 루트 권한을 내줄 수 있다는 연구 결과가 공개됐다. 연구자 Rasmus Moorats는 원플러스 자체 소프트웨어의 결함 2건을 연결해 안드로이드 최상위 제어권을 얻었고, 원플러스는 "다수 자사 기기와 OPPO 기기도 같은 결함의 영향을 받는다"고 인정하면서도 아직 수정본을 내놓지 않았다.

  • 공격 체인: ① 디버깅 데이터를 모으는 AtlasService가 루트로 실행되면서 호출자 검증 없이 모든 앱의 요청을 받고, 그 텍스트를 시스템 명령에 그대로 넣는다 → 제한된 루트(dumpstate 영역) 획득. ② 하드웨어 헬퍼 olc2가 받은 셸 명령을 무조건 실행해 권한을 완전한 루트로 확장한다.
  • 조건: 기기에 앱을 설치할 수 있어야 시작되지만, 그 앱은 어떤 권한도 요구하지 않고 사용자에게 아무 프롬프트도 띄우지 않는다. Moorats가 개조하지 않은 순정 기기에서 성공했고 OnePlus 12 Pro에서도 재현됐다. 실제 공격 사례는 아직 확인되지 않았다.
  • 5개월 타임라인: 4/18 신고 → 5/20 원플러스가 결함 확인 + "공개 여부는 회사가 단독 결정"이라며 게시 시 "관련 법적 책임을 추궁하겠다"고 경고 → 6/22 수정 진행 상황을 알리며 9/17까지 보류 요청(연구자 동의) → 7/20·9/11 업데이트 요청에 무응답 → 9/24 연구자가 공개.
  • 현재 상태: CVE 미부여, 수정 패치 없음, 결함을 명시한 원플러스 보안 공지도 없음. OxygenOS 16 전반에 같은 문제가 있을 것으로 추정된다.
  • 임시 대응: 이 공격은 기기 안의 악성 앱에서만 시작되므로, 당분간 실질적 방어는 "신뢰할 수 있는 출처의 앱만 설치"하는 것이다.

  • 무기화 경로: GitHub 검색 기준 이 도메인을 인용하는 공개 저장소가 1,700개를 넘는다. AI 에이전트 스킬 문서와 MCP 서버 문서가 "예시 엔드포인트"로 인용한 사례까지 포함된다. 그 모든 위치에서 원래는 순수한 플레이스홀더였지만, 지금은 ClickFix 서버를 가리키는 살아있는 포인터다.
  • 감염 방식: 최소 2026년 6월부터 가동. Windows 방문자에게 가짜 Cloudflare 검증 화면을 보여주고 클립보드에 명령을 심은 뒤 Windows 실행(Run) 창에 붙여넣도록 유도한다. 붙여넣은 명령은 원격 PowerShell 페이로드를 받아 실행한다. macOS 방문자에게는 "이 사이트는 Windows PC가 필요하다"는 오류만 표시된다.
  • 신뢰 경로 오염: 문서·스킬·에이전트 설정에 박힌 예시 도메인이 실제 C2로 바뀌면 프롬프트 인젝션과 의도치 않은 자동 요청으로 이어질 수 있다. 비예약 플레이스홀더 도메인(yourcompany.com, mycompany.com, your-api.com 등)은 탈취 가능한 자원으로 취급해야 한다.
  • 현재: 해당 도메인은 VirusTotal과 Google Safe Browsing 양쪽에서 악성·위험으로 등록된 상태다.

9. [트렌드] ClickFix가 '구독 상품'이 됐다 — 17,000개 감염 URL·3,000개 활성, AI 어시스턴트는 시크릿을 2배로 흘린다

CTM360의 글로벌 위협 보고서는 ClickFix가 2023년 말의 신기한 수법에서 온체인 인프라와 국가 지원 사용자층을 갖춘 구독형 상품으로 진화했음을 보여준다. 익스플로잇도, 첨부파일도, 디스크에 남는 파일도 없이 기업 네트워크에 들어가는 가장 흔한 경로가 됐다.

  • 규모: 가짜 Cloudflare 검증 페이지를 제공하는 감염 URL 17,000개 이상을 캠페인 단위로 분석했고, 보고서 작성 시점에도 약 3,000개가 여전히 루어를 제공 중이었다. 인프라는 테이크다운을 견디도록 설계돼 있다.
  • 왜 도메인 차단이 통하지 않는가: 침해된 정상 사이트의 자체 페이지가 루어를 뿌리므로 신뢰 도메인이 그대로 공격면이 된다. 오늘 1번·2번·3번 항목이 모두 같은 수법(정상 사이트·신뢰 도메인·플레이스홀더 도메인 악용)이라는 점이 이 트렌드의 실체다.
  • 탐지 전환: 네트워크 IOC보다 실행 경로를 봐야 한다. Windows 실행(Run) 창·터미널로 붙여넣기되는 msiexec·PowerShell 명령, 서명된 프로세스에서 시작되는 자식 프로세스, 클립보드 쓰기 직후의 실행을 탐지 대상으로 삼는 것이 권고된다.
  • AI 개발 환경의 시크릿 유출: GitGuardian '2026 State of Secrets Sprawl' 보고서에 따르면 AI 지원으로 식별된 커밋은 사람이 작성한 커밋보다 약 2배 높은 비율로 시크릿을 유출한다. 증가 속도가 가장 빠른 유출 자격증명 범주 대부분이 AI 서비스와 연결돼 있다. AI 코딩 에이전트를 하나의 신원(identity)으로 관리하고, .env·MCP 설정·IDE 설정에 정적 자격증명을 두지 않는 것이 기본 대응이다.
