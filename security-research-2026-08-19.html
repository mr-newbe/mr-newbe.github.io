제목: COMA: A Compositional Misleading Attack Class on Security-RAG, and a Causal Counterfactual Defense

저자: Chinmay Gondhalekar, Urjitkumar Patel

분야: 사이버보안 (cs.CR) / LLM 보안 · RAG 보안 · AI 에이전트 보안

게시일: 2026-08-18 (arXiv: 2608.17960)

연구 배경

보안운영센터(SOC)에서 활용되는 분석가용 코파일럿은 대부분 RAG(Retrieval-Augmented Generation) 기반으로, 취약점 평가와 대응 조치(remediation)를 문서 검색 결과에 의존해 생성한다. 기존 공격 연구는 악성 문서에 명령 주입(instruction injection)을 심거나 사실과 모순되는 내용을 넣는 방식에 집중해 왔다. 이에 따라 방어 측도 '문서의 개별 사실성 검증'에 초점을 맞춰 왔다. 그러나 이 연구는 문서 하나하나가 모두 사실적이고, 명령이 없고, 모순이 없으며, 분포상으로도 정상(non-adversarial)인데도 — 문서들의 '조합(composition)'만으로 보안 코파일럿의 최종 판단이 오도될 수 있음을 보인다.

핵심 내용

  • COMA(Compositional Misleading Attack) 공격 클래스 정의: 개별 문서는 전부 진실·무지시·무모순·정상 분포이지만, 문서 간 조합이 답변을 오도하는 공격류.
  • action-corruption 구현: 취약점을 올바르게 진단하도록 유도한 뒤, 그 취약점을 그대로 열어두는 열등한(열악한) remediation으로 대응을 끌고 가는 공격.
  • verdict-flip 구현: 결정 불가능한 도달성 체인(undecidable reachability chain)을 구성해 exploitability 판정을 불안정하게 뒤집는 공격.
  • 실험 결과: action-corruption은 프런티어 reasoning 모델을 포함한 테스트된 5개 모델 모두에서 모든 실행(run)에 성공했고, 합성 도메인 2종과 실제 CVE(CVE-2021-33813)에서 재현됨. verdict-flip은 확률적으로 성공하며 모델 능력이 높을수록 감소하지만 완전히 사라지지는 않음.
  • 공통 원리 규명: 공격은 '모호성을 해소하는 핵심 사실을 직접 읽을 수 있을 때'가 아니라 '추론(infer)해야만 할 때' 성공한다.
  • 방어 제안: CCD(Causal Counterfactual Defense) — 각 검색 문서의 leave-one-out 인과 영향을 측정하고, 답변의 영향력이 낮은 신뢰도 문서에 집중될 때 플래그를 띄우는 감사 기법. 정상 멀티문서 컨트롤 4종에서 false positive가 없었고, 영향력을 분산시키는 적응형 공격자는 aggregate 변형으로 탐지.
  • 공격 시드(attack seeds)와 CCD 레퍼런스 구현을 공개.

보안 시사점

  • 보안 코파일럿의 신뢰성 검증은 '개별 문서의 사실성'만으로는 불충분하다. 문서 간 조합 효과가 그 자체로 공격면이 되므로, RAG 파이프라인 전체의 출력 검증이 필요하다.
  • 취약점 자동 평가·자동 대응이 확산될수록 '정확한 진단 → 잘못된 조치' 유도 공격은 실질적인 위험이다. 진단은 맞아도 대응이 무력화되면 실제 침해로 이어질 수 있기 때문이다.
  • 프런티어 reasoning 모델에도 100% 성공하는 action-corruption은, 단순히 모델을 더 크고 강하게 만드는 것만으로는 이 공격류가 사라지지 않음을 시사한다.
  • CCD처럼 '문서의 인과적 영향력 + 신뢰도'를 결합한 감사는 기존 RAG 보안 코파일럿에 비교적 가볍게 적용할 수 있는 실용적 방어 축을 제시한다.
  • 공개된 공격 시드는 보안 LLM 레드팀 평가·벤치마크로 활용 가능해, 향후 RAG 보안 연구의 비교 기준이 될 수 있다.

결론

이 연구는 '모든 검색 문서가 진실'이라는 조건만으로는 보안 RAG 코파일럿이 안전하지 않다는 점을 체계적으로 입증했다. 개별 문서의 악성이 아니라 문서 간 조합이 답변을 오도하는 COMA 공격류는 실제 CVE에서도 재현됐고, 인과적 반사실 감사(CCD)는 false positive 없이 공격 문서를 국소화하는 방어를 제시한다. LLM 기반 보안 자동화를 도입하는 조직이라면 문서 조합 효과를 검증하는 계층을 의무적으로 고려해야 한다는 중요한 함의를 주는 연구다.
