1. [사건] Rank Math PRO 공급망 백도어 CVE-2026-111862 (9.8) — 지워도 다시 살아난다

WordPress SEO 플러그인 Rank Math PRO(유료판)의 배포본이 변조됐다. 2026-10-15 20:02 UTC ~ 10-16 07:12 UTC 사이에 rankmath.com에서 내려받았거나 업데이트로 설치된 사본에 악성코드가 들어 있었고, 해당 사이트는 침해된 것으로 간주해야 한다. Wordfence는 CVE-2026-111862, CVSS 9.8을 부여했다.

  • 자기 복구형 백도어: 사이트에 방문자가 들어올 때마다 숨겨진 백도어를 다시 생성한다. 그래서 “의심 파일 삭제 → 스캔” 순서로는 끝나지 않는다. 재생성 원인을 먼저 끊어야 한다.
  • 버전 번호로는 판별 불가: 문제 버전은 3.0.123인데 체인지로그상 날짜는 10월 7일이다(윈도우 개시 8일 전). 즉 10-15 20:02 UTC 이전에 받은 3.0.123은 안전하고, 같은 번호라도 윈도우 안에 설치·활성화했으면 감염이다. 무료판(WordPress.org, 활성 400만+)은 이 사안에 포함되지 않는다.
  • 남겨졌을 수 있는 것들: 다른 플러그인·테마·mu-plugins 디렉터리의 PHP 백도어, 관리자 계정, 가짜 코어 파일, .htaccess에 .cache를 PHP로 실행시키는 규칙, 예약 작업, SSH 키. 사이트가 접근할 수 있었던 모든 비밀번호·DB 자격증명·API 키는 노출로 가정하라고 안내한다.
  • 복구 순서: 10-15 20:02 UTC 이전 백업으로 복원 → 스캔 → 모든 비밀번호·키 교체가 Rank Math의 권장 순서다. 깨끗한 3.0.124는 플러그인 파일만 교체하며, 이미 심어진 백도어·계정·예약 작업은 지우지 않는다.
  • 왜 탐지 규칙이 없나: Patchstack은 “공격이 벤더 자신의 시스템에서 이뤄졌기 때문에 시그니처 룰로 막을 수 없다”고 밝혔다. 공급망 신뢰 자체가 뚫린 사례로, 남는 통제는 무결성 검증과 행위 기반 탐지뿐이다.

2. [사건] OpenCode Console 침해 — 1.4% 사용자의 AI 프로바이더 키가 위험해졌다

코딩 에이전트 OpenCode의 호스팅 서비스 Console이 침해됐다. 10월 16일 밤 레거시 시스템에 침입자가 도달했고, 사용자가 Console 워크스페이스에 저장해 둔 OpenAI·Anthropic·Google API 키가 노출됐을 수 있다고 17일 공지했다. 대상은 Console 사용자 중 1.4%로, 모두 외부 프로바이더를 연결한 계정이다.

  • 범위 구분: 위험한 것은 Console에 붙여넣은 키뿐이다. CLI·데스크톱 앱에 넣은 키는 로컬 SQLite에 있고 “우리에게 오지 않는다”고 공동창업자 Dax Raad가 밝혔다.
  • 실제 과금 피해: 사용자 신고로 OpenAI 키 $281·Anthropic 키 $168, 한 사용자는 $1,700, 또 다른 사례는 Anthropic $400·Google 약 €200이 청구됐다. 회사 표현은 “노출됐을 수 있다(may have been exposed)”이며 복사·사용이 확인된 것은 아니다.
  • 지우기 ≠ 폐기: Console에서 키를 삭제해도 프로바이더 쪽에서 revoke하지 않으면 계속 유효하다. Console 예산(budget)으로도 상한을 못 잡는다 — Console은 자기 게이트웨이를 통과한 요청만 보기 때문이다. 베어러 자격증명의 전형적인 함정이다.
  • 대응: 프로바이더 대시보드에서 폐기 후 재발급, 키를 쓰던 모든 스크립트 갱신, 최소 10월 16일까지 사용량·청구 내역에서 심사 않은 요청 확인, 툴별 키 분리와 지출 한도·알림 설정.
  • 배경: OpenCode는 이 사고를 “대규모 증류(distillation) 공격”과 관련 있다고 표현했다. 경쟁 모델 학습용으로 응답을 대량 수집하는 캠페인이 가짜 계정망을 통해 프로바이더에 접근해 왔다는 것이 Anthropic의 9월 경고다. 키 하나가 곧 대리 과금 통로가 되는 구조다.

3. [사건] Plex2Shell — PoC 공개 하루 만에 무기화, 채굴기와 리버스 프록시가 들어왔다

Plex Media Server의 4개 결함을 연쇄시키는 Plex2Shell이 기술 상세 공개(10월 16일) 다음 날부터 실제 공격에 쓰였다. 결과물은 XMRig 채굴기와 Linux 리버스 프록시 백도어다. 결함 자체는 7월 27일 Plex에 보고돼 8월 3일 1.43.3.10861에서 이미 패치됐다 — 즉 지금 뚫리는 곳은 미적용 인스턴스다.

  • 체인 구성: CVE-2026-96652(5.3, /player/timeline의 protocol 파라미터 미검증 SSRF) → CVE-2026-96654(6.9, searchOne URL 처리 결함으로 소유자 admin 토큰 획득) → CVE-2026-96655(5.3, /video/:/transcode/universal로 임의 주소 요청, 공격자 호스팅 ELF 전송) → CVE-2026-96656(8.6, Codecs 디렉터리에 임의 경로로 ELF 기록 후 실행). 여기에 CVE-2026-96651(7.1)까지 묶여, 최종적으로 비인증 RCE가 된다.
  • 페이로드: 광부는 mylovelyminer, 채굴 서버는 ota.proxystream[.]st. 프록시 아티팩트는 myawesomeproxy이며 실행하면 “이 소프트웨어를 쓰면 당신의 인터넷 트래픽이 외부에서 사용될 수 있음에 동의하는 것”이라는 문구가 뜬다.
  • 인프라 연결: 같은 도메인의 global.relay.proxystream[.]st는 2026년 8월 Bitsight가 AISURU DDoS·프록시웨어 봇넷과 연관해 지목한 적이 있다. 채굴+대역폭 판매를 한 번에 노리는 조합이다.
  • IoC: 배포 217.60.194[.]116, 공격 시도 91.92.40[.]202·176.65.139[.]228·45.194.92[.]222. Reddit에는 같은 mylovelyminer에 감염된 사례가 다수 올라왔다.
  • 시사점: CVSS가 5.3~8.6인 “중간 정도” 결함 4개가 합쳐지면 인터넷 노출 서비스의 완전 장악이 된다. 개별 점수로 패치 우선순위를 정하는 방식의 한계를 보여주는 사례다.

4. [사건] GhostAction 진화 — 폰트 파일로 위장한 탈취기, 94개 저장소로 확산

GitHub Actions 워크플로를 오염시키던 GhostAction이 수법을 바꿨다. GitHub의 차단 조치로 워크플로가 실행되지 않자, 이번에는 오픈소스 메인테이너를 피싱해 가짜 폰트 파일에 숨긴 스틸러를 심는다. OpenSourceMalware가 10월 19일 공개했고, 확인된 저장소는 94개다.

  • 인프라: 10월 9일 등록된 my-github[.]com이 193.32.204[.]199를 가리킨다. 이 IP는 악성 워크플로가 탈취 데이터를 내보내던 기존 유출 엔드포인트와 동일하다. 17일 먼저 등록된 my-gitlab[.]com은 명명 규칙이 같지만 등록기관·ASN·DNS 설계가 달라 직접 연결은 확인되지 않았다.
  • 피싱 흐름: noreply@my-github[.]com이 “모스크바에서 새 로그인”이라는 GitHub 보안 경고를 사칭해 발송 → 링크는 리버스 프록시로 동작하며 비밀번호와 2FA 코드를 수집 → 삽입된 JS가 repo·workflow·read:org 스코프의 OAuth 디바이스 플로를 자동 승인한다.
  • 자동화의 핵심: 피해자가 기기 코드를 입력하거나 앱을 승인할 필요가 없다. 스크립트가 /login/device 폼을 파싱해 사용자 코드를 넣고 authorize=1을 붙여 인증된 프록시 세션으로 승인을 대신 전송한다. 토큰은 my-github[.]com TCP/8443으로 유출된다.
  • 지속성: 악성 워크플로를 지워도 개발자 PC에 남는 2단계가 추가됐다. tasks.json에 "runOn": "folderOpen"을 넣어 폴더를 열기만 해도 실행되게 하는 VS Code 설정이 대표적이며, 이런 파일이 3종 함께 커밋된다.
  • 의미: 저장소 단위 자동화와 사람 대상 사회공학이 결합됐다. 저장소 스코프 OAuth 토큰은 재사용 가능한 API 자격증명이라, 한 번 승인되면 조직·레지스트리·다운스트림 사용자까지 영향 범위가 넓어진다.

5. [사건] 닛케이, 한 달에 세 번째 유출 — 이번엔 183만 건, 경로는 또 ‘탈취된 자격증명’

6. [취약점] Broadcom Wi-Fi 무패치 ‘forever day’ — 전파 범위 안에서 라우터 root 장악

Broadcom의 WPS(Wi-Fi Protected Setup) 구현에, 전파가 닿는 거리에서 비밀번호 없이·페어링 없이 라우터에 root 권한으로 코드를 실행하는 결함이 공개됐다. 연구자 Quentin Kaiser가 10월 16일 공개했으며, CVE도 패치도 없다.

  • 원인: 조각난 WPS 설정 메시지를 재조립하는 과정의 처리 오류로 라우터 메모리가 손상된다. Kaiser는 여기서 메모리 읽기와 코드 실행 두 가지를 만들어냈다.
  • 실증: 벨기에 Orange 게이트웨이(Askey TCG3000)에서는 저장된 Wi-Fi PSK를 읽어 전파로 되돌려보낸 뒤 그 비밀번호로 네트워크에 접속했다. Proximus 게이트웨이(Sagemcom BBOX3V+)에서는 Wi-Fi 프레임에 실어 보내는 리버스 셸을 열었다 — 외부 서버도 필요 없다. VOO 게이트웨이에서도 확인됐고 Telenet은 미시험.
  • 영향 칩: 구형 eCos 계열 BCM3380·BCM3383·BCM33834는 사용 가능한 수정이 없어 영구 미패치(forever day)로 불린다. 신형 Linux 계열 BCM3390·BCM65xx·BCM68xx는 Wi-Fi 소프트웨어를 hostapd로 교체하면 고칠 수 있다. 벨기에 통신사만 합쳐 수십만 대로 추정되고, 전 세계적으로는 수백만 대가 영향권이라는 게 연구자의 추정이다.
  • 왜 CVE가 없나: 코드는 최소 2010년까지 거슬러 올라가고, 2018년에 불완전한 수정만 배포된 뒤 벤더는 hostapd 전환을 권고했다. Kaiser에 따르면 Broadcom은 2018년부터 알고 있었다고 인정하면서도 CVE 등록과 공개 설명을 거부했다.
  • 완화: WPS를 끄고(가능하면 UI·CLI 모두), IoT용 SSID 분리, 제조사 펌웨어가 나온 모델은 즉시 적용. eCos 계열은 교체만이 답이라는 점을 자산 수명주기에 반영해야 한다.

7. [취약점] Siemens Software Center CVE-2026-110936 — 정품 서명 파일 + 악성 DLL 조합, ClickFix로 유포

Siemens는 Software Center의 DLL 검색 경로 제한 미비(CVE-2026-110936, CVSS v4 8.4) 결함이 실제 공격에 악용됐다고 밝혔다. 10월 15일 공개 후 이틀 뒤 4.0.9.8에서 수정됐고, 설치돼 있으면 다음 실행 시 자동 업데이트된다.

  • 공격 방식: 공격자는 정상 서명된 Siemens 실행 파일과 자신이 만든 악성 DLL을 한 폴더에 묶었다. 프로그램은 시작할 때 같은 폴더의 헬퍼 파일을 검증 없이 로드했고(당시 최신 3.5.8.7), 그대로 공격자 코드가 실행됐다. Siemens 제품·업데이트 채널이 뚫린 것은 아니라고 밝혔다.
  • 유포 플랫폼: Siemens는 이 캠페인을 Romulus ClickFix 작전과 연결했다. Forescout이 분석한 Romulus는 여러 악성코드를 내보내는 ClickFix 배포 플랫폼이며, LegionLoader와 Stardock 서명 앱을 이용한 DLL 사이드로딩 설치본을 배포했다.
  • 앞선 사례: Huntress는 9월 말 가짜 ChatGPT Custom GPT로 ClickFix 페이지에 유인해 Canon·Stardock 서명 프로그램으로 사이드로딩, 최종적으로 RAT를 심는 캠페인에서 40건 이상 대응했다. Siemens Software Center는 그 보고서에 없지만 인프라가 겹친다.
  • 탐지: 사용된 실행 파일이 정품이라 해시 기반 탐지는 무력하다. Siemens는 행위와 악성 DLL이 놓이는 폴더 경로 중심으로 볼 것을 권고하고 IoC를 함께 공개했다.

8. [패치] 10월 Windows Server 업데이트가 Exchange 로그인·메일 흐름을 멈춰 세웠다

Microsoft가 10월 Windows 보안 업데이트의 부작용을 확인했다. Windows Server 2019 이상에 적용 후 일부 온프레미스 Exchange에서 OWA 로그인 실패, Outbox에 남는 메일, 사서함 복제 지연이 발생한다. 전형적인 “패치가 만든 장애”다.

  • 증상: MapiExceptionMdbOffline: Unable to make connection to the server. (hr=0x80004005, ec=1142), 애플리케이션 로그 Event ID 1006.
  • 원인: 10월 업데이트가 Endpoint Mapper의 메모리 사용량에 기본 상한을 걸었다. Endpoint Lookup 호출 동시 512건이 기본값인데, Exchange처럼 부하가 큰 워크로드에서는 부족하다.
  • 임시 조치: 관리자 권한 명령 프롬프트에서 Endpoint Lookup 동시 호출 상한을 올리는 레지스트리 값을 추가하고 재부팅. 영향은 서버 부하에 따라 달라 “전혀 문제없는 서버도 있다”고 Microsoft는 설명했다.
  • 주의: Microsoft는 이 문제가 10월 Exchange 보안 업데이트 설치와는 무관하며 제거하지 말 것을 강조했다. Exchange 보안 업데이트를 빼면 실제 취약점이 열린다 — 장애 대응과 보안 롤백을 혼동하면 안 되는 지점이다.
  • 운영 교훈: 이번 주 패치 창에서는 Exchange·OWA 헬스체크를 배포 후 검증 항목에 넣고, 부하 피크 시간대 적용을 피하며, 레지스트리 완화책을 미리 문서화해 두는 것이 좋다. 같은 주에 KB5124010 미리보기가 게임·앱 크래시를 일으켰다가 수정된 사례도 있었다.

9. [트렌드] MITRE ATT&CK v20 — 프롬프트 인젝션·MFA 우회·수도시설이 ‘기법’이 됐다

MITRE가 ATT&CK v20을 공개했다. 가장 큰 변화는 “최근 공격자의 활동과 수법에 대한 커버리지 확대”다. Enterprise 도메인에 9개(기법+서브기법)가 추가됐다.

  • AI가 기법으로 편입: 프롬프트 인젝션이 2개 기법으로 분리됐다 — LLM 인터페이스에 직접 입력하는 경우와, 모델이 읽어들이는 자료에 숨기는 경우. 조직의 자체 AI 에이전트를 악용한 데이터 탈취, AI 검색·어시스턴트 추천을 왜곡하려는 웹 콘텐츠 오염, LLM 기반 악성코드 분석 방해도 추가됐다.
  • 인증 우회: 애플리케이션 전용 비밀번호 탈취(MFA 프롬프트 없이 로그인)와 CAPTCHA 우회(자동 해결 / 회피)가 새로 들어갔다. 손상된 의존성·개발 도구 서브기법은 이제 IDE와 코딩 에이전트 설정 파일까지 포함한다 — GhostAction의 tasks.json 같은 사례를 정확히 겨냥한 확장이다.
  • ICS: 인터넷에 노출된 PLC를 통해 미네소타 30개 이상 수도·하수 처리장의 운영자가 시스템에서 잠긴 캠페인이 등재됐다(귀속 미확인, 이란 연계 가능성 언급). 멕시코 정부 기관을 IT·OT 동시에 침해해 지방 상수도까지 도달한 AI 지원 침해도 함께 문서화됐다.
  • 행위자: IRGC 연계 Nimbus Manticore(항공·방산·통신), Salt Typhoon의 네트워크 경계 장비 익스플로잇 추가, APT38의 금전 탈취 → 소프트웨어 공급망 공격 전환 반영, RaaS The Gentlemen 신규 등재.
  • 탐지: 탐지 전략 15개·분석 38개가 추가됐고, ICS용 9개는 정상적인 엔지니어링·유지보수 작업을 걸러내도록 설계됐다. 모바일은 공식 스토어 밖 설치 기법이 v11 이후 부활했고, NFC로 카드 데이터를 중계해 ATM 인출을 노리는 NGate가 들어왔다.
  • 실무 적용: 프롬프트 인젝션·에이전트 남용·앱 비밀번호 탈취는 이제 “신종 위협”이 아니라 통제 항목이다. 탐지 커버리지 매핑표를 v20 기준으로 갱신하고, 에이전트 도구 권한·IDE 설정 파일 무결성을 점검 목록에 넣을 시점이다.

10. [트렌드] 표적은 여전히 사람 — AI 크레딧 미끼 npm, MS 사칭 33%, 그리고 직원의 집까지

기술적 결함이 아니라 사람의 판단을 노린 세 갈래 흐름이 같은 날 보고됐다. 가짜 AI 도구, 브랜드 사칭 피싱, 그리고 랜섬웨어의 가족 협박이다.
