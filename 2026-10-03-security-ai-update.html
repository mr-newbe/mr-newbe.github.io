1. Antino 백도어 — 중국 연계 UAT-11587, Microsoft 365(Outlook·OneDrive)를 C2로 쓴다

Cisco Talos가 아시아 정부·정책 기관을 겨냥한 중국 연계 캠페인의 신종 백도어 'Antino'를 공개했다. 추적명은 UAT-11587이며, 대만·인도·필리핀·캄보디아·파키스탄·태국·미얀마 등 8개국 16개 기관이 표적이 됐다. Antino는 Rust로 컴파일된 Windows 백도어로, 전용 C2 서버 대신 Microsoft 365(Graph)를 명령 채널로 악용한다.

  • 귀속: 2025년 9월 대만의 학계·싱크탱크·시민사회 정책 커뮤니티를 겨냥한 스피어피싱에서 처음 탐지됐고 이후 8개국 16개 기관으로 확대됐다. 거의 12개의 Antino 빌드 산출물에서 rsproxy.cn(중국 내 crates.io 미러·프록시) Cargo 경로가 발견됐고, 다운로더가 Arctic Wolf가 과거 플래그한 CloudFront 도메인을 참조하는 점이 China-nexus를 가리킨다.
  • C2 은닉 — M365를 dead drop으로: 공격자의 Outlook 사서함 폴더에서 command_req_[session_id] 접두사가 붙은 메시지를 10초마다 폴링해 명령을 회수한다. OneDrive는 하트비트와 파일 전송에 쓴다. 눈에 띄는 전용 C2 서버 없이 이미 신뢰된 SaaS 안에 통신을 묻는다.
  • 5단계 공격 체인: 피싱 메일의 Cloudflare URL → HTA/WSF 스테이저 → JavaScript 다운로더·복호화기 → .NET 역직렬화 체인으로 TestAssembly.dll 로더 실행 → 미끼 문서 열기 + 디코이 Calculator 실행 + Antino(slc.dll) 배포. 임플란트는 Microsoft 서명 바이너리 GatherOsState.exe를 이용한 DLL 사이드로딩으로 실행된다.
  • 기능·은닉: 호스트 정찰, 셸·PowerShell 실행, 파일 전송, 인메모리 셸코드 로딩, 지속성을 지원한다. Windows Scripted Diagnostics 프레임워크를 악용해 공격자 PowerShell을 정상 Windows 컴포넌트를 통해 실행 — 원본 임플란트로의 행위 귀속을 어렵게 만든다(관측 가능한 PowerShell·파일·레지스트리 텔레메트리는 남는다).
  • 시사점: C2가 '차단 가능한 인프라'에서 '이미 신뢰하는 SaaS 내부'로 이동했다. M365 트래픽을 통째로 막을 수는 없으므로, 탐지는 메일함 이상 행위·Graph API 호출 패턴·DLL 사이드로딩 텔레메트리로 옮겨가야 한다.

2. Dell CSM 치명적 결함 5건 — CVSS 10.0 두 건, 무인증 스토리지 관리자 권한과 K8s 노드 루트

Dell이 컨테이너 스토리지 모듈(CSM)의 치명적 결함 여러 건을 수정했다. 무인증 원격 공격자가 스토리지 백엔드 관리자 자격증명을 획득하거나, 단일 리소스 제출로 Kubernetes 클러스터 전체를 장악할 수 있는 취약점들이다.

  • CVE-2026-63688 (10.0): csm-authorization-storage gRPC 서버의 critical function 인증 누락. 무인증 원격 공격자가 등록된 모든 스토리지 배열의 백엔드 관리자 자격증명에 접근해 5개 스토리지 제품군 전반의 완전 관리 통제를 얻는다.
  • CVE-2026-63692 (10.0): 인가 프록시·테넌트 서비스의 인증 누락. 무인증 네트워크 공격자가 인증을 우회해 관리자급 권한을 얻고 모든 테넌트의 스토리지 자원을 접근·조작할 수 있다.
  • CVE-2026-67269 (9.9): 권한 관리 부실 — 단일 커스텀 리소스 제출로 Kubernetes 클러스터 내 모든 노드를 침해할 수 있다.
  • CVE-2026-54472 · CVE-2026-67273: CSM 인가 프록시의 인증 통제 우회 + 클러스터 전역 K8s Secret 읽기·cluster-scoped RBAC 리소스 생성 — 의도된 Kubernetes 접근 제어를 실질적으로 무력화한다.
  • 영향·수정: CSM 1.17.0 미만 전체가 영향받으며 1.18.0에서 수정됐다. 워크어라운드나 완화책이 없다. Dell은 업데이트 적용과 함께 JWT 서명 시크릿 로테이션을 권고했다.
  • 시사점: 스토리지 데이터 경로를 관리하는 컨트롤 플레인이 '인증 누락' 하나로 뚫린다 — 클러스터 하나 침해가 스토리지 백엔드 자격증명 전체로 확대되는 전형이다. CSI/CSM류 컨트롤 플레인 컴포넌트를 인터넷이나 테넌트 네트워크에 노출하지 말 것.

3. FortiMail 제로데이(CVE-2026-104286, 9.8) 실제 익스플로잇 — CISA KEV 등재, 무인증 임의 파일 쓰기

CISA가 Fortinet FortiMail의 치명적 결함을 KEV 카탈로그에 등재했다. 실제 익스플로잇 보고에 따른 것으로, 무인증 공격자가 조작된 HTTP/HTTPS 요청만으로 시스템에 임의 파일을 쓸 수 있다. 10-02 게시물에서 '10/4 KEV 마감'으로 예고했던 건이 실제 익스플로잇 확인으로 확정된 단계다.

  • 결함: CVE-2026-104286 (CVSS 9.8) — 경로 순회(CWE-22)와 NULL 바이트 미중화(CWE-158)의 조합. 무인증 공격자가 조작된 HTTP/HTTPS 요청으로 기반 시스템에 임의 파일을 쓴다.
  • 영향 버전: FortiMail 8.0.0~8.0.1(→8.0.2 이상), 7.6.0~7.6.6(→7.6.7 이상), 7.4.0~7.4.x(→7.4 브랜치 이상). 일부 버전은 수정본 공개 전까지 아래 워크어라운드가 필요하다.
  • 워크어라운드: IBE 기능 비활성(config system encryption ibe → set status disable), 그리고 관리 인터페이스의 인터넷 접근 차단·신뢰 사설망만 허용.
  • 침해 지표(IoC): IP 79.141.169.187, 45.129.0.192. 파일 추가 — /data/lib/liblog.so, /data/bin/webconsole, /data/bin/mailservice, /data/etc/ld.so.preload; 수정 — /bin/smit, /data/etc/httpd.conf, /data/migadmin.tar.gz.
  • 마감: FCEB(연방 민간 행정부) 기관은 2026-10-04까지 패치 또는 워크어라운드 적용이 권고된다. 같은 KEV 묶음에 Check Point(85102·93616), Arista VCO(93952), F5 BIG-IP APM(94127), Cisco SD-WAN(76504), Citrix NetScaler가 함께 있다.
  • 시사점: 메일 게이트웨이는 최전방 노출 자산이다. /data/etc/ld.so.preload 추가는 LD_PRELOAD 기반 은닉·지속성 시도의 정황 — 파일 무결성 모니터링(FIM) 대상에 반드시 포함해야 한다.

8. [패치] Android 17 Advanced Protection — 접근성 서비스 잠금, 침입 로깅·USB 보호 추가 / KEV는 오늘이 Cisco 마감일

Google이 Android 17에서 Advanced Protection을 켜면 접근성 서비스(AccessibilityService) 접근을 '접근성 도구'로 검증된 앱으로만 제한한다고 발표했다. 스파이웨어·금융 사기 악성 앱의 핵심 통로를 닫는 조치다.

  • 왜 중요한가: 접근성 서비스는 화면을 읽고 키 입력을 기록하며 정상 앱 위에 가짜 로그인 화면을 덧씌울 수 있어 악성 앱·금융 사기의 주 통로였다. 그동안 사이드로드 앱의 접근성 활성 차단, 인콜 보호, AAPM 등 단계적 대응이 있었다.
  • 신규 기능: Intrusion Logging(프라이버시 보존형 포렌식 로깅 — 정교한 스파이웨어 조사용), USB Protection, 완전 잠금 다운(추가 탐색 차단), Supporting Apps(Advanced Protection을 사용 중인 앱 확인). 개발자는 상태 통보를 받아 자사 기능을 자동 활성화할 수 있다.
  • KEV 마감 — 오늘이 Cisco: Cisco Catalyst SD-WAN Manager(CVE-2026-76504, 9.8)가 오늘(10/3) 마감이다 — 무인증 admin API 장악, 워크어라운드 없음. 이어 FortiMail(104286) 10/4, Zammad 세션 고정·권한상승(102489·102490) 10/5가 도래한다.
  • 시사점: KEV 마감은 '지금 패치'의 가장 명확한 트리거다. 원격 무인증(네트워크 노출 자산) → 파일 열기(사용자 단말) → 로컬(LD_PRELOAD·세션) 순으로 우선순위를 잡으라.

9. [트렌드] AI가 취약점 '발견·익스플로잇'의 속도를 동시에 올린다 — Google GTIG, 공개 2배·고위험 +167%

Google Threat Intelligence Group(GTIG)이 AI가 취약점 위협 지형에 미친 영향을 통계로 정리했다. 결론은 AI가 취약점 발견 속도뿐 아니라 발견되는 결함의 유형과 위험 프로파일까지 바꾸고 있다는 것이다.

  • 공개량 2배: 취약점 공개 건수가 2026년 들어 두 배로 늘었다. 고위험 결함은 2026년 1월 131건에서 8월 350건으로 167% 증가했다(전체의 약 3%).
  • 무엇을 찾는가: AI 보조 발견은 저위험 결함 비중을 줄이고, 중위험 및 RCE로 이어지는 결함을 비례적으로 더 많이 찾는다 — "AI는 더 결과가 큰 결함을 찾는다."
  • 익스플로잇 가속: 제로데이 익스플로잇이 2025년 월평균 8건 → 2026년 1~8월 월평균 11건으로 늘었고, 2026년 8월엔 22건으로 급증했다. CVE 익스플로잇 증가(+127%)가 공개 증가(+128%)와 나란히 스케일한다.
  • 균형점: 익스플로잇 비율 자체는 여전히 희박하다 — 2026년 공개 취약점의 0.23%(약 431건 중 1건)만 실제 익스플로잇이 관측됐다.
  • 데이터 함정: 'Linux Kernel' 키워드만으로 2026년 1~8월 약 5,000건 CVE가 생성됐지만, 실제 익스플로잇된 제로데이는 0건이었다. CNA 배정 정책이 기준선을 부풀릴 수 있다.
  • 오늘과의 수렴: GitLab AI Gateway 샌드박스 탈출·Mooncake 전송 엔진·WordPress 플러그인 9.8×4 — 모두 '경계 검증 누락·인가 누락'이라는, AI 보조 발견이 양산하는 유형이다. 같은 도구가 방어자의 패치 백로그를 키우고 공격자의 진입점 목록을 넓힌다.
  • 시사점: '공개 2배'를 트리아지 인력 확충으로는 못 따라간다. GTIG 데이터가 말하는 것은 자산 귀속(ownership)과 익스플로잇 가능성(EPSS/KEV) 기반의 우선순위화다 — CVE 개수 관리가 아니라 '실제로 익스플로잇되는 것' 관리다. CISA의 CVE 근대화 계획, EU CRA가 수동 트리아지를 '죽인다'는 평가도 같은 방향을 가리킨다.
