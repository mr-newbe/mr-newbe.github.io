1. [사건] PwnEscape CVE-2026-99999 — 게스트 VM이 호스트 메모리를 읽는다, 클라우드 '공유 계층'의 결함

리눅스 커널 네트워킹 코드에서 가상머신 안의 코드가 호스트 메모리를 읽을 수 있는 크리티컬 결함이 공개됐다. 별명 PwnEscape, CVSS 9.3. 보안업체 pwn.ai의 Paulos Yibelo가 Vercel의 보안 챌린지에서 발견했고, Vercel이 자사 프로덕션 샌드박스를 대상으로 메모리 유출을 재현·확인했다.

  • 무엇이 새는가: 게스트가 보낸 패킷 하나당 호스트 메모리 약 32바이트가 되돌아온다. 패킷을 계속 보내면 계속 읽힌다. 조작된 패킷 2개로 호스트를 크래시시켜 그 위에서 돌던 모든 샌드박스를 함께 내릴 수 있었다.
  • 탈출까지: 같은 결함으로 연구자는 호스트의 관리자 권한에 도달해 VM 경계를 벗어났다. 다만 연구자는 "어떤 벤더의 프로덕션 환경에서 root 명령 실행을 주장하는 것이 아니다"라고 선을 그었다 — 크래시와 코드 실행은 Vercel 구성을 복제한 자기 장비에서만 관측됐다.
  • 공격 벡터는 local: 이미 게스트 안에서 코드를 돌리고 있어야 한다. 인터넷 건너편에서 패킷만 던져 터지는 결함이 아니며, CISA KEV에 없고 실제 악용 흔적도 보고되지 않았다.
  • 왜 남 일이 아닌가: Vercel Sandbox는 고객 코드를 Firecracker 마이크로VM에 격리한다. 문제는 그 '벽'이 아니라 호스트가 쓰는 리눅스 커널의 네트워킹 코드다. 거의 모든 대형 클라우드가 같은 커널 계층으로 고객 워크로드를 분리하기 때문에, 특정 사업자가 아니라 공유 인프라 전체의 위험이 된다.
  • 수정: 커밋 6785011f8b16(Red Hat의 Michael S. Tsirkin, 메인라인 머지) — 패킷의 checksum 데이터가 IPv4 헤더를 가리키지 못하도록 검사 한 줄을 추가한다.
  • 시사점: AI 보조 연구 도구(Omega-Pwn 하네스 + GPT-5.6 Sol)가 커널 수준 결함을 찾아낸 사례다. "우리는 하드닝을 잘했다"는 클라우드의 주장은 커널 하나가 격리의 바닥이라는 사실을 바꾸지 못한다.

2. [사건] Citizen Lab — 알자지라를 노린 Candiru 제로클릭 스파이웨어, 감염 경로는 '평범한 온라인 광고'

토론토대 Citizen Lab이 상용 스파이웨어가 표적 광고를 통해 실제 기기까지 도달한 첫 공개 기술 확인을 내놨다. 이스라엘 Candiru의 스파이웨어가 알자지라 기기를 사용자 클릭 없이 감염시켰다.

  • 수법: 광고는 이스라엘 회사 Discover-Tech가 집행했다. 광고에 실린 작은 코드가 로드되는 순간 기기의 광고 ID와 IP를 Discover-Tech 서버로 전송하고, 그 서버가 표적 여부를 판정해 공격 코드를 돌려보냈다. 광고 자체엔 공격 코드가 없어 광고 네트워크가 탐지할 것이 없었다. 광고가 화면 밖에서 로드된 경우도 있었다.
  • 피해: 2024~2025년 알자지라 최소 45대가 표적됐다. 감염 기기의 트래픽 로그는 매번 같은 순서를 보였다 — Discover-Tech 광고 서버 → 기기를 심사하는 Candiru 서버 → 스파이웨어를 돌리는 C2 서버.
  • 귀속 근거: 감염 기기에서 빼낸 Windows 실행 파일이 Citizen Lab이 2021년 해부한 Candiru 도구와 같은 고유 기법을 썼다(high confidence). 어떤 정부가 배후인지는 밝히지 않았다. 익스플로잇 자체는 확보하지 못했다.
  • 플랫폼 대응: Google과 IAB Europe이 10월 초 Discover-Tech를 승인 광고 벤더 목록에서 제거했다(2020년부터 등재돼 있었다). Google은 광고 거래소 접근을 차단했고 Comcast(Beeswax)·Vungle·Eskimi도 각각 차단·검토에 들어갔다.
  • 맥락: Candiru는 2021년 미국 수출 블랙리스트에 올랐지만 2025년 미국 투자사에 자산이 팔려 제재 밖 신설 법인으로 옮겨졌다. 알자지라는 2020년 NSO Pegasus로도 기자들의 아이폰이 뚫린 전력이 있다.
  • 시사점: '공격 코드가 없는 광고'는 광고 생태계의 심사 모델 자체를 우회한다 — 방어선이 브라우저가 아니라 광고 공급망으로 이동한다.

3. [사건] Silent Lynx(UAT-6275) — WinRAR 결함으로 CIS 정부 기관에 리버스 셸, 9개국 표적

Cisco Talos와 Recorded Future Insikt Group이 2025년 6월 ~ 2026년 8월 CIS(독립국가연합) 정부·핵심 인프라를 겨냥한 Silent Lynx(UAT-6275 / TAG-193) 캠페인을 공개했다. 서로 다른 4가지 감염 체인이 커스텀 리버스 셸로 이어진다.

  • 4개 감염 체인: ①(2025-06) 매크로 문서로 2단계 바이너리 실행 ②(2025-07) PS2EXE 다운로더 + 예약 작업으로 지속성 ③(2025-10) RAR 아카이브 속 악성 LNK → PowerShell → GitHub 호스팅 스크립트 ④ WinRAR 결함 CVE-2025-8088을 악용한 조작 아카이브.
  • 페이로드: FoalShell·Chvost·Laplas·PickleShell 등 커스텀 리버스 셸을 배포해 감염 호스트에 대화형 원격 접속을 확보한다.
  • 표적·수법: 카자흐스탄·키르기스스탄·타지키스탄·투르크메니스탄·우즈베키스탄·아르메니아·아제르바이잔·러시아·벨라루스 9개국. 외교·국제무역·에너지·항공을 주제로 한 유인 문서를 썼고, 탈취한 정부 계정에서 발송해 신뢰를 만들었다.
  • 확장 신호: 공개된 스테이징 디렉터리 3곳에서 리눅스용 도구와 Fortinet FortiWeb SQL 인젝션 CVE-2025-25257 PoC가 발견됐다 — 인터넷 노출 어플라이언스로 활동을 넓히려는 정황이다.
  • 귀속: 카자흐스탄 연계로 평가되며 최소 2020년부터 활동. YoroTrooper·ShadowSilk·Cavalry Werewolf·Tomiris와 겹친다.
  • 시사점: 공격자 자신의 OPSEC 실수 덕에 연구진이 인프라와 악성코드 개발 과정을 직접 들여다봤다 — 반면 수법은 GitHub·WinRAR·탈취한 정부 메일함 등 '정상 서비스'만으로 4개 체인을 조립한다.

4. [사건] 가짜 Arch Linux 패키지가 root 권한으로 악성코드를 심는다 — yay·paru 사칭, AUR 대량 업로드

공격자가 Arch Linux의 커뮤니티 저장소 AUR에 인기 헬퍼 도구 yay·paru를 사칭한 악성 패키지를 올렸다. 10월 13일 탐지됐고, 사용자 marchos1as가 올린 타이포스쿼팅 이름들이 문제였다.

  • 트로이 목마 구조: 정품 소스 URL과 소스 타르볼을 그대로 가져와 정품 재포장처럼 보이게 만든 뒤, 악성 설치 스크립트(install scriptlet)로 root 권한으로 원격 셸 스크립트를 실행한다. AUR 관리자는 "패키지 이름과 악성 스크립트가 진짜 패키지에 섞여 들어가도록 설계된 트로이 목마 사칭"이라고 경고했다.
  • 페이로드 경로: Wayback Machine URL을 경유해 러시아 호스팅 GitFlic의 개인 저장소(hellscripter/install-scripts)에서 내려받는다 — 원본 서버를 숨기는 이중 우회다.
  • 연계 의혹: SafeDep가 문서화한 npm 캠페인 'DirtyBlanket'이 Codeberg의 같은 hellscripter/install-scripts 저장소에서 코드를 가져왔고, OSV 권고도 같은 Wayback·GitFlic 도메인을 지목한다. CHAOS 원격 접속 트로이목마를 폰트 서비스로 위장한 리눅스 웜이 AUR 패키지에 로더를 주입한 사례다.
  • 대응: AUR 팀이 계정을 차단하고 악성 패키지를 제거했다. 의심 패키지를 설치한 사용자는 시스템이 이미 침해됐다고 가정하고 즉시 재설치·자격증명 교체를 해야 한다.
  • 전례: 6월에는 400개 패키지가 루트킷급 자격증명 탈취 악성코드를 배포했고, 7월 캠페인으로 Arch가 패키지 '입양(adoption)' 기능을 일시 중단했다.
  • 시사점: 배포판 커뮤니티 저장소는 이제 공급망 공격의 1순위 표적이다 — PKGBUILD를 직접 읽지 않으면 아무도 대신 검사해 주지 않는다.

5. [사건] 유출 후폭풍 — 영국 Legal Aid는 1978년 기록까지, CenterPoint는 100만 명

두 건의 대형 유출이 이번 주 규모를 확정했다. 영국 법률구조청(LAA)은 침해 범위가 1978년까지 거슬러 올라간다고 밝혔고, 미국 유틸리티 CenterPoint Energy는 텍사스 주민 106만 명이 영향을 받았다고 통지했다.

  • LAA 규모: 압수된 기록 대부분은 2007~2025년 신청·청구·지급 관련이지만, 약 25만 건이 2007년 이전이다. 대부분 1990~2000년대이고 1990년 이전은 극소수, 현재 확인된 가장 오래된 기록은 1978년이다.
  • LAA 내용: 신청자·수령자의 이름, 주소, 생년월일, NI 번호, 사건번호, CCMS 입력 내용. 업무 종사자(변호사·사무소·법관)의 계약·결제 정보·포털 자격증명도 포함됐고, 2010~2017년 보호관찰(Probation) 대상자 일부 데이터도 확인됐다.
  • 왜 이렇게 늦었나: 2025년 4월 침해, 5월 공개. 여러 시스템에 걸쳐 비정형·파편화 데이터가 방대해 분석이 오래 걸렸다며, 유출 정보가 공개·판매된 증거는 없다고 밝혔다. 영국 법무부는 디지털 서비스 현대화에 2억 파운드 이상을 투입 중이다.
  • CenterPoint: 휴스턴 기반 유틸리티로 텍사스 1,062,060명 피해를 텍사스 법무장관실에 신고했다. 이름·주소·주민번호·운전면허번호가 포함됐고, 개인 통지서는 아직 발송되지 않은 것으로 보인다. 인디애나·미네소타·오하이오 고객도 영향권이지만 전체 규모는 불명이다.
  • 맥락: 침해 공개 며칠 전 범죄 포럼에 750만 건 확보 주장이 올라왔고, 9월 12일에는 약 300만 개 전화번호를 포함한 2.5GB 아카이브가 유포됐다. 반면 SEC 신고서는 "고객 일부만 영향"이라고 적었다 — 신고 수치와 공표 규모 사이의 간극이 남는다.
  • 시사점: 40년 넘게 보관된 종이 시대 데이터가 온라인 시스템에 얹혀 있으면 침해 한 번에 그 전체가 위험해진다 — 데이터 보존 기간(retention) 정책 자체가 보안 통제다.

6. [취약점] '인증은 있는데 검증이 없다' — 서비스 인프라 인증 우회 클러스터

이날 NVD 크리티컬 목록의 공통 결함 형태는 "경계를 신뢰하지만 다시 검증하지 않는다"였다. 인증 로직이 붙어 있음에도 대상·출처·무결성 중 하나를 확인하지 않는 결함들이다.

  • WMS MobileServer CVE-2026-89309 (CVSS 10.0): 권한 부여 미들웨어가 GET·HEAD 요청에만 Authorization 헤더를 요구한다. 다른 HTTP 메서드는 검사 없이 통과해 무인증 접근이 가능하다 — 메서드 하나로 인증 전체가 무력화된다.
  • Znuny CVE-2026-93483 (9.5): 애플리케이션이 특정 HTTP 요청 헤더를 신뢰해, 조작된 헤더로 표준 로그인 절차를 우회하고 민감 시스템 기능에 접근한다. 7.3.6 이하 영향.
  • IBM i CVE-2026-96119 (9.9): HTTP Server Administration 웹 애플리케이션의 부적절한 데이터 정제로, 원격 인증 사용자가 임의 코드를 실행하거나 민감 정보를 획득할 수 있다. 7.3~7.6 영향.
  • Stela CVE-2026-101287 (9.3): authProcess 쿠키의 무결성을 검증하지 않는다 — 사용자 식별자와 인증 상태를 담은 쿠키를 공격자가 직접 만들 수 있다. 1.60.1 이전.
  • EthereumAuthenticator CVE-2026-19863 (9.3): 요청 경로에 로그인 경로 문자열이 포함되기만 하면 보호 자원에 접근된다 — 앵커 없는 부분 문자열 매칭(unanchored substring match)이 원인이다.
  • 시사점: 이 클래스는 스캐너가 "인증 없음"으로 잡기 어렵다 — 코드가 인증을 시도하는 것처럼 보이기 때문이다. 검사 대상은 '인증 코드의 존재'가 아니라 '모든 경로가 같은 검사를 통과하는가'다.

10. [트렌드] 발견은 폭증했는데 익스플로잇은 따라오지 않는다 — AI가 바꾼 '속도'의 실체

이번 주 여러 보고서가 같은 질문에 서로 다른 답을 냈다. AI가 취약점 발견을 폭증시켰다는 것까지는 합의, 그러나 실제 피해로 이어지는 비율과 협박의 방식은 전혀 다른 곳에서 움직이고 있다.

  • Cisco Talos Q3 결함 펄스: CVE가 7만 건을 넘겼고 전년 대비 +105%. 반면 KEV(실제 악용)는 +37%에 그쳤다. 더 중요한 건 KEV의 33%가 2025년이나 그 이전 CVE라는 점 — 실제 위협의 3분의 1은 패치 부채(patch debt)다. 2026년 CVE 중 공개일과 KEV 등록일이 같은 비율은 29%로, 2025년 전체보다 2%p 높은 수준에 불과하다.
  • Censys 노출 지도: AI 관련 소프트웨어의 인터넷 노출이 9개월 만에 63% 증가했다(2025년 10월 164,088개 → 2026년 7월 267,915개 IP). 워크플로 자동화 n8n이 113,926개 호스트로 최다이며, 버전을 신고한 n8n 중 76.1%가 CVSS 9.0 이상 결함의 영향 범위에 있다 — 그리고 이 서버들은 워크플로가 연결하는 서비스의 자격증명을 들고 있다.
  • 속도의 비대칭: 자체 호스팅 AI 에이전트 OpenClaw는 제어 패널이 포함된 첫 릴리스(2026-01-05) 6일 뒤 노출 패널이 2개였는데 4월 7일에는 85,478개가 됐다. 반대로 ICS 노출은 2년 반 동안 약 4% 증가에 그쳤고(약 129,000 → 134,000대, 70%가 소비자·모바일 회선), Telerik·Jenkins·Cleo MFT·SharePoint의 최고(最古) 버전 점유율은 1%p 이내로 거의 변하지 않았다.
  • 협박의 인격화: 한 보고서는 랜섬웨어 공격의 84%에서 AI가 사용됐다고 집계했고, 여러 매체가 공격자들이 직원과 그 가족을 직접 겨냥해 스와팅·실명 위협·"우리가 어디 있는지 안다"는 식의 압박을 가한다고 보도했다. 몸값을 못 받는 조직이 늘면서 기술적 압박이 심리적 압박으로 대체되는 흐름이다.
  • 방어선도 AI로: Google은 Android에 Gemini 기반 클라우드 스캠 분석(Private AI Compute 환경)과 기기 내 Gemini Nano 링크 검사를 넣었고, 가짜 CAPTCHA를 악용한 ClickFix 공격은 2025년 조사한 피싱킷 공격의 43%에서 확인됐다.
  • 시사점: "AI가 10억 개의 취약점을 찾았다"는 헤드라인은 위험의 총량이 아니라 스캐너의 처리량을 말한다. 실무 우선순위는 새로 발견된 7만 건이 아니라 — 이미 1년 이상 방치된, KEV에 남아 있는 패치 부채다.
