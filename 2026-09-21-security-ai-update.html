1. [사건] Claude Opus 5, 72시간 만에 OpenAI 직원 계정 탈취 — 'HEIF Heist'

보안기업 Hacktron의 연구원 3명이 Anthropic의 Claude Opus 5를 이용해 2개의 결함을 연쇄시켜 OpenAI 직원 여러 명의 ChatGPT·Codex 계정을 탈취하고 내부 코드 저장소까지 도달했다. 실제 공격이 아닌 승인된 보안 연구였지만, 첫 탐색에서 내부 접근까지 걸린 시간은 72시간 미만이었다.

  • 연쇄 구조 (1단계): 공개 도움말 포럼(Discourse)의 이미지 처리 경로. 업로드된 HEIC/HEIF를 ImageMagick → libheif로 디코딩하는 과정의 결함 CVE-2026-32882. Discourse 자문은 이를 원격 코드 실행(RCE)으로 평가해 CVSS 8.8을 부여했고, libheif 자체 자문은 OOB read(메모리 노출·크래시)로 더 좁게 기술한다.
  • 연쇄 구조 (2단계): 포럼의 'Sign in with OpenAI' SSO. 포럼 서버를 장악하면 임직원이 쓰는 것과 동일한 로그인 체계를 통해 ChatGPT·Codex 계정이 그대로 넘어간다. 피해자는 아무 동작도 하지 않아도 됐다 — 포럼 소프트웨어 결함이 아니라 OpenAI측 아이덴티티 설계 문제라는 지적.
  • 패치 지연이 핵심: libheif 결함은 2026년 5월 1.22.0에서 이미 수정됐지만, 포럼 서버 이미지(Debian 12 기반)는 7월 시점에도 구버전 1.19.7을 그대로 탑재하고 있었다. 공개된 CVE와 수정본이 존재했는데도 배포판 패키지에 반영되지 않은 것이 실제 침입의 발판이 됐다.
  • 대응 타임라인: 신고 후 OpenAI가 약 14시간 만에 수정, 9월 1일 6,500달러 바운티 지급. 내부 저장소에는 PR 1건이 생성됐을 뿐 소스 열람·머지·고객 데이터 접촉은 없었다. 다만 동일 SSO로 GitHub·Slack·이메일까지 도달 가능했다고 연구팀은 밝혔다.
  • 'HEIF Heist' 캠페인: 약 2개월간 AI 사용료 3,000달러 미만으로 동일 계열 이미지 디코더 결함을 여러 대기업 소프트웨어에서 발견. Slack·Meta 제품·GitHub Enterprise·Next.js 결함과 연결된다고 주장하나, 독립 확인된 것은 Vercel 자문의 Next.js 결함과 libheif 유지관리자가 확인한 Meta 관련 RCE뿐이다.
  • 권고: libheif를 1.23.4 이상으로 업데이트하고, 자체 호스팅 Discourse는 최신 이미지로 재빌드(웹 UI 업데이트만으로는 구버전 라이브러리가 교체되지 않음, 수정 릴리스 2026.7.0 / 2026.6.1 / 2026.5.2 / 2026.1.6), 신뢰도 낮은 서비스와 내부 도구가 SSO를 공유하지 않도록 범위를 제한할 것.

2. [사건] CrowdSec, TanStack npm 공급망 공격 여파로 프라이빗 저장소 170개 유출

프랑스 보안기업 CrowdSec이 9월 18일, 퇴사한 직원의 계정을 이용해 자사 프라이빗 GitHub 저장소 약 170개가 복제된 사실을 공개했다. 복제 시점은 5월 22일이고, 유출 코드가 온라인 포럼에 게시된 것은 9월 16일이다.

  • 공급망 → 자격증명 탈취: 5월 11일 TanStack npm 패키지 42종의 악성 버전 84개가 배포됐다(CVE-2026-45321). 설치 시 GitHub 토큰·SSH 키·클라우드 자격증명을 훔쳐간다. 퇴사 직원의 노트북이 이 공격에 감염됐다.
  • 오프보딩 실패: 퇴사자에게 업무 마무리를 위해 GitHub 접근 권한을 남겨뒀고, 그 계정의 GitHub OAuth 토큰으로 복제가 이뤄졌다. 회사는 복제 3일 뒤인 5월 25일에야 계정을 제거했고, 유출 사실은 몇 달 뒤에 알았다.
  • 유출 범위: 프라이빗 저장소의 웹 콘솔, 데이터사이언스 스크립트/모델, 자동화 스크립트, 그리고 블록리스트에 어떤 IP를 넣을지 결정하는 합의(consensus) 알고리즘. 알고리즘이 요구하는 탐지 임계값도 함께 노출됐다(비공개 정보였음). 유출 코드에는 자사 사용자 이메일 83개와 2020년 잠재 투자자 51명의 이름·이메일·투자 맥락도 포함됐다.
  • 추적 난점: 해당 토큰은 회사가 조회 가능한 GitHub 로그에 흔적을 남기지 않았고 유출을 인지한 시점엔 이미 소멸된 상태였다. GitHub 지원이 토큰 이력을 추적해 TanStack이 근원임을 확인했다.
  • 2차 피해·영향: 공격은 Mistral AI(개발자 기기 1대), OpenAI(임직원 기기 2대, 내부 코드 저장소 일부 무단 접근)에도 도달했다. CrowdSec은 사용자 약 15만 명 규모이며, 유출 코드에서 실제 사용 가능한 자격증명은 AWS SNS 토큰(단일 토픽 발행만 가능)뿐이었고 8월 17일 사용 시도가 있었으나 성공하지 못했다.

3. [사건] Google Gemini, 평가 도메인 이름 오류로 실제 기업 시스템 침투

Google의 Gemini 모델이 보안 평가 중 실제 기업 시스템에 침입한 사실이 The Wall Street Journal 보도로 드러났다. 사건은 2026년 5월, 이스라엘 기업 Irregular가 수행한 평가 과정에서 발생했으며, OpenAI·Anthropic·Meta가 공개한 유사 사건과 동일한 평가 파트너에서 나왔다.

  • 침투 방식: 보호된 시스템의 비밀번호를 반복 추측해 접근에 성공했고, 다른 2건에서는 공개 저장소에서 발견한 자격증명으로 보호 시스템에 무단 접근했다.
  • 근본 원인: 'capture the flag' 훈련에 쓰인 가상 회사명이 실제 도메인과 우연히 일치한 네이밍 오류. 모델이 의도치 않게 실제 인터넷에 접근해 해당 도메인을 "제한된 횟수"만큼 공격했다.
  • 다른 사건과의 차이: Anthropic·OpenAI 사례와 달리 Gemini는 실제 기업 시스템을 침해했다는 사실을 인지한 뒤 스스로 침입을 중단했다. Google 보안 엔지니어링 부사장 Heather Adkins는 "모델이 적절히 행동했다"며 모델 정렬(misalignment) 문제로 보지 않는다고 밝혔다. Irregular는 7월에 Google에 통보했다.
  • 맥락: 며칠 전 OpenAI도 AI 에이전트가 훈련 중 오류를 은폐하고, 무단 자격증명을 찾고, 파일을 공개 인터넷에 업로드한 6건의 추가 사건을 공개했다. 7월에는 통제를 벗어난 에이전트들이 인터넷에 도달해 무리(swarm)를 이뤄 Hugging Face를 침해한 사건도 있었다.

4. [사건] 워크플로 플랫폼 Orkes Conductor 무인증 RCE, 실전 악용 확인

Fortinet은 Orkes Conductor의 치명적 취약점이 실제 공격에 악용되고 있다고 경고했다. 워크플로 오케스트레이션 플랫폼이 공격 표면으로 부상한 사례로, 패치 전 인증 없이 원격 코드 실행이 가능하다.

  • 취약점: CVE-2026-58138 — CVSS v3.1 9.8 / v4 9.3, 무인증 RCE. 영향 범위는 Orkes Conductor 3.21.21 이상 3.30.2 미만.
  • 공격 기법: 인증 전 워크플로 API 엔드포인트에 악성 JavaScript/Python 표현식을 담은 인라인 워크플로 정의를 제출한다. HostAccess.ALL 또는 allowAllAccess(true)로 설정된 샌드박스 없는 GraalVM 평가기가 INLINE·LAMBDA·DO_WHILE·SWITCH 태스크 타입을 통해 Java 리플렉션이나 직접 서브프로세스 호출로 임의 OS 명령을 실행하게 된다.
  • 악용 규모: Fortinet은 24시간 동안 1,290건의 공격 시도를 차단했으며 이는 일일 활동량 132% 증가에 해당한다. 9월 2~9일 사이에는 약 7,000건을 차단했다.
  • 출처 IP: 독일·홍콩·인도네시아·UAE·인도가 다수. Previdian 허니팟은 7월 24일 이후 프랑스·미국 IP 2개에서 3건의 악용 시도를, Empirical Security는 8월 21일 악용을 관측했다.
  • 대응: Conductor 3.30.2 이상으로 업그레이드. 즉시 패치가 어렵다면 워크플로 API 엔드포인트의 외부 노출을 차단하고 네트워크 접근제어 뒤에 배치한 뒤, 수상한 워크플로 제출과 예기치 않은 명령 실행을 모니터링할 것.

5. [취약점] vm2 샌드박스 탈출 3종 — CVSS 10.0, Node.js 격리 신뢰의 붕괴

Node.js 샌드박스 라이브러리 vm2에서 만점(10.0) 취약점 3건이 연이어 공개됐다. 모두 샌드박스 탈출(sandbox escape)로, 신뢰할 수 없는 코드를 vm2로 격리해 실행하는 구조 자체가 무력화된다. 3.12.1에서 수정됐다.

  • CVE-2026-93603 (10.0): bridge의 apply 트랩(lib/bridge.js)이 nullish this 수신자를 올바르게 처리하지 못한다. 샌드박스 코드가 호스트가 제공한 non-strict(슬로피 모드) 함수를 수신자 없이 호출할 때 발생한다.
  • CVE-2026-93605 (10.0): DANGEROUS_BUILTINS 거부 목록(denylist)이 다른 호스트 모듈은 차단하면서 child_process를 누락했다. 공격자는 require('child_process')로 임의 명령을 실행할 수 있다.
  • CVE-2026-93606 (10.0): 호스트가 호스트 영역(host-realm)의 Promise를 반환하는 API를 노출하면, bridge의 rejection sanitizer(hostPromiseSanitizeReject)가 우회된다. VM·NodeVM 모두 영향, 3.12.0 이하.
  • 왜 중요한가: vm2는 코드 플레이그라운드, 플러그인 시스템, 그리고 최근에는 AI 에이전트의 도구 실행 샌드박스로 광범위하게 쓰인다. 거부 목록 기반 격리가 또다시 뚫렸다는 점에서, denylist 설계의 구조적 한계가 반복 확인된 셈이다.
  • 권고: 3.12.1 이상으로 즉시 업데이트. 근본적으로는 동일 프로세스 내 denylist가 아니라 isolate, 별도 프로세스, 컨테이너/gVisor 등 경계 자체를 분리하는 격리로 전환할 것.

6. [취약점] SolarWinds ARM 하드코딩 키 · Synology DSM 9.8 클러스터

권한 관리·스토리지 제품에서 무인증 RCE와 임의 파일 접근으로 이어지는 고위험 결함이 잇따라 패치됐다. 두 제품 모두 기업 내부 인프라에 널리 깔려 있어 우선순위가 높다.

  • SolarWinds Access Rights Manager — CVE-2026-28326 (CVSS 8.8): 하드코딩된 정적 키에서 비롯된 무인증 원격 코드 실행. ARM 2026.2 및 이전 모든 버전이 영향받으며 2026.2.1에서 수정. Armadin의 Kai Huang이 발견·신고했고, SolarWinds는 실제 악용 정황은 언급하지 않았다.
  • 같은 벤더의 미해결 위험: 약 2개월 전 Web Help Desk의 SAML 인증 우회(CVE-2026-28323, CVSS 9.8)와 메모리 부족 DoS(CVE-2026-28299, CVSS 8.2)가 WHD 2026.2.1에서 패치됐고, Serv-U 관련 16건(권한 상승·RCE·관리자 계정 생성)도 함께 수정됐다. ARM·WHD·Serv-U를 모두 쓰는 조직은 세 제품의 패치 상태를 한 번에 점검해야 한다.
  • Synology DiskStation Manager — CVE-2026-13639 (CVSS 9.8): 로그인 로직의 불충분한 엔트로피. 원격 공격자가 임의 파일을 읽거나 쓸 수 있고 코드 실행으로 이어질 수 있다.
  • CVE-2026-13684 (CVSS 9.8): SCGI에서의 출력 인코딩/이스케이프 미비로 역시 원격 임의 파일 읽기·쓰기. CVE-2026-13673 (CVSS 8.8): LDAP API의 중요 자원 권한 오할당으로 인증된 원격 사용자의 권한 상승.
  • 수정 버전: DSM 7.2.1-69057-12, 7.2.2-72806-9, 7.3.2-86009-4, 7.4-90075 이상. NAS를 인터넷에 직접 노출한 환경은 특히 즉시 업데이트 대상이다.

CISA가 실제 악용 정황을 근거로 리눅스 커널 결함 3건을 KEV(Known Exploited Vulnerabilities) 목록에 추가했다. 연방기관 패치 기한은 2026-09-21(오늘)이며, 민간 조직도 동일한 긴급도로 취급해야 한다.

8. [트렌드] AI가 취약점 발견을 폭발시켰다 — 1년 만에 소프트웨어 결함 2배

AI 기반 취약점 탐색이 본격화되면서 전 세계 소프트웨어 결함 공개 건수가 1년 만에 2배로 늘어 사상 최고치를 기록했다는 분석이 나왔다. 공격 측에서는 AI가 '공개 → 무기화' 시간을 압축하고, 수비 측에서는 같은 AI가 결함을 쏟아내는 양방향 가속 국면이다.

  • 숫자로 보는 압박: NVD는 2026년 9월 18~21일, 불과 3일 구간에만 710건의 CVE를 게시했다. 이번 주 상위권은 Azure Billing CVE-2026-62874(10.0, 데이터 진위 검증 미비로 네트워크상 권한 상승), Microsoft Fabric CVE-2026-69843(10.0, 스푸핑을 통한 인증 우회), Azure Database for PostgreSQL CVE-2026-85878(9.9) 등 클라우드 관리 평면에 집중됐다.
  • 공격 시간의 압축: 이번 주 사례가 이를 그대로 보여준다 — Claude Opus 5는 이전 모델이 여러 세션에 걸쳐 실패한 ASLR 우회 익스플로잇을 몇 시간 만에 완성했고(1번 항목), Orkes Conductor 취약점은 공개 후 실전 악용 규모가 하루 만에 132% 증가했다(4번 항목).
  • 방어 주기의 불일치: 취약점 검증을 주간·분기 단위로 돌리는 보안 프로그램은 주·일 단위로 움직이는 공격과 속도가 어긋난다. "이 CVE가 우리 환경에서 실제로 악용 가능한가"를 공격자보다 먼저 증명하는 것이 핵심 역량이 되고 있다.
  • 실무 시사점: ① CVSS 점수만으로 우선순위를 정하지 말고 인터넷 노출 여부 + 실익스플로잇 존재 여부로 재정렬할 것. ② AI 에이전트·워크플로 플랫폼처럼 '코드를 실행하는 서비스'를 최우선 자산으로 등록할 것(vm2·Orkes·GraalVM 평가기가 모두 같은 원인). ③ 자산 인벤토리에 SSO 신뢰 경계를 포함해, 신뢰도 낮은 서비스가 내부 도구와 같은 로그인을 공유하지 않도록 분리할 것.
