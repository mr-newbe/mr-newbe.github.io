1. 프랑스 국세청(DGFiP), 훔친 직원 계정으로 세금 데이터 탈취 — 7주 동안 아무도 못 봤다

공격자가 프랑스 세무당국(DGFiP) 직원의 탈취한 비밀번호를 이용해 6월과 7월에 걸쳐 수십만 명의 납세자·기업 세금 데이터를 빼냈다. 세무당국과 프랑스 국가사이버안보기관(ANSSI) 어느 쪽도 데이터가 나가는 것을 보지 못했다. ANSSI가 화요일 공개한 보고서의 결론은 냉정하다 — 공격은 정교하지 않았고, 약한 로그인 보호, 제대로 분리되지 않은 네트워크, 모니터링의 공백 때문에 성공했다.

  • 두 개의 침투 경로: ① 일반 직원 계정(특권 없음)으로 들어가 다른 정부기관까지 도달 — 권한은 최소였는데 접근 가능한 데이터는 방대했다. ② 부동산 등기 데이터로 이어지는 파트너 포털 APEX(비밀번호 + 이메일 일회용 코드) — 측량사 PC가 침해돼 뚫렸다.
  • 탐지 실패의 구조: DGFiP SOC에는 이미 '탈취 계정' 대응 루틴이 있었다. 침해 계정을 탐지하면 비밀번호를 재설정했다. 이 루틴은 공격자의 일부 활동을 실제로 잡았지만 데이터 탈취는 놓쳤다. 6월 7일 탈취 계정을 이용한 검색이 시작됐고, 페이지당 요청 1회가 필요한 스크래핑 징후가 있었지만 단독으로는 오경보가 많아 함께 묶어야 경보가 됐을 신호였다.
  • ANSSI의 사각지대: 탐지 센서가 RIE·인터넷 출입구에만 있고 애플리케이션 로그 접근 권한이 없었다. 공격자가 실제 직원 계정을 썼기 때문에 네트워크 모니터링에는 아무 이상이 없었다. 8월 6일 ANSSI가 과거 센서 데이터를 뒤져 의심 IP 2개를 넘겼고 DGFiP는 차단·계정 5개 재설정을 했지만, 그때도 탈취 자체는 인지하지 못했다.
  • 7주: 8월 12일 공격자가 온라인 포럼에서 직접 주장하고 나서야 두 기관이 인지했다. 이후 총리 지시로 ANSSI 심층 감사가 시작됐다.
  • 시사점: 자격증명 기반 공격에서 로그인 성공/실패 모니터링은 아무것도 잡지 못한다. 최소 권한도 충분하지 않다 — 데이터 볼륨·조회 패턴 이상탐지가 없으면 '정상 계정의 비정상 사용량'은 영원히 보이지 않는다. ANSSI의 권고는 강한 인증, 전 업무 애플리케이션으로의 모니터링 확대, 접근 가능한 데이터 양 제한이었다.

2. 러시아 Star Blizzard, 가짜 행사 초대장으로 100개 이상 조직에 CosmicPulse 백도어

러시아 국가 해커 Star Blizzard(미국·영국·호주·캐나다·뉴질랜드는 2023년 12월 이 그룹이 러시아 FSB 중앙 18센터 소속이 거의 확실하다고 밝혔다)가 가짜 행사 초대장으로 표적을 속여 Windows 백도어를 설치하고 있다고 Microsoft가 밝혔다. 1월 이후 우크라이나 관련 인물·조직 100개 이상이 영향을 받았고 대부분 미국과 영국에 있다. 최소 1대가 감염된 것이 확인됐지만 침해 규모는 공개되지 않았다.

  • 기법 전환 — RedFlick: 올해 그룹은 ClickFix에서 Microsoft가 RedFlick이라 부르는 방식으로 옮겨갔다. Windows 예약 작업(scheduled task)을 이용해 CosmicPulse(Python 기반 백도어)를 설치한다.
  • 미끼: 초대장은 Chatham House, Atlantic Council 같은 잘 알려진 싱크탱크·NGO를 주최자로 사칭하며, 상당수는 표적 조직 내부에서 온 것처럼 위장한다. 첫 메일에는 첨부가 없고, 회신하면 비밀번호로 보호된 악성 문서를 보낸다.
  • iPhone 경로: Atlantic Council 테마 초대장에 회신한 사람에게는 Windows 백도어 대신 DarkSword 아이폰 익스플로잇 키트 링크가 갔다. Proofpoint가 3월에 이 테마 메일과 메일량 급증을 보고했고 Trellix는 3월 26일 발송 4건을 확인했다(익스플로잇 페이지가 오프라인이었고 익스플로잇 코드가 회수되지 않아 확신도는 '중간').
  • 감염 체인: PDF로 위장한 LNK 바로가기 → 원격 서버에서 MSI 설치본을 받아 예약 작업 등록 → C2에서 다음 단계 로드 → 제어판 항목으로 위장한 다운로더(기존 보고의 NOROBOT / BAITSWITCH) → CosmicPulse 설치. 6월 우크라이나 시민사회단체를 노린(우크라이나 디지털보안연구소 보고) 캠페인과 기법이 겹친다.
  • 탐지 포인트: Defender 검출명 Trojan:Script/RedFlick, Backdoor:Python/CosmicPulse와 예약 작업 3개 이름. Microsoft의 Defender XDR 헌팅 쿼리는 7일만 조회하므로 1월까지 거슬러 확인하려면 Sentinel 등 더 긴 로그 보존이 필요하다. 아웃바운드 SMB도 차단·제한하라고 권고했다.

3. 악성 npm 패키지 101개 'PhantomSub' — 개발자를 무단으로 WhatsApp 그룹에 끌어들인다

OX Security 연구진이 WhatsApp 그룹 구독 캠페인 'PhantomSub'에 악용되는 npm 패키지 101개 클러스터를 확인했다. 이 패키지들은 오픈소스 WhatsApp 라이브러리 Baileys를 악용해 피해자의 동의 없이 개발자 계정을 그룹에 추가한다. 누적 다운로드 49만 회, 그중 11.6만 회가 최근 30일간 발생했다.

  • 세 가지 변종: 변종 1(패키지 19개)은 런타임에 GitHub에서 채널 ID를 가져오고, 변종 2(60개)는 채널 ID를 소스에 평문으로 박아 두고, 변종 3(14개)은 인코딩·난독화해 숨긴다.
  • 수익 구조: 그룹 중 하나는 인도네시아 기반으로 보이며 봇 스크립트, 봇 제작 서비스, '프리미엄' APK, 소셜미디어 부스팅을 판매한다 — 팔로워 수 자체가 사회적 증거(social proof)로 쓰인다. 패키지 이름은 ourin-baileys, @nexustechpro/baileys, @chatunity/baileys 등 대부분 Baileys 포크를 사칭한다.
  • 공유 수혜자: 여러 패키지가 같은 채널 ID, 같은 원격 채널 목록, 같은 GitHub 계정을 공유한다. "채널을 공유한다는 것은 수혜자를 공유한다는 뜻" — 이름과 게시자가 달라도 팔로워는 결국 한 곳으로 모인다.
  • 배경: 2026년 8월 SafeDep이 악성 행위를 하는 Baileys npm 포크를 확인했고, 9월 초 Xygeni가 @dappaoffc/baileys-mod가 개발자의 인증된 봇 세션을 공격자 뉴스레터 채널에 구독시키는 사례를 공개했다.
  • 대응: 무단 추가된 WhatsApp 그룹을 확인해 차단하고, 악성 Baileys 패키지 차단 탐지 규칙을 설정하며, 개인 WhatsApp 계정 연결을 요구하는 패키지는 쓰지 않는 것이 권고된다. 4월의 DAEMON Tools 공급망 사건, 어제의 악성 npm 클러스터와 함께 패키지 레지스트리가 지속적으로 무기화되는 흐름의 연장선이다.

4. Kiteworks, 9시간 예방적 셧다운 중 '미공개 치명적 결함' 발견·수정

9월 26일 게시물에서 다룬 Kiteworks(구 Accellion)의 "임박한 제로데이 공격" 경고의 후속이다. 회사는 주말 동안 연방 정보기관과 협력해 예방적 셧다운 중 이전에 알려지지 않은 치명적 결함을 발견해 수정했다고 월요일 밝혔다. 지난 09-26 보도에서는 고객에게 9시간 시스템 오프라인을 권고하고 자체 호스팅 환경도 내렸는데, 그 창구에서 실제로 결함이 나왔다.

  • 범위: 결함은 고객 기반 1% 미만이 활성화한 기능에 국한되며, 악성 컨텍스트에서 그 기능이 오용될 수 있는 유형이다. 다른 Kiteworks 제품은 영향받지 않았다.
  • 대응: 셧다운 창구 안에서 수정을 개발·배포하고 전 환경에 추가 보호 계층을 적용했다. 익스플로잇된 증거는 없다. 9월 27일 셧다운 권고가 해제됐고 이상 징후가 관찰되지 않아 고객은 재가동이 권고된다.
  • CVE 미부여: 결함의 구체적 성격과 익스플로잇 방법은 공개되지 않았고 CVE ID도 아직 없다. THN은 공개 권고 계획을 회사에 질의했다.
  • 시사점: 벤더가 자발적으로 9시간 프로덕션 중단을 택한 드문 사례다. CISO 프랭크 발로니스의 말은 실무적으로 곱씹을 만하다 — "프로덕션 시스템을 내려달라고 요청하는 건 어떤 벤더도 가볍게 하는 결정이 아니다. 확실성과 편의 사이에서 고객 데이터를 도박하지 않겠다." 사후 통보형 침해 대응과 정면으로 대비된다.

5. ShinyHunters 수사 — 네덜란드 경찰, 암스테르담 24세 남성 체포

네덜란드 경찰이 해커 그룹 ShinyHunters 수사와 관련해 암스테르담 거주 24세 남성을 체포했다고 확인했다(경찰 국가수사·개입팀 X 게시, 9/28). 이달 초 체포됐으며 9월 29일 로테르담 지방법원 영장심문(raadkamer)에 출석했다. 09-28 게시물에서 다룬 FBI 침해 주장(PeopleSoft 제로데이, 2~3TB 탈취)의 수사 진전이다.

  • 신원: KrebsOnSecurity를 비롯한 복수 소스가 그를 Pepijn van der Stap — 네덜란드 보안업계 종사자이자 과거 해킹 혐의로도 기소된 이력이 있는 인물 — 로 지목했다. 9월 15일 경찰은 그가 어머니와 함께 사는 암스테르담 자택을 수색해 전자기기 여러 대를 압수했다.
  • 연결 고리 'Umbreon': ShinyHunters와의 연결은 별칭 Umbreon을 통해 이뤄진다. 그는 2021년부터 BreachForums에서 이 핸들과 포켓몬 이미지를 사용했다. FBIjobs.gov 침해 후 남긴 디페이스에는 같은 포켓몬의 ASCII 아트가 크게 들어갔고, 그 이미지는 2020년 ShinyHunters에 귀속된 HackForums 디페이스에 쓰인 것과 동일해 보인다 — van der Stap이 Umbreon 계정을 만든 해보다 1년 앞선다.
  • 해석의 여지: 이 마지막 단서는 양방향으로 읽힌다. 별칭이 그보다 먼저 이 맥락에 존재했다는 뜻이거나, 시점이 어색하게 겹친다는 뜻이다. KrebsOnSecurity는 수사에 정통한 소스의 더 날카로운 해석을 덧붙였다 — FBI의 침해 범위 파악이 아직 진행형이라는 것.
  • 시사점: 8월 프랑스 국세청 사건(1번 항목)도 그렇고, 최근 대형 사건들은 수사·귀속 단계에서 개인 신원이 특정되는 흐름이 뚜렷하다. 동시에 '보안 전문가가 다시 해킹 혐의로 서는' 구도는 업계 신뢰 문제와 접근 권한 관리 문제를 함께 던진다.

6. [취약점] Spectre-v2 'BTR'(Branch Target Reuse) — JIT 엔진이 처음으로 일시적 실행 창을 열었다

VUSec과 Scuola Superiore Sant'Anna 연구진이 웹 브라우저·언어 런타임·OS 커널의 JIT 엔진에 영향을 주는 새 Spectre-v2 변종을 공개했다. 코드명은 Branch Target Reuse(BTR)이며 여러 CPU 제조사에 걸쳐 영향을 준다. 핵심 통찰은 이렇다 — "현대 CPU는 자기수정 코드(SMC) 이후 아키텍처적 코드 일관성은 복원하지만, 오래된 간접 분기 예측 항목(즉 분기 타깃)을 반드시 무효화하지는 않는다."

  • 메커니즘: JIT 엔진에서 이 잔존 타깃은 원본 코드보다 오래 살아남았다가 코드 캐시가 다시 채워질 때 재사용되며, 일시적 execute-after-free 원시연산(transient execute-after-free primitive)을 만든다. 공격자는 이를 이용해 이미 폐기된 오프셋의 새로 생성된 코드로 일시적 제어 흐름을 가로챌 수 있다 — 소프트웨어 하드닝을 우회하거나 misaligned 가젯에 도달한다.
  • 영향 범위: SpiderMonkey(Firefox의 JIT 엔진), GraalVM, Linux 커널의 cBPF JIT에서 모두 영향이 확인됐다. 다만 익스플로잇 가능성과 유출률은 확연히 다르다. PoC로 Linux 커널 대상 end-to-end 익스플로잇 2건이 제작됐다.
  • 전제 조건: JIT 엔진에서 비특권 코드를 실행할 수 있고, 호스트 환경의 민감 데이터를 노출하려는 공격자를 가정한다. 훈련 청크 할당 → 분기 타깃 버퍼(BTB) 항목 삽입 → 청크 해제·주소 재사용 할당 → 간접 분기 유도 순으로 진행된다.
  • 완화: 책임 있는 공개 절차를 거쳐 Linux 커널에 완화책이 병합됐다(CVE-2026-64507, CVE-2026-64508). GraalVM은 JIT 코드 캐시 위치 무작위화로 영역 재사용을 방해한다. Mozilla는 IBPB(간접 분기 예측 장벽) 기반 완화를 검토했지만 현재는 사이트 격리(site isolation) 완성·배포를 우선하고 있다.
