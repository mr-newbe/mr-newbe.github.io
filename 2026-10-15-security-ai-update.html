1. [사건] Cisco Secure Email Gateway 제로데이 CVE-2026-76519 — 첨부파일 하나로 루트 권한, 실제 익스플로잇 확인

Cisco가 2026년 10월 14일, Secure Email Gateway(SEG)의 실제 악용 중인 제로데이를 패치했다. 메일 첨부파일 처리 결함으로 로그인 없이 장비 OS에서 root 권한으로 명령을 실행할 수 있다.

  • 원인: SEG의 Advanced Malware Protection(AMP) 기능 내 상대 경로 탈출(relative path traversal) — 첨부파일 처리 로직이 경로를 제대로 정규화하지 않는다.
  • 조건: File Reputation 서비스가 메일 정책에 할당되어 있고, Content Scanner Tools 버전이 25.3.0.5525 미만인 인스턴스. contentscannerstatus CLI와 Mail Policies → Advanced Malware Protection 체크박스로 확인한다.
  • 결과: 공격자가 임의 파일을 쓰고 이어서 root 권한 명령을 실행. Cisco는 공격자가 침해 흔적을 삭제할 수 있다며 방화벽·네트워크 로그 교차 점검을 권고했다.
  • 규모: Shadowserver 기준 인터넷에 노출된 SEG가 약 300대. Cisco는 클라우드 인스턴스에 완화책을 적용하고 잠재 침해 고객에게 개별 통지했다.
  • 대응: 최신 릴리스로 업그레이드 + 장비 자격증명·암호 자재 갱신 + 접근 제한. CISA KEV에 10월 14일 등록되어 연방기관 마감은 10월 17일이다.
  • 맥락: SEG는 반복 표적이다 — CVE-2024-20401(2024-07), CVE-2025-20393(최대 심각도), CVE-2026-76461(지난달 AsyncOS 메일 파싱 제로데이)에 이어 올해만 세 번째다.

6. [취약점] Nextcloud Collabora CODE 서버 CVE-2026-110447 (CVSS 9.2) — 무인증 웹셸, 9월 10일부터 실제 공격

Nextcloud의 선택 설치 앱 Collabora Online - Built-in CODE Server(패키지명 richdocumentscode)의 크리티컬 결함이 9월부터 실제 공격에 악용돼 서버에 웹셸이 심겼다. Collabora는 9월 11일 26.4.303에서 수정했지만 권고문은 10월 14일에야 공개됐다.

  • 결함 형태: 앱의 proxy.php가 로컬 CODE 서버가 죽어 있을 때(재시작·업그레이드·크래시) 이를 기동하는데, 이때 요청에서 온 텍스트(경로 포함)를 큰따옴표로 감싼 bash 명령에 그대로 삽입한다 — 셸은 큰따옴표 안의 $(...)도 실행한다. Nextcloud 코드를 전혀 로드하지 않는 독립 PHP 파일이라 프레임워크 방어가 없다.
  • 실제 공격: 한 관리자의 서버 2대 로그에 9월 10일 19:51, 9월 11일 09:56(UTC+2) 동일 IP에서 proxy.php?status 경로에 명령을 숨긴 요청이 찍혔다. 모두 26.4.302였다.
  • 공격자 행동: 한 줄짜리 PHP 웹셸을 앱 폴더에 디코드해 심고 uname -a 출력을 webhook.site로 전송한 뒤, *.kdbx·wallet.dat·keystore.json과 bitwarden·1password·.bitcoin·.electrum·.monero·.ethereum 같은 이름을 찾아 자격증명 저장소와 암호화폐 지갑을 뒤졌다.
  • ⚠️ 대응: 앱을 끄는 것으로는 부족하다 — 26.4.303 이상으로 업그레이드하거나 제거해야 한다. 수정본은 Nextcloud 30 이상을 요구하는데 29 이하는 EOL이고, 앱스토어는 여전히 취약본을 제공한다. 2025년 12월의 CVE-2025-66208(같은 스크립트의 다른 명령 주입) 수정은 이번 결함을 막지 못한다.

7. [취약점] curl HTTP/2 업로드 use-after-free CVE-2026-92392 — 서버가 클라이언트를 코드 실행, 8.23.0 긴급 수정

공격 방향이 서버 → 클라이언트인 결함. 악성 서버가 업로드를 받는 과정에서 클라이언트의 메모리를 오염시키고, 신고한 연구자가 이를 업로드하는 기기에서의 코드 실행까지 발전시켰다. curl 프로젝트는 릴리스 주기를 2주 앞당겨 10월 14일 curl 8.23.0에서 수정했다.

  • 영향 범위: curl·libcurl 8.12.0 ~ 8.22.0 (2025년 2월 이후 모든 릴리스) — CLI 도구와, 많은 프로그램이 쓰는 라이브러리 모두. curl 자체 4단계 척도에서 High이며 2023년 10월 SOCKS5 힙 오버플로 이후 첫 High다.
  • 공격 체인: 약 135KB 파일을 HTTP/2로 업로드 → 서버가 윈도우를 0으로 만들어 전송을 멈추고 응답 일부를 반환한 뒤 연결은 유지한 채 스트림을 리셋 → curl은 재시도로 판단 → 정리 단계에서 남은 업로드 바이트가 새 요청으로 해석되어 easy handle 포인터를 보유한 스트림이 열림 → 재시도가 HTTP/1.1 연결에서 끝나고 애플리케이션이 핸들을 해제해도 옛 연결이 그 포인터를 계속 사용한다.
  • 요건: 서버 인증서가 클라이언트 검사를 통과해야 하고, libcurl이 HTTP/2 지원으로 빌드되어야 한다. 실제 공격 사례는 보고되지 않았다.
  • 대응: 8.23.0으로 업그레이드(또는 8.14.3 / 8.16.2 / 8.20.2, Debian 13은 DSA-6558-1). 즉시 불가하면 HTTP/2를 쓰지 않는다 — --http1.1, 애플리케이션은 CURLOPT_HTTP_VERSION을 CURL_HTTP_VERSION_1_1로 설정.
  • 참고: 이번 릴리스에서 총 24개 CVE가 수정됐고 나머지 23건은 Low 등급이다. HackerOne 리포트(악성 서버 스크립트 + 코드 실행 재현 Docker 컨테이너)도 10월 14일 공개됐다.

10. [트렌드] AI 에이전트가 6일 만에 만든 Chrome 풀체인 — '프리-LLM 6~9개월'이 무너진다

보안기업 XBOW가 당시 미공개였던 Chrome 취약점 3개를 연쇄해, 사용자가 웹페이지만 열면 Windows에서 코드가 실행되는 풀체인을 만들었다. 사용한 것은 공개된 OpenAI GPT-5.6 Sol 모델을 돌리는 AI 에이전트들이고, 제작 기간은 6일이었다.
