1. Rust 크레이트 공급망 공격 — 2억 4,500만 다운로드 크레이트 3종에 빌드타임 멀웨어 주입

Rust 프로젝트가 손상된 유지관리자 계정으로부터 게시된 악성 릴리스를 crates.io에서 삭제했다. 인기 크레이트 arrayref(0.3.10), internment(0.8.7), append-only-vec(0.1.9)에 typosquat 의존성 'proc-macro1'이 추가됐고, 해당 크레이트의 빌드 스크립트가 컴파일 중 원격 페이로드를 다운로드·실행했다. 세 릴리스 모두 2026-08-20에 게시된 후 86~107분 만에 제거됐다.

  • 공격 메커니즘: 매니페스트에 proc-macro2의 typosquat인 proc-macro1 한 줄 추가 — 라이브러리 소스는 정상 proc-macro2 사본이라 빌드가 정상 완료됨
  • 페이로드: 빌드 시점에 base64 조각으로 C2 주소 재조립, TLS 검증을 무력화하는 커스텀 인증서 검증기 설치, OS·CPU별 4종 페이로드 선택 (Unix/macOS: /tmp/rust-setup 실행, Windows: PowerShell 스크립트를 wscript.exe로 은밀 실행)
  • 피해 범위: 세 크레이트 누적 다운로드 약 2억 4,500만 회 (RUSTSEC-2026-0260 등 공지 — 현재까지 실제 악용 증거는 없다고 기록)
  • 판단: Rust 보안 대응팀은 arrayref 저자(David Roundy)의 의도적 악행보다 컴퓨터/자격증명 탈취로 추정 — 패치 버전 없음, CVE 미지정
  • 대응: 개발자는 ~/.cargo/registry/cache에서 삭제된 크레이트 파일 검색, arrayref는 0.3.9 이하로 고정 권고 (Nextron Systems가 최초 발견·신고)

2. 러시아 해커 3개 클러스터, Google OAuth 피싱·WhatsApp 연동 남용으로 계정 탈취

Google 위협 인텔리전스 그룹(GTIG)이 유럽과 미국의 학계, 항공우주·방산, 정부, 싱크탱크 종사자를 표적으로 정당한 인증 흐름을 악용하는 러시아 연계 스파이 클러스터 3개(UNC6293, UNC5976, UNC7005)를 공개했다.

  • UNC6293: Ice Relic(APT29/Cozy Bear/Midnight Blizzard) 하위 클러스터 — 국무부 관료를 사칭한 앱 비밀번호 피싱, 외부 로그인 후 검증 코드 공유 유도 (2026년 6월에도 관찰)
  • UNC5976: 파일공유 사칭 도메인 12개 이상 구매 후 가짜 파일공유 페이지에 'Continue with Google' 팝업을 띄워 OAuth 토큰 수집 자동화 — 2026년 3월부터 활동, 악성 Excel 플러그인 'HEADRUSH'로 HTA 배포 (우크라이나 항공우주·방산 기업 표적)
  • UNC7005: WhatsApp 계정 연동 흐름 악용 — 군사·항공우주·방산·NGO/싱크탱크 중심, 우크라이나·아르메니아 지역 집중 표적
  • 특징: 소규모(5명 미만) 표적 피싱, 정당한 OAuth 흐름을 무기화해 MFA 우회 — Google은 관련 인프라 12개 이상을 교란

3. Citrix NetScaler 인증 우회 CVE-2026-19490 (CVSS 9.3) — 게이트웨이·AAA 서버 대상 치명적 결함 패치

Citrix가 NetScaler ADC 및 NetScaler Gateway의 보안 결함 2건에 대한 업데이트를 배포했다. CVE-2026-19490(CVSS 9.3)은 SAML 액션과 함께 Gateway(SSL VPN, ICA Proxy, CVPN, RDP Proxy) 또는 AAA vserver로 구성된 어플라이언스에서 인증을 우회할 수 있는 치명적 취약점이다.

  • CVE-2026-19490 (CVSS 9.3): 인증 우회 — 버전별 조건 충족 시 Gateway/AAA vserver 구성에서 원격 인증 우회 가능
  • CVE-2026-19489 (CVSS 8.8): 메모리 오버플로 — Large Scale NAT(LSN) 구성에서 SIP ALG 활성화 시 비정상 동작·DoS 유발
  • 패치 버전: NetScaler ADC/Gateway 14.1-73.32 이상, 13.1-63.21 이상, FIPS/NDcPP 빌드 포함
  • 완화: NetScaler Console의 Global Deny Lists 시그니처가 기본 활성화 — 설정 검증 문자열(add authentication samlAction 등)로 사전 점검 가능
  • 발견: JPMorgan Chase 펜테스트 팀의 Samarth Vashisht가 보고

4. Zimbra SNMP 명령 주입 CVE-2026-73570 (CVSS 8.9) — 비인증 RCE 활성 악용 경고

폴란드 CERT(CERT Polska)가 Zimbra Collaboration(ZCS)의 패치된 취약점이 야생에서 활발히 악용되고 있다고 경고했다. CVE-2026-73570(CVSS 8.9)은 명령 주입으로 이어져 Zimbra 사용자 권한으로 원격 코드 실행(RCE)이 가능한 결함이다.

  • 취약점: CVE-2026-73570 — SNMP 처리 과정의 명령 주입, 비인증 원격 코드 실행 가능
  • 패치 상태: 지난달 Zimbra 10.1.20에서 수정됨 — 미패치 서버는 즉시 업데이트 필요
  • 감염 지표: /var/log/zimbra.log의 의심스러운 서비스 재시작, /opt/zimbra/jetty/webapps/, /opt/zimbra/jetty_base/webapps/, /tmp/ 디렉터리의 최근 30일 내 생성 파일 점검
  • 배경: Zimbra는 지속적 표적 — 러시아 연계 Laundry Bear가 CVE-2025-66376(XSS)로 'ZimReaper' 페이로드를 전달해 메일 탈취하는 캠페인도 최근 공개됨

5. isolated-vm 샌드박스 탈출 취약점 (GHSA-864f-rcv7-6rh4) — AI 프로젝트에서 널리 쓰이는 JS 샌드박스 RCE 위험

보안 연구사 Endor Labs가 인기 오픈소스 JavaScript 샌드박스 isolated-vm(GitHub 2,900+ 스타)에서 샌드박스 내 코드가 호스트 프로세스의 메모리를 손상시킬 수 있는 치명적 결함을 발견했다. AI 관련 프로젝트에서 널리 사용되는 라이브러리다.

  • 공격 방식: python-snap7/snap7.dll 등 오픈소스 산업 자동화 라이브러리로 정상 모니터링 유틸리티를 모방한 커스텀 Python 스크립트 — S7comm 프로토콜로 PLC 메모리·설정·래더 로직 읽기/쓰기

7. '암호화 컨텍스트 주입' 공격 — 웹페이지 요약만으로 Grok 채팅 데이터 탈취 가능

AI 보안 기업 Adversa AI가 xAI의 Grok 챗봇이 사용자의 이름, 대략적 위치, 구독 등급, 대화 중 프롬프트를 공격자 제어 서버로 전송하게 만드는 'Cryptographic Context Injection' 기법을 공개했다. 사용자가 평범한 웹페이지 요약을 요청하면 악용이 시작된다.

  • 공격 체인: 암호화된 JSON 객체(PBKDF2 + AES-256-GCM)로 지시사항을 전달 → 콘텐츠 분류기가 읽을 수 없어 필터 우회 → Grok의 Python 실행 런타임이 복호화해 지시사항을 모델 컨텍스트에 주입
  • 데이터 유출: 복호화된 지시가 개인 세션 컨텍스트(이름·위치·등급·채팅 기록)를 URL 쿼리 파라미터에 실어 '추가 컨텍스트 조회' 네비게이션으로 외부 전송
  • 핵심 문제: 신뢰할 수 없는 외부 페이지가 권한 있는 인터넷 연결 도구 호출을 구동 — 효과적인 이그레스 경계·동의 게이트·출처 분리 부재
  • 공개 상태: 2026년 6월 3일 xAI 및 HackerOne 버그 바운티에 보고했으나 xAI는 구체적 대응·완화 타임라인 없이 묵묵부답 (8월 4일·10일 재연락에도 무응답, 8월 20일 기준 공식 권고 없음)

8. 'Zombie Card' 공격 — 만료된 Visa 비접촉 카드를 NFC로 부활시켜 실제 결제

매사추세츠대 애머스트(UMass Amherst) 연구진이 만료된 Visa 비접촉 결제 카드를 NFC를 통해 재활성화해 실제 매장 결제에 사용할 수 있는 공격을 시연했다. 카드 암호화를 깨지 않고 POS 단말이 읽는 만료일만 재기록하는 방식이다.

  • 공격 원리: 터미널이 검증하는 Application Expiration Date(TLV 태그 5F24)만 미래 날짜로 재기록하고, 발급사가 확인하는 Track 2(태그 57)는 유지 — 카드 서명과 암호문 모두 여전히 유효
  • 근본 원인: Visa Kernel 3는 두 만료일 표현의 일관성을 요구하지 않으며, fDDA 서명이 5F24를 전혀 포함하지 않음 — 카드 개인키 자체에 만료 개념이 없음
  • 실증: 5개 은행의 만료·재발급 카드로 테스트 — 은행 A는 수정 허용·다중 카드 동시 승인, B는 감지 후 단일 카드만 허용, D는 감지했으나 여전히 다중 카드 승인 등 정책이 제각각
  • 공개: 2026년 8월 12~14일 USENIX Security 2026 발표 — 2025년 5월 Visa·은행에 책임 공개, CVE 미지정·실제 악용 보고 없음 (Visa/EMVCo 권고 없음)
