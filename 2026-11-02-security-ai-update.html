1. Polymarket, 외부 스크립트 교체로 726개 지갑에서 264만 달러 탈취 — DebugBear DNS 하이재킹

예측시장 Polymarket이 사이트가 외부 업체에서 불러오던 페이지 속도 측정 스크립트를 공격자 코드로 바꿔치기당해, 10월 29일 로그인 상태의 트레이더 포지션이 매도되고 자금이 빼돌려졌다. 바꿔치기된 스크립트는 실사용자 모니터링(RUM) 업체 DebugBear의 것이었고, DebugBear는 자사 도메인 등록기관을 통해 DNS 레코드가 침해됐다고 밝혔다. 초기 조사 결과 공격은 특정 고객사 한 곳을 겨냥했다.

  • 자금 흐름: 공격자 지갑은 17:10 UTC에 첫 입금을 받아 18:02 UTC까지 33개 지갑에서 2,860만 POL과 포지션을 모았다. 18:19 UTC 기준 약 264만 달러였고, 18:28~18:38 UTC에 3개 주소로 다시 분산됐다.
  • 공격 방식: 악성 코드는 이미 로그인된 페이지의 권한을 그대로 재사용했다. 브라우저에 보관된 트레이딩 API 키를 읽고, 페이지에서 주문 실행 코드와 서명기(signer)를 찾아냈다. 지갑 로그인 계정은 포지션을 공격자 지갑으로 바로 옮겼고, 이메일 로그인 계정은 점점 불리한 가격으로 포지션을 매도한 뒤 자금을 이동시켰다.
  • 주목할 점: API 키만으로는 주문이 불가능하다(지갑 서명 필요). 코드에는 키·비밀번호·시드·개인키를 외부로 보내는 부분이 없었고, 대신 피해자 계정의 서명기에게 서명을 요청해 릴레이어로 넘겼다. Hudson Rock은 "서명 요청 자체가 사용자가 프롬프트를 보지 않고 서명했다는 증거는 아니다"라고 선을 그었다.
  • 대응·보상: Polymarket은 18:05 UTC 취소 전용 모드로 전환하고 1시간 내 스크립트를 제거, 전체 캐시 삭제·로그인 세션 초기화를 진행했다. 726개 지갑에 약 270만 달러를 환불(10월 30일까지 689개 완료)하고, 거래 중단 피해 약 5,500개 지갑에 119만 달러를 추가 보상해 총 390만 달러를 돌려준다. 사건은 수사기관에 이관됐다.
  • 교훈: 결제·거래 화면에 서드파티 스크립트가 붙어 있으면, 그 업체의 DNS/등록기관 계정이 곧 내 거래소의 세션 권한이다. SRI·CSP·서드파티 스크립트 인벤토리 없이는 이번 유형을 막을 수 없다.

2. Alpine Linux, GitLab 전면 재구축 — CVE-2026-97229 실제 익스플로잇 시도 8회

경량 리눅스 배포판 Alpine Linux가 개발 인프라 GitLab에서 10월 20~21일 원격 코드 실행 공격 시도를 받고 서버를 처음부터 재구축하고 전 사용자 비밀번호를 초기화했다. 노린 것은 GitLab 최대 심각도 결함 CVE-2026-97229로, CI/CD 파이프라인 설정에 조작된 정규식을 넣어 무인증 RCE를 일으키는 정수 오버플로다(Ruby에 번들된 정규식 컴파일러 Onigmo).

  • 왜 패치가 안 먹혔나: Alpine은 수정 버전(19.3.5)이 아닌 19.3.4를 설치했다. 이후 19.3.6으로 올렸지만, 이 결함의 완전한 수정에는 Ruby 패치가 필요했고 GitLab 공식 패키지는 Ruby를 번들하지만 Alpine의 자체 컨테이너 이미지는 그 Ruby를 포함하지 않았다.
  • 공격 결과: 워커 크래시 8회, 그중 4회는 부분적 성공. 끝까지 성공한 흔적은 없었으나, 공격자들이 Alpine의 GitLab 컨테이너 이미지를 내려받은 정황이 확인돼 공급망 공격 준비 가능성이 제기됐다.
  • 피해 범위: 10월 27일까지 저장소 커밋·패키지·릴리스에서 변조는 발견되지 않았고, 서명 키는 GitLab 서버에 없어 노출되지 않았다. 다만 익스플로잇이 성공했다면 사용자 정보, 비밀번호 해시, 2FA 시크릿, CI/CD 시크릿, 연동 자격증명, 비공개 프로젝트 내용이 노출될 수 있었다.
  • 재구축 결정: "코드 실행을 배제할 수 없고, 배제에 필요한 증거(로그·아웃바운드 연결 기록)가 이미 남아 있지 않다"는 이유로 재구축을 택했다. Alpine은 Docker 이미지의 기반 배포판이라 aports 빌드 레시피가 오염되면 하위 생태계 전체가 영향을 받는다.
  • 지금 할 일: GitLab 비밀번호 재설정, 그리고 10월 27일 공개된 alpinelinux/gitlab:19.3.6 이미지(Ruby 3.3.13 포함)로 교체. 같은 CVE를 쓰는 자체 빌드 환경은 "패키지 버전이 아니라 런타임(Ruby)까지 확인"해야 한다.

3. 아시아 정부 전용 Windows 10 빌드 노린 NetamLoader — Patch My PC CAB 재활용한 .NET 주입

카스퍼스키가 아시아 정부 기관 전용 커스텀 Windows 10 빌드를 겨냥한 "고도로 정교한 감염 체인"을 공개했다. 핵심은 이전에 보고되지 않은 .NET 어셈블리 로딩 프레임워크 NetamLoader로, 2026년 상반기에 처음 발견됐다. 특정 조직·행위자로 귀속되지는 않았고, 감염 시스템이 1대를 넘는지, 민감 정보 유출이 있었는지도 확인되지 않았다.

  • 드롭 위치: 악성 CAB 아카이브가 C:\Windows\SoftwareDistribution\Download\e4537a17…에 놓이고 내용이 …\Download\Install\로 풀렸다. 즉 정상적인 Windows 업데이트 패키지 저장 경로를 위장 장소로 썼다.
  • 구성: 7개 파일 중 4개는 Patch My PC(엔드포인트 관리 소프트웨어)의 정상 컴포넌트였다. 이 중 PatchMyPC-ScriptRunner.exe.config가 AppDomainManager 인젝션을 일으켜 Microsoft.HostIntegration.Connectors.dll을 실행시키고, 그 DLL이 fabric.config를 파싱해 Resources.resx를 로드한다.
  • 2단계 체인: Resources.resx에는 인코딩·압축·암호화된 다층 페이로드(XAML, .NET 어셈블리, JSON)가 들어 있다. XAML-1이 XAML-2를, XAML-2가 AMSI 우회용 XAML-2-1과 .NET 로더 + C2 설정(JSON-1)을 담은 XAML-2-2를 로드하는 구조다.
  • 공급망 의심: 카스퍼스키는 신뢰된 서드파티 벤더가 침해돼 하위 사용자에게 전달됐을 가능성을 제시했다. 정상 서명된 관리 도구의 파일 구성만 재활용하는 방식이라 파일 평판 기반 탐지가 쉽지 않다.
  • 탐지 관점: SoftwareDistribution\Download 하위의 비정상 CAB, 그리고 PatchMyPC-ScriptRunner.exe.config의 변조 여부를 확인해야 한다. AppDomainManager 인젝션은 합법 프로세스 안에서 실행되므로 부모-자식 프로세스 관계만으로는 잡히지 않는다.

4. ChatGPT 공유 링크 하나로 세션 내 코드 실행 — OpenAI P1, 발판은 MathLive 리스너

보안기업 Parameter는 악성 ChatGPT 공유 링크를 열기만 하면 로그인된 사용자 세션에서 공격자 코드가 실행되고, 한 번도 공유한 적 없는 비공개 대화까지 읽을 수 있음을 증명했다. 10월 18일 버그바운티로 신고했고 OpenAI는 8일 뒤 수정하며 P1(최고 등급)으로 올렸다. 실제 악용 정황은 보고되지 않았다.

  • 공격 조건: 피해자는 아무것도 설치할 필요가 없었다. 가장 안정적인 버전은 링크를 열고 Preview 버튼을 한 번 클릭하는 것, 이후 버전은 링크를 여는 것만으로 자동 실행됐다.
  • 샌드박스가 뚫린 3가지 설계: ① 대화 안의 인터랙티브 그래프가 메인 페이지에 수학 라이브러리 MathLive를 로드했고, ② MathLive가 보낸 프레임을 확인하지 않고 온스크린 키보드 설정 메시지를 받아들였으며(게다가 원시 HTML 운반 허용), ③ 그 HTML이 샌드박스가 없고 chatgpt.com 신원을 물려받는 프레임을 만들 수 있었다.
  • 마지막 단계: ChatGPT CSP가 인라인 스크립트는 막지만 YouTube 스크립트는 허용했기 때문에, 공격자는 YouTube에서 코드를 불러와 그 프레임 안에서 실행했다. Parameter는 "YouTube 차단만으로는 막히지 않는다"고 못 박았다 — 근본 원인은 신뢰되지 않은 Preview가 메인 사이트에 HTML을 밀어넣는 것이다.
  • 무엇이 가능했나: 화면을 긁는 방식이 아니라 ChatGPT의 로그인 API를 직접 호출했다. 최근 대화 목록 조회, 공유된 적 없는 비공개 대화 열람, 일부 내용을 연구진 서버로 전송, 그리고 "계정을 대신해 할 수 있는 모든 행위"가 가능했다.
  • 사용자 조치: 10월 26일까지 두 웹 프론트엔드 모두에서 공격에 쓰인 메시지가 거부되도록 수정됐다. 사용자가 따로 할 일은 없다. 다만 같은 패턴(postMessage origin 미검증 + HTML 운반 허용)은 다른 SaaS에도 그대로 존재한다.

5. FBI, 바이낸스 64억 3,000만 달러 탈취를 북한 TraderTraitor로 공식 지목 — 28억 5,000만 달러는 온체인 동결

미 FBI가 비밀경호국(USSS)·IRS 형사수사국(IRS-CI)과 함께, 바이낸스에서 탈취된 60억 달러 이상의 가상자산을 북한 연계 해킹 조직 TraderTraitor(Jade Sleet, Pressure Chollima, PUKCHONG, Slow Pisces, UNC4899)의 소행으로 공식 귀속했다. 규모는 64억 3,000만 달러로 2025년 2월 Bybit의 14억 6,000만 달러를 넘어 역대 최대 암호화폐 탈취다.

  • 자금 세탁: FBI는 조직이 탈취 자산을 주로 이더리움(ETH)으로 바꾸고 있으며, 이후 DeFi·즉시 스왑 서비스를 거쳐 추가 세탁 단계로 넘길 것으로 본다고 밝혔다. 세탁에 쓰이는 지갑 주소 목록도 공개됐다.
  • 동결 규모: 64억 3,000만 달러 중 28억 5,000만 달러가 Tether·Circle·Ripple·Arbitrum·Optimism에 의해 온체인에서 동결됐다. 탈취 자금은 11개 블록체인에 걸쳐 있었고 82%가 이더리움·비트코인이었다.
  • 국가 예산 규모: Elliptic은 "이번 단일 사건이 북한이 그간 탈취한 암호자산 총액을 거의 두 배로 늘렸다"며 DPRK 연계 조직의 누적 탈취액을 65억 달러 이상으로 추정했다.
  • 새 수법: 최근 이 조직은 악성화된 Terraform 프로바이더를 유통 경로로 쓰고, 껍데기 회사를 세워 보안·AI·블록체인·채용 업계 종사자를 직무 사칭으로 겨냥한다. Bash 로더가 OS별 악성코드를 골라 받고, 정보 탈취기 FLATROOF와 원격 제어 백도어 ROOFDECK을 설치하는 흐름이다.
  • 현황: 바이낸스는 11월 1일 06~09시(UTC)부터 1단계 출금을 재개했다. 입금 서비스는 사고 기간에도 정상 운영됐다. 개발자 입장에서는 Terraform 모듈·프로바이더 버전 고정과 서명 검증이 새 필수 점검이 됐다.

6. LXD·MicroCloud CVE-2026-112816 (CVSS 10.0) — 인증서 체인 검증 오류로 '신뢰 클라이언트' 사칭

Canonical의 LXD와 MicroCloud에서 최대 CVSS 10.0 결함이 나왔다. 공격자는 해당 클라이언트의 개인키 없이 신뢰된 클라이언트로 로그인할 수 있다. 조건은 네트워크로 HTTPS API에 도달하고, 신뢰된 클라이언트의 공개 인증서를 갖는 것 — 공개 인증서는 비밀이 아니다.

  • 결함의 정체: LXD·MicroCloud는 상호 TLS(mTLS)로 API를 노출한다. 서버는 클라이언트가 보낸 모든 인증서를 신뢰 저장소와 대조했는데, TLS 연결은 체인의 첫 번째(리프) 인증서에 대해서만 개인키 소유를 증명한다. 나머지 체인은 클라이언트가 임의로 붙일 수 있다.
  • 공격: 공격자는 자기 인증서 뒤에 신뢰된 클라이언트의 공개 인증서를 붙이는 것만으로 그 클라이언트로 인정받는다. 이후 클러스터와 VM에 접근하고, 사칭한 계정이 권한 있는 계정이면 호스트 root까지 얻는다.
  • 영향 버전: CVE 기록은 LXD 4.0.14, 5.0.10, 5.21.8, 6.9 이전 버전을 영향 대상으로 든다. 수정 snap은 6/stable 6.10.1, 5.21/stable 5.21.9, 5.0/stable 5.0.11, 4.0/stable 4.0.15, MicroCloud 3/stable 3.4.1.
  • MicroCloud 특이점: 여러 머신을 하나의 클러스터로 묶는 구조라, 멤버가 클러스터에 조인하는 순간의 공개 인증서를 캡처할 수 있으면 그 멤버로 로그인할 수 있다. 클러스터 조인 트래픽을 볼 수 있는 위치(같은 L2·미러링·프록시)가 곧 공격 위치다.
  • 노출 판단: 단독 LXD 서버는 기본적으로 로컬 소켓만 열고, 관리자가 core.https_address를 켜야 네트워크 API가 열린다. 즉 "네트워크 API를 켠 적이 있는가"가 첫 질문이고, 켰다면 snap 채널별 수정 버전 적용이 즉시 필요하다.

  • 지금 할 일: ① ClickHouse는 신뢰 네트워크로만 접근 제한(프록시·mTLS·사용자 인증 강제) 및 벤더 수정 버전 적용, ② Teltonika는 최신 펌웨어 적용 + WAN 측 웹 관리 콘솔 비활성, ③ 두 제품 모두 인터넷 노출 여부를 먼저 확인.

9. Bitcoin Core, 보안 결함 3건 공개 — 29.5·30.4·31.2·32.1에 백포트, 32비트는 여전히 영향

Bitcoin Core가 10월 28일 보안 권고 3건을 연달아 공개했다. 모두 Low 등급이고 "쉽게 발견 가능(easily discoverable)"으로 분류돼, 별도 엠바고 없이 포인트 릴리스와 동시에 공개됐다.

  • CVE-2026-117346 (undo 파일 오버플로): 채굴자가 다른 노드의 undo 데이터를 손상시켜, 정교하게 맞춘 리오그가 뒤따르면 노드가 종료된다. 블록 파일 위치가 32비트 정수여서 4GiB를 넘으면 위치가 감긴다. 64비트 위치 저장으로 수정됐고, 64비트 시스템용 수정은 29.5·30.4·31.2·32.1에 들어갔다.
  • 잔여 위험: 32비트 시스템과 FAT32에 블록을 저장하는 노드는 이번 릴리스에서도 영향받는다(FAT32는 4GiB 파일 한계). 해당 구성은 -reindex로도 완전 복구가 안 될 수 있어 64비트·비FAT32로 이전이 근본 대응이다.
  • CVE-2026-117349 (일시정지 피어 큐 무한 증가): pre-BIP31 피어는 영원히 일시정지 상태로 남을 수 있고, Bitcoin Core가 그런 피어에게도 공지(announcement)를 계속 큐에 쌓아 메모리가 무한히 증가한다.
  • CVE-2026-117350 (TCP urgent data OOM): 리눅스 이외 플랫폼에서 악성 피어가 TCP urgent(out-of-band) 데이터를 보내 노드 메모리를 고갈시킬 수 있다.
  • 일정·정책: 10월 27일 31.2·32.1, 10월 28일 29.5·30.4 릴리스. Bitcoin Core는 "간단한 LLM 프롬프트로 발견 가능한" 취약점을 easily discoverable로 분류해 즉시 포인트 릴리스하는 정책을 쓰고 있다 — AI 시대의 공개 정책 변화로 읽을 부분이다.

10. Microsoft, 9월 패치가 깨뜨린 Always On VPN 회귀 수정 — "이미 고쳤다"던 안내도 정정

마이크로소프트가 2026년 9월 Windows 11 보안 업데이트 이후 발생한 Always On VPN 연결 실패를 마침내 해결했다. 수정은 10월 프리뷰 업데이트 KB5127936을 설치한 사용자에게 적용된다. 회사는 앞서 이 문제를 10월 누적 업데이트에서 이미 고쳤다고 잘못 표기했다가 정정했다.

  • 증상: 자동 프로토콜 선택(IKEv2 + SSTP) 구성에서 VPN이 계속 "Connecting" 상태에 머물거나, 첫 연결 실패 후 재시도 시 "지정한 포트가 이미 사용 중" 오류가 뜬다.
  • 영향 범위: Always On VPN은 DirectAccess를 대체한 원격 접속 솔루션으로, 도메인 조인·비조인·Entra ID 조인 Windows 10/11·Windows Server 단말을 모두 지원한다. 즉 재택·지사 단말 전체가 대상이다.
  • 임시 우회: 프리뷰 업데이트를 건너뛰고 다음 패치 화요일까지 기다리려면, VPN 프로필을 자동 선택에서 단일 프로토콜(SSTP only 또는 IKEv2 only)로 바꾸면 된다. 조직 환경에 맞는 프로토콜을 골라야 한다.
  • 함께 고친 것: 같은 프리뷰 업데이트는 "Administrator protection" 기능이 켜진 상태에서 비관리자 사용자가 RDP로 접속하지 못하던 문제도 수정한다.
  • 실무 메모: 이번 건은 "패치가 만든 회귀"의 전형이다. 9월 업데이트 이후 VPN 헬프데스크 티켓이 늘었다면 KB5127936 적용 여부를 먼저 확인하고, 자동 선택 프로필을 쓰는 그룹 정책이 있는지 점검해야 한다.
