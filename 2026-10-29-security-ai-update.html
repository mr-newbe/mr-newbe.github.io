1. Volt Typhoon, 'Silent Train' 은닉 네트워크로 제로데이 4건 악용 — 피해자 수백 곳

Lumen Technologies의 Black Lotus Labs가 중국 연계 스파이 그룹 Volt Typhoon(Bronze Silhouette·Insidious Taurus·UNC3236·Vanguard Panda)이 운영한 은닉 접근 네트워크 Silent Train을 공개했다. 이미 2023년 말부터 가동된 이 인프라는 침해된 SOHO·IoT·엔터프라이즈 장비를 사슬처럼 회전시키며 제로데이 익스플로잇과 전략적 상시 접근에 쓰였다. 확인된 피해자는 통신사업자, 정부, 방위산업체, 위성·임무핵심 통신, 대학, IT 기업, 그리고 물·에너지·교통·해운·철도·항공·응급서비스 같은 핵심 인프라에 걸쳐 수백 곳이다.

  • 운영 모델: Silent Train은 장비를 "필요할 때 익스플로잇 → 표적에만 사용 → 작전 후 삭제 → 계속 교체"하는 방식으로 굴러간다. 덕분에 탐지·귀속·교란 기회가 크게 줄었고, Lumen은 여기에 안티포렌식·작전 분할(compartmentalization)까지 결합됐다고 평가했다.
  • 제로데이 4건: 이미 알려진 Versa Director 파일 업로드 취약점 CVE-2024-39717(VersaMem 웹셸)이 이 네트워크를 통한 4건 중 하나였다. 나머지 3건은 아직 상세가 공개되지 않았고, 별도로 Quest KACE 추정 제로데이(2025년 10월 패치)가 30곳 이상을 때린 것으로 의심된다.
  • 시작 시점의 의미: 인프라는 2023년 11월 무렵, 즉 중국 연계 IoT 봇넷 KV-botnet 1차 교란 직전에 형태를 갖췄고, 2024년 1월 말 2차 교란 이후 활동이 급증했다. 봇넷이 무너질 때마다 대체 은닉 인프라가 준비돼 있었던 셈이다.
  • 표적 선정 논리: 대규모 엔터프라이즈 환경 전체를 들여다보고 제어할 수 있는 관문 시스템만 반복해서 노린다. 단일 호스트 탈취보다 "가시성 확보"가 목적이라는 뜻으로, 초기 침해 로그만 지워도 흔적이 남지 않는 구조다.
  • 방어 포인트: ① SOHO·VPN·방화벽 등 엣지 장비의 펌웨어/모델 인벤토리를 만들고 지원 종료 장비부터 교체 ② 동일 ASN·회선에서 반복되는 스캔·인증 시도 상관분석 ③ 핵심 인프라 구간의 아웃바운드 화이트리스트 ④ 프록시 로그·NetFlow 보존 기간을 최소 1년으로 확대(귀속 분석의 전제).

2. 소니 ISP 자회사 침해 — 258만 건 유출, NTT도코모 회선 고객까지 영향

Sony Network Communications(소니그룹 자회사, 일본 ISP)가 약 258만 5,481건의 고객 개인정보 유출을 확인했다. 침해는 10월 19일 발생했고 10월 23일에 탐지돼 서버 격리·외부 통신 차단이 이뤄졌다. 유출 대상은 'So-net' 회원 DB 214만 1,986건과 'plala(S코스)' 44만 3,495건이며, 후자는 NTT도코모가 위탁 운영하는 도코모 히카리 회선 고객과 직접 겹친다.

  • 유출 범위: 은행·결제카드·계좌 정보는 포함되지 않았다. 다만 별도로 이메일 주소 5만 4,401건과 계정 비밀번호가 함께 노출돼 회사가 비밀번호 변경을 권고했다.
  • 2차 피해 신호: NTT도코모는 자사 고객에게 d POINT 클럽·유니버설 스튜디오 재팬(USJ) 캠페인 사칭 피싱을 경고했다. "티켓 당첨" 미끼로 개인정보 입력을 유도하는 전형적 유출 데이터 악용 패턴이다.
  • 영향 고지: 회선 서비스 전 Current 고객과 해지 후 6개월 이내 고객이 대상이다. 소니는 일본 개인정보보호위원회(PPC)에 신고하고 원인·범위를 조사 중이며, 10월 27일 기준 악용 정황은 확인되지 않았다.
  • 일본 연쇄 침해: 올해 일본은 KDDI(1,200만 건), IDC Frontier(랜섬웨어), 니혼콜롬비아(860만 건), 타임즈카(660만 건), GMO 오나마에 데스크톱 클라우드(아래 4번)까지 연속 피격됐다. 결국 일본 정부가 이번 주 월요일 긴급 회의를 열고 대응책을 논의할 정도로 이상 수준의 유출 러시다.
  • 실무 대응: 유출된 이메일·비밀번호 조합은 크리덴셜 스터핑의 원료다. 해당 ISP 고객은 즉시 ① 비밀번호 변경 + 재사용 중단 ② 패스키/2차 인증 전환 ③ '당첨·결제·배송' 링크는 공식 앱에서 직접 확인.

3. PHP2Shell + 커널 LPE 결합 공격, 25대 서버 루팅 — 미 정부 연계망 침해, 한국도 포함

이스라엘 보안기업 Dream이 AI 보조 정황이 뚜렷한 중국 연계 추정 공격을 공개했다. 2026년 10월 25일 관측된 작전은 PHP 취약점군 PHP2Shell과 리눅스 커널 권한상승 익스플로잇(CVE-2026-46300)을 결합해 미국·일본·대만·한국에 걸친 25대 서버를 루팅했고, 그중 3대는 미국 정부 연계 환경이었다.

  • 공격 체인: 특정 대형 벤더의 방화벽 소프트웨어(appweb 관리 서버)를 노려 PHP의 session.upload_progress 처리 결함을 트리거했다. 해당 펌웨어는 PHP 8.0.30 + 높은 메모리 한도를 쓰는데, 이 조합이 메모리 손상 단계를 가능하게 한다. 이후 커널 LPE로 root를 얻고 Active Directory로 이동해 자격증명 추출·디렉터리 열람을 수행했다.
  • 커스텀 무기화: Dream은 회수한 익스플로잇이 공개 PoC 복사본이 아니라 비공개 커스텀 빌드라고 밝혔다. 개념은 같지만 표적 방화벽 플랫폼에 맞춰 독자 개발된 형태다.
  • AI 흔적 — 핵심: 공격 인프라에서 Anthropic Claude Code 설치, FOFA API 키, DeepSeek·Kimi 계열 LLM을 붙인 공격형 플랫폼 aiscan 설정이 발견됐다. 또 약 40개 스크립트의 코드 구조·주석 스타일·일관성이 AI 보조 개발의 특징을 보인다.
  • 한국 관련: 피해 25대에 국내 시스템이 포함됐다. 노출된 PHP 기반 방화벽·어플라이언스 관리 인터페이스를 운영 중인 조직은 ① 관리 콘솔의 인터넷 노출 제거 ② PHP 8.0 계열 EOL 대응 ③ CVE-2026-46300 커널 패치(KEV 기한 10월 31일, 아래 10번) 확인이 시급하다.
  • 해석: PHP2Shell은 CISA가 실제 악용을 확인한 상태이고(10월 27일), 이제 AI로 무기화 속도와 커스터마이징 수준이 올라간 사례가 나왔다. "패치 전에 익스플로잇이 완성되는" 구간이 더 짧아지고 있다.

4. GMO 오나마에 데스크톱 클라우드 — 고객 서버 2만 6,739대 악성코드 감염, 데이터 유출 확인

일본 대형 도메인 등록업체 GMO 인터넷의 VPS 서비스 오나마에 데스크톱 클라우드가 침해됐다. 10월 20일 침투를 탐지했고 최대 26,739대 고객 서버에 악성코드가 설치됐을 수 있다고 공지했다. 이후 공격자는 랜섬웨어 실행을 예고했고, 회사는 자사와 고객 데이터가 실제로 온라인에 게시됐다고 확인했다.

  • 고객 대상 조치: GMO는 고객에게 인터넷 연결 차단과 PC 전원 종료를 권고했다. 서버를 켠 상태로 두면 암호화·추가 유출 위험이 커지기 때문으로, VPS 사업자 단위 사고에서 나온 이례적으로 강한 권고다.
  • 노출 자산: 결제 정보는 안전하다고 밝혔지만 MetaTrader 4/5(MT4/MT5) 자격증명과 트레이딩 계좌 정보가 노출·탈취됐을 수 있다. 비밀번호 재설정 + 활성 세션 강제 종료가 필요하다.
  • 왜 중요한가: FX 자동매매·트레이딩 봇을 VPS에서 돌리는 사용자는 거래소 API 키와 MT 단말 자격증명을 같은 호스트에 두는 경우가 많다. 서버 루팅은 곧 계좌 직접 조작 권한 탈취로 이어진다.
  • 함께 볼 사건: 10월 28일 소니 ISP 침해(위 2번)와 묶어 보면, 일본 호스팅·통신 사업자를 겨냥한 연속 공격이 공급자 경유 대량 피해 형태로 굳어지고 있다. 일본 정부가 긴급 회의를 연 배경이다.

5. FBI·유럽 수사기관, 방탄호스팅 'Virtualine' 도메인 압수 — 고객 3,000명 데이터 확보

미 법무부(DOJ)가 사이버범죄 포럼에서 활동한 방탄호스팅 Virtualine의 주 도메인 virtualine[.]net을 압수했다. FBI 주도로 독일 헤센 경찰, 네덜란드 미덴네덜란드 경찰, 영국 NCA, 그리고 OverRIPE·Lumen·Chainalysis가 참여했다. 서비스는 Secury·Massgod·Spamhouse·Lanedo·Omegatech 등 여러 이름으로 운영됐다.

  • 영업 모델: 법 집행기관·권리자의 신고를 차단해 주는 것을 내세웠고, DOJ는 피싱·스팸·카딩·포트스캔 등 "불법/블랙햇 활동"을 명시적으로 허용했다고 밝혔다. 비트코인 직접 결제(비수탁 지갑)를 받아 거래소 컴플라이언스 검사를 우회하고 자금을 세탁했다.
  • 자금 흐름(TRM): 랜섬웨어 조직이 약 5%, 러시아 마약 마켓이 약 44%를 차지했고, 대형 섹스토션 조직과 믹서도 주요 자금원이었다. 인포스틸러 StealC와는 올해 상시적 금융 관계가 확인됐다.
  • 수사 성과: 네덜란드 경찰은 림뷔르흐에서 물리 서버 수십 대를 압수해 가상 서버 수백 대를 오프라인화했고, 3,000명 이상 고객 데이터를 확보해 후속 수사에 들어갔다. 최소 2022년부터 랜섬웨어·봇넷·인포스틸러·피싱·아동성착취물 유통을 조력한 것으로 파악된다.
  • 여전히 부분 가동: 운영자는 새 사이트(virtualine[.]org)에서 혐의를 부인했고, 네트워크 프리픽스 일부는 아직 살아 있는 것으로 관측됐다. 압수는 "완전 종료"가 아니라 인프라 재편 국면으로 봐야 한다.

6. Oracle E-Business Suite CVE-2026-101767 (CVSS 9.8) — 패치 직후 인터넷 전체 스캔 시작

지난주 Oracle Critical Patch Update에서 수정된 CVE-2026-101767(CVSS 9.8)에 대한 대규모 인터넷 스캔이 관측됐다. Defused Cyber가 포착한 이 활동은 패치 공개 후 며칠 만에 이뤄진 것으로, 통상 익스플로잇 무기화 직전 단계의 신호로 읽힌다.

  • 취약점 내용: Oracle E-Business Suite의 Application Object Library(Core) 인증 결함. 12.2.3 ~ 12.2.15 버전이 영향받으며, 네트워크 접근이 가능한 무인증 공격자가 HTTP로 제품 전체를 장악(takeover)할 수 있다. 벡터는 AV:N/AC:L/PR:N/UI:N으로 사실상 "붙으면 끝" 유형이다.
  • 위험도가 높은 이유: EBS는 재무·구매·ERP 핵심 데이터를 들고 있고, 외부 파트너·공급업체 포털(iSupplier 등)로 인터넷에 노출되는 경우가 흔하다. 한 번 뚫리면 회계·조달 데이터 무결성까지 신뢰할 수 없게 된다.
  • 대응: ① 10월 CPU 적용 여부 즉시 확인(가능하면 12.2.15 최신 RU) ② EBS 로그인·iSupplier 엔드포인트의 인터넷 노출 최소화(WAF·VPN 뒤로) ③ `X-Forwarded-For`·비정상 경로 요청 로그 점검 ④ 침해 의심 시 DB 감사로그·세션 이력 보존 후 포렌식.
  • 맥락: 최근 오라클 제품은 패치 후 수일 내 스캔이 반복 관측된다. CPU 주기(1·4·7·10월)에 맞춘 패치 캘린더를 사내 SLA로 고정하지 않으면 매 분기 같은 구간이 노출된다.

7. EDK II PXE 취약점 CVE-2026-97631 (CVSS 9.5) — 16년 묵은 버퍼오버플로, Secure Boot 이전 코드 실행

대부분의 하드웨어 제조사가 UEFI 펌웨어를 만들 때 쓰는 오픈소스 EDK II에서 16년 된 버퍼오버플로가 발견됐다. TianoCore는 10월 22일 권고를 내고 CVE-2026-97631에 9.5점을 매겼다. 문제는 네트워크(PXE) 부팅 중에만 트리거되지만, 성공하면 Secure Boot 등 부팅 시 보안 장치가 로드되기 전에 코드가 실행된다.

  • 기술적 원인: PXE 드라이버가 ICMP 오류 메시지와 라우터가 보내는 상태 메시지를 고정 504바이트 영역에 복사하는데, IPv4·IPv6 양쪽 모두 크기 검사가 잘못돼 있다. 504바이트를 넘는 메시지 하나로 인접 메모리를 공격자 데이터로 덮어쓸 수 있다.
  • 공격 조건: 비밀번호도 기존 접근 권한도 필요 없고, 부팅 중인 짧은 창에 인접 네트워크 위치에서 조작된 메시지 1개를 보내면 된다. Red Hat·SUSE도 "인터넷이 아닌 인접 네트워크" 공격으로 평가했다. 단순 결과는 부팅 행(hang)이고, 코드 실행은 정확한 펌웨어 빌드를 알아야 해 난도가 높다.
  • 영향 범위: edk2-stable202608(2026-08-21)까지 전 버전. 결함 코드는 2010년 11월 커밋부터 들어가 있었다. AMI·Insyde·Phoenix는 물론 Microsoft의 강화 포크 Project Mu도 같은 레퍼런스를 쓴다. EDK II 표준 빌드에서 PXE가 기본 활성화돼 있다.
  • 패치 상황 — 가장 답답한 부분: 코드 수정은 존재하지만 안정 릴리스에는 아직 반영되지 않았고, 권고에도 패치 버전이 비어 있다. 즉 "오늘 설치할 것"이 없는 상태다. Intel은 보안 지원 중인 자사 상용 제품은 영향 없다고 밝혔고 Arm도 자사 포트폴리오에는 직접 해당 없다고 했다.
  • 완화: ① 데이터센터·서버에서 PXE/네트워크 부팅 비활성화 또는 필요 시에만 활성화 ② PXE·DHCP·TFTP가 닿는 L2 도메인 분리(VLAN·ACL) ③ 부팅 순서를 로컬 디스크 우선으로 고정 ④ BMC/펌웨어 제공사 권고 추적 후 수정 빌드가 나오면 즉시 적용. 가정·사무실의 로컬 디스크 부팅 사용자는 해당 없음.
