2. JFrog Artifactory 결함 2건 체인 — 익명 토큰이 관리자 권한으로 승격, 백도어 설치

클라우드 보안업체 Wiz는 공격자들이 JFrog Artifactory의 결함 2건을 연쇄 악용해 자체 호스팅 서버의 관리자 권한을 장악하고 백도어를 심었다고 보고했다. Wiz가 확인한 공격은 2026년 8월 15일부터 9월 8일 사이에 이뤄졌으며, JFrog는 그 이전에 두 결함을 모두 수정했기 때문에 미업데이트 서버만 영향을 받았다.

  • CVE-2026-42018: Artifactory가 내부 익명 사용자 토큰을 로그인하지 않은 호출자에게 발급 — 익명 접근이 꺼져 있어도 마찬가지
  • CVE-2026-42016: 그 저권한 토큰을 관리자 범위 토큰으로 교환할 수 있게 함 — Artifactory가 토큰의 서명과 발급자만 확인하고 '무엇을 할 수 있는지(권한 범위)'는 검사하지 않는 허점을 이용
  • 흔적 은닉·속도: 관리자 권한 작업이 로그에 이름 있는 계정이 아닌 'token:anonymous'로 남음. 첫 요청에서 새 관리자 계정 생성까지 5분 이내로 끝난 사례도 있었다
  • 영향 범위: 서버가 두 결함에 모두 취약해야 성립 — CVE-2026-42016은 7.133.11에서 범위가 끝나 7.146·7.161 브랜치는 해당 없음. CVE-2026-42018 수정은 7.146 브랜치에 4월 28일, 7.133 브랜치에 8월 12일(공격 개시 3일 전) 배포
  • 공격 후 행동: 관리자 계정 생성·잔존, Groovy 플러그인 악성 설치로 서버 코드 실행, 플러그인 실행 엔드포인트로 셸 명령·파일 탐색, HTTP 드로퍼로 /tmp 같은 전역 쓰기 가능 디렉터리에 바이너리 기록 후 C2 채널 개설, 커스텀 Rust 백도어 배치
  • 별개 결함 CVE-2026-82329 (CVSS 9.8): 9월 1~8일 별도로 악용된 인증 우회 — 기본 설정에서 무인증 공격자만으로 관리자 권한 획득 가능, 7.161까지 6개 브랜치 영향. CISA는 9월 2일 KEV 등록 후 9월 5일 연방 패치 마감을 설정했고, CDN 업체 Fastly는 9월 2일 하루에 약 406,000건의 악용 시도를 관측(트래픽 기준 시도이며 침해 건수는 아님). Wiz는 이 결함으로 장악된 서버에서 Artifactory 노드 간 등록에 쓰이는 '클러스터 조인 키'가 탈취된 사례도 확인

3. 중국 연계 UNC3569, Sogou 입력기 결함 악용해 GRAYRABBIT 백도어 유포 — 링크 클릭 한 번으로

보안업체 Gen Digital은 중국 연계 해킹 그룹 UNC3569가 윈도우용 Sogou 입력기(중국 최대 입력기)의 결함을 악용해 GRAYRABBIT 백도어를 설치했다고 발표했다. 공격은 조작된 링크 클릭으로 시작해 최종적으로 로그인 사용자가 할 수 있는 모든 권한을 공격자가 갖는 것으로 끝난다.

  • 취약 체인: Sogou는 단일 프로그램이 아니라 'sgbiz:' 커스텀 링크 타입으로 서로 통신하는 컴포넌트 집합 — 링크를 열면 Windows가 biz_helper.exe에 전달하는데, 이 핸들러가 '시작할 프로그램'은 확인하지만 '전달할 명령줄 인자'는 전혀 필터링하지 않음
  • 악용: 링크가 Sogou 설정 프로그램 SGMyInput.exe를 가리켜 공격자가 고른 웹 주소로 스킨 스토어(브라우저 창을 여는 유일한 화면)를 열게 함 — 주소 검증이 전혀 없음
  • 근본 원인: 그 브라우저는 Sogou가 자체 빌드한 Chromium 80(2020년 3월경) — 샌드박스와 동일 출처 정책이 코드 차원에서 꺼진 상태로 작성됨. 샌드박스가 없으면 페이지의 자바스크립트 결함이 곧 사용자 권한의 코드 실행이 되며, 브라우저를 빠져나오는 2단계 탈출도 필요 없음
  • 미완의 수정: Tencent의 패치는 진입 경로만 막았을 뿐 공격을 가능케 한 부분은 바꾸지 않음 — Gen이 조사한 패치 버전에서도 내장 브라우저 엔진은 2020년 버전이고 샌드박스는 여전히 꺼져 있었다. Tencent는 체인이 상대적으로 복잡하고 팝업 승인 등 사회공학이 필요하다고 반박
  • 배경: UNC3569는 2021년부터 활동하며 정부·교육·기술·금융 부문(주로 동·동남아시아)을 표적으로 삼아왔다. GRAYRABBIT은 원격 명령 셸, 양방향 파일 이동, 공격자 서버에서 추가 모듈 로드 기능을 제공한다. Sogou 입력기는 Citizen Lab의 2023년 연구 기준 월 4억 5,500만 명 이상이 사용하며 중국 입력기 시장의 약 70%를 차지한다

4. GitLab, 최고 심각도 경로 순회 결함 CVE-2026-85706 — 자체 호스팅 서버 즉시 패치 권고

GitLab이 자체 호스팅(self-managed) 설치 사용자들에게 최고 심각도(maximum-severity) 경로 순회 취약점 CVE-2026-85706에 대한 즉시 패치를 권고했다. 결함은 GitLab Community Edition(CE)과 Enterprise Edition(EE) 버전 19.3.2, 19.2.6, 19.1에서 수정됐다.

  • 원인: 저장소 커밋 API의 부적절한 경로 제한(path confinement)과 인증 강제 누락 — 무인증 공격자가 '특정 조건에서' 자격증명·시크릿 등 민감 정보를 포함한 임의 데이터를 서버에서 읽을 수 있음
  • 제보: 보안 연구자 's3ntago' 핸들이 GitLab의 HackerOne 버그바운티 프로그램을 통해 보고. 아직 실제 악용 징후는 표시되지 않음
  • 패치 안내: "이 버전들은 중요한 버그·보안 수정을 포함하므로 모든 자체 관리 GitLab 설치를 즉시 업그레이드할 것을 강력히 권장한다" — GitLab.com은 이미 패치된 버전을 운영 중이고, GitLab Dedicated 고객은 조치가 필요 없음
  • 배경: GitLab은 2023년 5월에도 소스코드·자격증명·토큰을 노출하는 최고 심각도 경로 순회 결함 CVE-2023-2825를 수정한 바 있어, 유사 유형의 재발이다

5. Microsoft Defender 'ShieldCrash' 제로데이 공개 — ShieldBreak(CVE-2026-69414) 미흡한 패치 우회, SYSTEM 권한

익명 연구자 'Nightmare Eclipse'가 9월 패치 데이 업데이트 직후 Microsoft Defender 제로데이 익스플로잇 'ShieldCrash'를 공개했다. ShieldCrash는 지난 6월 공개돼 7월에 패치된 RoguePlanet을 우회했던 ShieldBreak(권한 상승) 결함을 다시 우회하는 익스플로잇이다.

  • 영향: 연구자에 따르면 ShieldCrash PoC는 완전히 패치된 Windows 10·Windows 11·Windows Server 시스템에서 SYSTEM 권한을 획득할 수 있게 한다 — 다만 침해 시스템에 대한 쓰기 권한까지 주지는 않는다
  • 연구자 주장: "Microsoft가 ShieldBreak CVE-2026-69414를 제대로 패치하지 못했다. 특정 조건에서는 ShieldBreak가 일으킨 것과 정확히 동일한 문제를 여전히 유발할 수 있다"
  • 패치 상황: 공식 패치는 아직 없으며, BleepingComputer가 논평을 요청했을 당시 Microsoft 대변인은 즉시 답변하지 않았다. 연구자는 과거에도 Defender 결함에 대해 비공식 패치를 공개해 온 인물이다
  • 시사점: Defender의 권한 상승 결함 계보(RoguePlanet → ShieldBreak → ShieldCrash)가 이어지며, 패치 이후에도 동일 근본 원인이 남아 있는지 검증하는 것이 중요해졌다

6. EU 사이버 복원력법(CRA) 24시간 취약점 신고 의무 발효 — ENISA 단일 신고 플랫폼 가동

EU 사이버 복원력법(CRA) 제14조의 의무 신고 규정이 9월 11일자로 발효됐다. EU 시장에 디지털 요소를 갖춘 제품을 공급하는 제조사는 소재지와 무관하게(규정상 면제 대상 제외) 적용되며, 악용 중인 취약점을 인지하면 정해진 시한 안에 당국에 신고해야 한다.

  • 신고 시한: 악용 중인 취약점을 인지한 뒤 24시간 내 조기 경고(early warning), 이어서 72시간 내 상세 통보 — 중대 사고에도 동일한 시한 적용
  • 신고 창구: ENISA의 '단일 신고 플랫폼(SRP)'을 통해 CRA상 지정된 조정 CSIRT에 제출 — EU 제조사는 주 사업장이 있는 회원국의 CSIRT, 역외 제조사는 별도 규칙으로 조정 기관이 정해짐
  • 사용자 통지: 악용 취약점·중대 사고가 발생하면 영향받는 사용자에게 적절한 경우 통지해야 하며, 이용 가능한 수정·완화책 정보를 부당한 지연 없이 제공해야 함
  • 제재: 위반 시 최대 1,500만 유로(약 1,740만 달러) 또는 전 세계 연매출의 2.5% 중 큰 금액. 이번 신고 의무는 CRA의 '핵심 책임(core responsibility)'으로 분류돼 최대 과징금 대상에 해당
  • 남은 일정: 나머지 CRA 조항 대부분은 2027년 12월 11일 적용 — 보안 내장 설계, 기본 비밀번호 금지, 보안 업데이트 의무화, 적합성 평가 후 CE 마크 부착이 의무화된다

7. 마케팅 플랫폼 Brevo의 SAML SSO 결함 악용 — Trezor 고객 34.7만 명에게 피싱 메일

하드웨어 암호화폐 지갑 업체 Trezor는 자사 뉴스레터에 쓰는 3자 마케팅 플랫폼 Brevo가 침해되면서 고객 약 347,000명이 피싱 이메일을 받았다고 밝혔다. Brevo는 자사의 SAML 싱글사인온(SSO) 처리 방식을 공격자가 악용해 138개 계정에 접근했다고 설명했다.

  • 공격 방식: 공격자가 Brevo 계정을 만든 뒤 그 계정에 SSO를 활성화하고 정당한 Brevo 사용자들을 해당 SSO 구성으로 초대 — 이후 자체 신원 제공자(IdP)를 이용해 '초대된 사용자'로 로그인하는 방식으로, 자체적으로는 정상 동작에 해당
  • 유출 규모: 공격자는 총 43개 계정에서 연락처를 빼냈고, 그중 하나가 Trezor의 이메일 목록이었다. Brevo 고객사에는 Trezor 외에 BitBox, CoinTracking 등도 포함된 것으로 보인다
  • 피싱 내용: 제목이 "Critical Security Alert: STM32 Entropy Vulnerability(중대 보안 경고: STM32 엔트로피 취약점)"인 메일이 악성 웹사이트 링크를 포함해 발송됐다. Trezor는 피싱에 쓰인 구체적 수법은 공개하지 않았다
  • 시사점: SaaS 마케팅 플랫폼의 SSO 초대 흐름이 공급망 공격의 진입점이 될 수 있음을 보여주는 사례로, 고객사 이메일 목록이 통째로 유출되면 피싱 신뢰도가 크게 올라간다

8. Surfshark, 잘못 구성된 내부 테스트 서버 침해 — 시스템 바이너리·내부 설정 유출

VPN·보안 서비스 업체 Surfshark가 내부 시스템 일부가 침해된 사고를 공개했다. 사고 보고서에 따르면 인터넷에서 접근 가능하도록 잘못 구성된(misconfigured) 내부 테스트 서버에 위협 행위자가 접근했다.

  • 유출 범위: 서버에는 제한적인 내부 엔지니어링 자료가 있었고, 여기에는 일부 서비스의 '시스템 바이너리 일부와 내부 설정'이 포함 — 사용자 데이터에 접근할 수 있는 권한은 없었다고 회사는 설명
  • 자격증명: 코드 이력에 커밋돼 있던 내부 빌드 관련 자격증명을 발견하고 교체 조치
  • 대응: Surfshark는 억제·복구 조치를 진행하고 있으며, 광범위한 인프라 환경의 보안 태세를 평가하기 위한 추가 독립 보안 감사를 실시할 예정이라고 밝혔다
  • 시사점: 테스트·프록시용 내부 서버가 인터넷에 노출되는 사고가 반복되고 있어, 비운영 환경 서버의 구성 관리가 주요 위험 요인으로 남아 있다

9. IDScan, 1억 5,300만 건 운전면허 스캔 유출 확인 — 신원확인 클라우드 플랫폼 침해

신원확인(identity verification) 업체 IDScan.net은 다크웹에서 1억 5,300만 건 이상의 운전면허 스캔이 담긴 데이터베이스가 유통된 지 며칠 만에 고객 데이터가 무단 접근됐음을 확인했다. 루이지애나에 본사를 둔 이 회사는 렌터카 업체, 소매점, 대마초 판매점 등에 신분증 검사 서비스를 제공한다.

  • 회사 공지: 9월 4일 웹사이트에 "2026년 9월 1일경 데이터가 무단으로 접근됐을 가능성을 시사하는 정보를 입수했다. 즉시 시스템 보안 조치를 취하고 3자 전문가를 투입해 사고의 전체 성격과 범위를 파악 중"이라고 게시
  • 유출 가능 데이터: IDScan 클라우드 플랫폼 계정에 저장된 고객 정보로, 이름과 운전면허증 등 정부 발급 신분증 번호가 위험에 노출
  • 대응: 회사는 접근에 '비용이 따랐다'고 표현하면서도 영향 가능자에게 '만일을 대비해' 통지하고 무료 신용 모니터링과 신원 보호 서비스를 제공 중
  • 시사점: 신분증 원본 스캔을 대량 보관하는 신원확인 업체가 공급망의 단일 실패점이 될 수 있음을 보여주며, 유출된 신분증 데이터는 재사용·계정 개설 사기에 악용될 위험이 크다
