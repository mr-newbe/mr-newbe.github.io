1. Microsoft, NeedyMantis 공개 — DAEMON Tools 공급망 공격과 연결된 장기 침투 악성코드

Microsoft가 NeedyMantis라는 신종 악성코드 계열을 분석해 공개했다. 이미 침해된 네트워크에 장기간 접근을 유지하는 것이 목적으로, 통신사·대학·의료 비영리단체·정부간기구·정부 계약업체에서 소규모 표적 침해가 확인됐다. 활동 시점은 최소 2025년 10월까지 거슬러 올라간다.

  • 발견 경로: Microsoft는 2026년 4월 8일 이후 배포된 DAEMON Tools Lite 12.5.1 서명 설치본에 악성코드가 들어간 공급망 공격(개발사가 5월 5일 정상본으로 교체)을 추적하던 Kaspersky 조사 단서에서 NeedyMantis를 역추적했다.
  • 위장 파일명: 정상 소프트웨어 DLL을 사칭한다 — WinSparkle.dll(Poedit 업데이터), curl, Vim, TightVNC, 그리고 NVIDIA·Intel·Broadcom·Microsoft Office DLL 이름. 상세 분석 표본은 Poedit의 업데이트 구성요소를 교체한 케이스였다.
  • 통신·지속성: HTTPS로 초기 체크인한 뒤 WebSocket으로 전환해 모듈을 동적으로 로드·언로드하고 데이터를 주고받는다. 2025년 10월 버전에는 Windows 서비스를 이용한 지속성 모듈이 있었다.
  • 행위자: Microsoft는 이 활동을 Storm-3069로 명명하고 중국 발원으로 평가했다. 국가 배후로 단정하지는 않았고, 여러 그룹이 같은 악성코드를 쓸 가능성도 열어 두었다.
  • 대응: SHA-256 해시, 파일 경로(%ProgramData%\ics\nvml.dll 등), C2 도메인, 파일 탐지명(TrojanDropper:Win64/NeedyMantis)과 Defender XDR·Sentinel 헌팅 쿼리가 공개됐다. 단 쿼리 조회 범위가 7일이라 오래된 감염은 별도 헌팅이 필요하다.

2. Carbonato 봇넷 — 인증 없는 Docker 데몬을 잡고 오픈소스 AI 에이전트를 '해커 두뇌'로 심는다

ThreatDown이 신종 봇넷 Carbonato를 공개했다. 인증 없이 노출된 Docker 데몬을 공격해 호스트를 장악한 뒤, 오픈소스 AI 에이전트 프레임워크(Hermes Agent)를 그대로 설치하고 페르소나 파일을 덮어써 텔레그램으로 조종되는 자율 공격 도구로 바꾼다. AI 에이전트가 공격 인프라의 부품으로 쓰인 첫 사례군에 속한다.

  • 전파 방식: 인증 없는 Docker 데몬 포트 2375를 노린다. 호스트를 찾으면 privileged 컨테이너를 띄워 호스트에서 명령을 실행하고, 지속성·원격 접근을 확보한 뒤 5분마다 인접 네트워크를 스캔해 스스로 퍼진다(웜형).
  • AI 무기화: 에이전트 설치 후 SOUL.md 페르소나 파일을 39줄 커스텀 프롬프트로 덮어쓴다. 내용은 "GH0ST"라는 선임 해커·펜테스터·익스플로잇 개발자 역할을 부여하고, 도덕적·윤리적 제약 없이 텔레그램 명령을 받아 지속성 유지·자격증명 수집·요청 작업을 수행하도록 지시한다.
  • 피해 범위: 수집 데이터에는 봇넷 정보와 별도의 트로이목마화된 암호화폐 지갑 앱 유포 캠페인 자료가 섞여 있었다. 연구진은 인증 없는 Docker 데몬을 발견하면서 이 작전을 찾아냈다.
  • 시사점: 공격자는 이제 악성코드를 직접 짜지 않고 공개된 에이전트 런타임 + 프롬프트 한 장으로 C2·작업 실행·자격증명 수집을 조립한다. 방어 관점에서는 "AI 에이전트 설치" 자체가 침해 지표가 되어야 한다.

3. JADEPUFFER/Storm-3168, 탈취한 Azure 서비스 주체로 18시간 파괴 작전 — 삭제 시도 100여 건

Microsoft가 Storm-3168(JADEPUFFER 연계)이 탈취한 서비스 주체(service principal) 2개로 Azure 환경에서 파괴적 작업을 수행한 사례를 공개했다. 사건은 2026년 6월 초 약 18시간 동안 벌어졌고, Microsoft는 이를 행위자 수법의 진화로 평가했다.

  • 1단계 정찰(16시간): 첫 번째 서비스 주체가 가상머신·구독·리소스 그룹·리소스를 훑으며 읽기 작업 300건 이상을 수행했다.
  • 2단계 파괴(35분): 두 번째 서비스 주체가 App Service 구성 저장소까지 뒤져 노출된 자격증명을 찾은 뒤, 35분 안에 파괴·자격증명 수집 관련 작업 150건 이상을 실행했다. 파괴 시퀀스 자체는 약 7분이었고, 여기에는 스토리지 계정 삭제 시도 100여 건과 Key Vault·Function App·VM·App Service 대상 작업이 포함됐다.
  • 유출 경로가 '공개 GitHub 이슈': 피해 조직 직원이 client ID·client secret·tenant ID를 평문으로 공개 GitHub 이슈에 게시했다. 시크릿을 지운 뒤에도 편집 이력(public edit history)으로 계속 접근 가능했다. 시크릿 회수만으로는 끝나지 않는다는 전형적 사례다.
  • 맥락: JADEPUFFER는 Sysdig가 "LLM의 도움으로 처음부터 끝까지 수행된 최초의 랜섬웨어 작전"으로 문서화한 그룹이며, 초기 침투에 Langflow 결함 CVE-2025-3248을 악용했다. Microsoft는 같은 인프라가 여러 고객의 Azure App Service를 반복적으로 탐침한 것도 확인했고, 작업 분담과 타이밍상 자동화·스크립트 기반으로 평가했다.

4. RatHat 안드로이드 뱅킹 악성코드 — Gemini로 '돈 될 표적'을 골라내는 MaaS 콘솔

Cleafy가 안드로이드 뱅킹 트로이목마 RatHat의 운영 콘솔을 분석해 공개했다. 2026년 4월 이후 콘솔 배포 약 100건이 확인되며, 고객마다 별도 사본을 돌리는 전형적 악성코드-서비스(MaaS) 모델이다. Zimperium이 이달 초 유포 경로를 먼저 보고했다.

  • AI가 표적 순위를 정한다: 콘솔은 감염 폰에서 수집한 문자메시지·입력 비밀번호 등을 저장하고, AI 모델로 각 피해자의 은행 잔액을 추정해 '고가치/중간가치' 그룹으로 분류한다. Cleafy는 분석 표본에서 자금 이체에 AI를 쓴 흔적은 없고, 역할은 "어느 피해자가 운영자의 시간을 쓸 가치가 있는지 결정"하는 것이라고 밝혔다.
  • 무선 디버깅 + 원클릭 셸: 악성 앱은 접근성(Accessibility) 권한을 받아 무선 디버깅을 켜고 ADB 페어링을 수행한 뒤, 콘솔에서 버튼 한 번으로 UID 2000(셸 사용자) 권한의 셸을 얻는다. 별도 Go 프로그램이 리버스 터널로 접속을 유지한다.
  • 제거 저항성: 이 Go 프로그램은 피해자가 앱을 지워도 재부팅 전까지 계속 동작하며, 앱을 재설치하고 접근성 권한까지 되돌릴 수 있다. 화면 녹화 은폐 기능도 있어 알림 표시등이 켜지지 않는다(Android 14 이상에서는 자체 캡처로 대체).
  • 인프라: 관측된 IP의 절반 가까이가 싱가포르 등록 대역 AS4907에 몰려 있다. 콘솔은 운영자 계정 수를 제한하고 일부 구역을 비관리자에게 숨기는데, Cleafy는 이를 "개발자가 완전히 신뢰하지 않는 고객을 전제로 한 설계"라고 해석했다.
  • Gemini 양쪽 사용: 최신 버전은 운영자용 피해자 선별에 Gemini만 지원하고(Google AI Studio 키 필요), 기기에서는 기기 화면 레이아웃을 Gemini에 보내 어디를 탭할지 물어 제조사별 UI 차이를 우회한다. ESET이 2월에 보고한 PromptSpy와 같은 기법이다.

5. Bitget 3억 8,800만 달러 탈취 사후 분석 — 제3자 보안 제품 제로데이, 소액 테스트 후 본공격

Bitget이 3억 8,800만 달러 탈취 사건의 침투 경로를 공개했다. 공격자는 거래소가 사용하던 제3자 보안 제품의 결함(제로데이로 설명)을 악용해 고위 권한 내부 자격증명을 확보하고, 9월 24일 이를 이용해 지갑 시스템에 위조 출금 명령을 보냈다.

  • 공격 타임라인: 9월 24일 18:31 UTC에 소액 테스트 전송 2건을 실행했다. 금액이 리스크 통제 임계치 아래여서 경보가 뜨지 않았다. 약 30분 뒤 본격적인 대량 전송이 시작됐고, 지갑 시스템은 리스크 통제를 우회한 채 이를 실행했다.
  • 정상 자격증명의 무기화: CEO는 "합법적 자격증명을 사용했고, 활동을 일상적 관리 작업으로 위장하면서 흔적을 지웠다"고 설명했다. 탈취 자금은 핫·웜 월렛 일부에서 나왔고 콜드 월렛은 영향받지 않았다. 프라이빗 키 유출은 없다는 것이 현재까지 조사 결론이다.
  • 대응: 내부 접근 제한, 출금에 대한 독립 검증 추가, 이상 활동 모니터링 강화, 내부 자격증명 재발급, 영향 기능 비활성화. 제3자 보안 제품의 평가·배포 절차도 재검토한다. 고객 계정 잔액은 영향 없고 보호 기금(Protection Fund)으로 손실을 충당한다. 비트코인 출금은 재개, 나머지 자산은 10월 2일까지 단계적 재개.
  • 귀속: Bitget은 지난주 북한 연계 조직을 지목했고 CEO는 여전히 "동일 그룹"으로 본다고 밝혔으나 공식 보고서 전까지 그룹명은 밝히지 않았다. Mandiant와 SlowMist가 조사를 지원하며 이번 주 정식 사고 보고서가 나온다.
  • 시사점: 보안 제품 자체가 공격 경로가 됐다는 점, 그리고 출금 승인 로직이 '정상 자격증명 + 관리자 UI'를 신뢰한 나머지 소액 테스트 2건을 놓쳤다는 점이 핵심이다.

7. [취약점] 컨테이너·웹앱 인프라 — LXD 경로 순회 3건, Apache Roller 역직렬화, IdentityIQ 무인증 RCE

두 번째 취약점 묶음은 자체 호스팅 인프라다. 컨테이너 관리 평면과 오래된 웹 애플리케이션이 같은 날 9점대를 쏟아냈다. 공통점은 권한 검사 누락과 경로·심볼릭 링크 신뢰다.

8. [패치] Citrix NetScaler KEV 마감이 내일(9/30) — 실제 글로벌 익스플로잇 진행 중, Apple은 CoreGraphics 제로데이 패치

오늘의 패치 우선순위는 내일이 KEV 마감일인 Citrix NetScaler 2건이다. 지난주 글에서 "9/30 마감"으로 예고했던 그 두 건이며, 그 사이 실제 익스플로잇 시도가 광범위하게 관측됐다. 여기에 Apple의 CoreGraphics 제로데이 패치가 겹쳤다.

  • Citrix NetScaler (마감 2026-09-30, D-1): CVE-2026-88771(CVSS 9.5, 입력 검증 결함 — 무인증 임의 명령 실행)과 CVE-2026-88772(CVSS 9.5, 메모리 버퍼 경계 처리 — RCE/DoS). CISA가 KEV에 등재했고, Citrix는 "즉시 업그레이드"를 권고했다. Unit 42·Bitsight·Cybersecurity Dive가 모두 야생 익스플로잇을 확인했다.
  • Apple CoreGraphics 제로데이: CVE-2026-86950 — CoreGraphics의 out-of-bounds write로, 악성 파일 처리 시 임의 코드 실행에 이른다. Apple은 "표적 공격에 악용됐을 가능성이 있다"고 밝혔고, Meta Product Security가 발견을 크레딧받았다. 수정 버전: iOS·iPadOS 26.7.1(iPhone 11 이상, iPad Pro/Air/mini 해당 세대), macOS Tahoe 26.7.1, macOS Sequoia 15.8.1. 개선된 경계 검사로 해결됐다.
  • 다음 마감 순서: KEV 카탈로그는 현재 1,728건 규모다. Citrix 2건(9/30) 이후 가장 임박한 항목은 별도 확인이 필요하지만, 지난주 마감된 MikroTik RouterOS CVE-2026-67279·SharePoint CVE-2026-65660·WordPress Core CVE-2026-87902가 실제 익스플로잇 확인 상태로 남아 있으므로 미적용 조직은 마감 여부와 무관하게 조치가 필요하다.
  • 왜 이 두 건을 같이 봐야 하나: NetScaler는 원격에서 무인증으로 들어오는 문, CoreGraphics는 사용자가 파일 하나를 여는 순간이다. 외부 노출 장비와 단말 패치를 같은 날 처리해야 하는 전형적 조합이다.

9. [트렌드] AI 에이전트가 공격·방어 양쪽의 '표준 부품'이 됐다 — 오늘 뉴스 네 건이 같은 지점을 가리킨다

오늘 수집한 사건 중 네 건은 서로 다른 나라·다른 표적·다른 행위자의 이야기지만, "AI 에이전트를 어떻게 쓰고 있는가"라는 한 축에서 정확히 만난다. 도구가 아니라 운영 방식이 바뀌고 있다.

  • 공격 — 에이전트를 실행 부품으로 조립: Carbonato 봇넷은 악성코드를 새로 쓰는 대신 오픈소스 AI 에이전트를 설치하고 페르소나 프롬프트 한 장으로 텔레그램 지휘 체계를 만들었다(항목 2).
  • 공격 — AI로 표적을 '선별': RatHat은 Gemini로 피해자 잔액을 추정해 고가치 폰만 골라낸다(항목 4). JADEPUFFER는 앞서 LLM의 도움으로 랜섬웨어 작전 전체를 수행한 첫 사례로 기록됐고, 이번에는 서비스 주체 탈취 경로가 드러났다(항목 3).
  • 방어 — AI로 취약점을 '대량 발견': 같은 시기 GitHub Blog는 오픈소스 AI 보안 에이전트로 안드로이드 취약점 24건을 찾은 방법을 공개했다. 방어 측도 사람 손으로는 못 따라가는 속도로 후보를 뽑아낸다.
  • 그래서 남는 질문은 '권한'이다: 오늘 사고들의 실제 피해는 하나같이 자격증명과 권한에서 발생했다 — 평문으로 공개된 서비스 주체 시크릿(항목 3), 제3자 제품에서 새어 나온 내부 자격증명(항목 5), 인증 없는 Docker 데몬(항목 2), 접근성 권한을 얻은 뒤 UID 2000 셸을 여는 악성 앱(항목 4). 에이전트가 무엇을 할 수 있는지는 결국 그 에이전트가 물려받은 권한이 결정한다. 에이전트 IAM(신원·권한 관리)을 "나중에"로 미룰 수 없는 이유가 이번 주 데이터에 그대로 들어 있다.
  • 실무 번역: 에이전트·서비스 계정 전수 조사, 최소 권한 재설계, 시크릿은 편집 이력까지 남지 않는 곳에 보관, 그리고 노출된 관리 인터페이스(2375, 관리 CGI, XML-RPC) 차단 — 이 네 가지가 AI 시대에도 변하지 않는 기본값이다.
