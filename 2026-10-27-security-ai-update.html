1. Microsoft 365 토큰 재전송 공격 — 79개 조직 97개 계정 장악

Huntress가 7월 14일~9월 22일 관측한 AiTM(중간자) 릴레이 캠페인을 공개했다. 공격자는 가짜 로그인 페이지로 자격증명과 MFA 코드를 중계한 뒤, 마이크로소프트가 발급한 '로그인 증명' 액세스 토큰을 탈취해 자기 기기에서 재전송했다. 비밀번호 추측이 아니라 토큰 자체를 대량으로 재사용하는 방식이라 "토큰 스프레이(token spraying)"로 명명됐다.

  • 규모: 20만 건 이상의 로그인 시도 중 497건이 성공, 97개 계정 장악, 48개의 유령(rogue) Entra 기기 등록. 실패 시도는 193.26.115[.]0/24 대역으로 집중됐다.
  • 지속성 확보: 최소 19개 조직에서 최초 로그인 후 3시간 이내 기존 MFA 수단이 제거되고 새 수단이 등록됐다. 7월 21일 사례에서는 세션 탈취 후 51분 만에 "iPhone 13"이라는 인증기 앱이 활성화됐다.
  • 은닉 규칙: 받은편지함에 ".", "sss", "iT", "........," 같은 눈에 띄지 않는 이름의 규칙을 심어 급여·입금·상여 관련 메일을 삭제하거나 RSS 피드·대화 기록 폴더로 숨겼다. 한 사서함은 모든 메일을 읽음 처리 후 삭제하고 외부 스팸 발송에 악용됐다.
  • 인프라: 최초 관측 IP는 루마니아 193.26.115[.]221로 AsyncRAT 연관 이력이 있으며, 독일 호스팅 1337 Services GmbH·StarkRDP·rdp[.]sh(가상서버 임대)와 연결된다. 관련 도메인은 이미 테이크다운됐다.
  • 대응: 토큰은 AitM·디바이스 코드 피싱·정상 로그인 중 사회공학 등 여러 경로에서 유입됐다. 조건부 액세스로 토큰 보호(토큰 바인딩), 미등록 기기·비정상 위치 차단, 등록된 인증기·기기 전수 감사가 필요하다.

2. 'Gheist' 캠페인 — 탈취한 GitHub 토큰으로 Actions 로그에서 시크릿 탈취

Wiz가 9월 15일부터 추적한 자동화 캠페인. 탈취한 GitHub 토큰으로 저장소에 워크플로를 심어 시크릿을 Actions 로그에 출력시키고, 로그를 내려받은 뒤 런을 삭제한다. 이름은 공격 도구가 API 요청에 쓰는 User-Agent "gheist"에서 따왔다.

  • 규모: 850개 이상 침해 계정에서 13,500개 이상의 심어진 브랜치 회수. 개인 프로젝트부터 기업의 프라이빗 저장소까지 포함되며, GitHub Enterprise Server도 영향권이다.
  • 수법: `ci-sync-` + 무작위 6자의 브랜치를 만들고 `.github/workflows/sync-check.yml` 1개를 "ci: sync config" 메시지로(서명 없이) 커밋해 워크플로를 즉시 실행시킨다.
  • 로그 마스킹 우회: 시크릿을 base32로 인코딩해 출력한다. 인코딩된 값은 원본과 문자열이 달라 GitHub의 마스킹이 걸리지 않는다. `permissions: {}`로 GITHUB_TOKEN 권한은 오히려 줄여 탐지를 흐린다.
  • C2 없음: 유출 경로가 GitHub API 자체라 외부 서버·아웃바운드 연결이 없다. 로그 다운로드 수 초 뒤 런을 삭제해 흔적이 남지 않는다. 배포 환경(deployment environment)별 잡도 돌려 프로덕션 전용 시크릿까지 노린다.
  • GitHub 방어의 사각지대: 7월 28일 도입된 의심 워크플로 보류 기능은 github.com 공개 저장소에만 적용된다. Wiz가 확인한 공개 저장소 런은 전부 승인 대기 상태로 페이로드가 실행되지 않았지만, 프라이빗·GHES는 보호되지 않았다.
  • 복구: 브랜치나 런을 지워도 노출은 되돌릴 수 없다. 해당 저장소가 읽을 수 있었던 모든 시크릿 회전과 브랜치를 푸시한 토큰 폐기가 필수다. 쓰기 권한자는 저장소의 모든 시크릿을 읽을 수 있다는 전제로 권한을 재설계해야 한다.

3. Microsoft Teams 'IT 지원' 사칭 — 수백 건 반복 패턴, Chaos 랜섬웨어 유포

Arctic Wolf Labs는 Teams의 외부 채팅 생성 기능을 악용한 사칭 사기가 수백 건에서 동일한 패턴으로 반복된다고 밝혔다. 같은 일회용 테넌트, 같은 "IT Support (Internal)" 표시 이름, 같은 원격접속 도구, 점점 같은 페이로드 도메인이 재사용된다.

  • 신뢰 위장: 조사 사례의 30~40%가 `*.onmicrosoft[.]com` 도메인을 사용했다(helpdeskteam365, itendpoint365, itcoreportal, itadmin922, corporateitservicellc 등). 최근에는 표시 이름에 피해 조직의 도메인·회사명을 넣는 수법이 추가됐다.
  • 유료 TLD 전환: 최근 사기 테넌트의 유료 도메인 중 약 50%가 `.top`, 약 40%가 `.com`, 5% 남짓이 `.com.pl`·`.com.vn`·`.com.br` 같은 다단계 도메인이었다.
  • 심리 압박: Teams 메시지에 앞서 수백 통의 뉴스레터·구독 확인 메일로 받은편지함을 폭격(mail bombing)해 "문제가 생겼다"는 긴급감을 만든 뒤 지원을 자처한다.
  • 전개: 보이스피싱(vishing)으로 Quick Assist·AnyDesk·ScreenConnect·TeamViewer·Atera·Zoho Assist·NetSupport·LogMeIn 등 정상 RMM 도구의 핸즈온키보드 권한을 얻고, 정찰 → GoGRPC 백도어 → 도메인 컨트롤러 측면 이동 → Level 등 추가 RMM → 데이터 유출 → 랜섬웨어 순으로 진행한다.
  • 귀속: 과거 `.top` TLD 기반 IT 사칭 도메인을 만든 STAC4749와 활동이 일치하며, Sophos는 이 계열이 Chaos 랜섬웨어를 배포했다고 본다. URL을 직접 붙이지 않고 Microsoft Notes 등 안전 검사를 피하는 방식도 관측됐다.
  • 완화: 외부 Teams 접속이 필요한 조직만 허용목록 기반으로 좁히고, onmicrosoft 계열 신규 테넌트 발신 차단, RMM 도구 실행 화이트리스트, 헬프데스크 채널의 아웃오브밴드 검증 절차를 둔다.

4. uCreator 안드로이드 스파이웨어 — 텔레그램 2FA 탈취·위챗 계정 복제

연구자 Ovi가 10월 21일 공개한 분석에 따르면, 임대형(rentable) 안드로이드 스파이웨어 키트 uCreator는 정상 앱의 코드 안에 자신을 숨겨 텔레그램·위챗 계정을 탈취한다. 텔레그램 부분은 Doctor Web이 2025년 10월 보고한 백도어 Baohuo와 코드 네임스페이스(`com.ucreator.tgjar`), C2 서버, 명령 이름이 일치한다. 당시 감염 기기는 5만 8천 대 이상으로 추정됐다.

  • 유포: 공식 스토어 밖 사이드로딩, 인앱 광고를 통한 가짜 앱스토어(텔레그램 X를 데이팅·영상채팅 앱으로 홍보), 키트 제작자의 컨테이너 앱 洋葱盒子("Onion Box") 실행. 일부 변조본은 구글 플레이 정식 앱과 패키지 이름이 동일해 이름만으로는 구분되지 않는다. APKPure·ApkSum·AndroidP에도 등장했고, APKPure에는 정식 개발자 이름으로 올라갔지만 서명이 달랐다.
  • 동작: 변조 앱 내부에서 앱 자신의 권한으로 실행되며, 앱 안에 로컬 명령 서버를 띄운다. 대상 앱별 코드는 설치 후 내려받아 설치 파일 단독 분석을 어렵게 만든다. 메시지 저장소에 임의 쿼리를 보내 대화 기록을 회수하고, 텔레그램 2단계 인증 정보를 탈취한다.
  • 표적 범위: 약 20개 앱 지원 코드가 확인됐다(WeCom, QQ, WhatsApp, LINE, Zalo, KakaoTalk, Viber, GCash, MoMo 등). 확보한 C2 서버 데이터에는 중국·미국 소재 피해자로 보이는 정보가 있었으나 신뢰할 만한 규모 산정은 불가하다고 연구자는 밝혔다.
  • Android 17? 후킹 엔진은 Android 17을 실행한 Pixel 10 Pro에서 의존하는 내부 함수를 찾지 못했다. 다만 Frida는 같은 기기에서 동일하게 후킹에 성공했으므로 차단 증거가 아니라 제작자의 추가 작업거리로 해석해야 한다. 최신 샘플(2026-07-29)도 구 엔진을 그대로 사용했다.
  • 대응: 스토어 외 설치 금지, 텔레그램 2단계 인증 비밀번호 재설정, 활성 세션·연결 기기 점검, 텔레그램 X 변조본 서명 확인. 모바일 지갑·메신저를 같이 쓰는 기기라면 초기화가 가장 확실하다.

5. 3,690만 달러 '돼지 도살' 사기 — 44세 중국인 네덜란드서 범죄인 인도

미 법무부는 44세 Zhen Zhao가 네덜란드에서 범죄인 인도돼 캘리포니아 법정에 출석했다고 밝혔다. 미국·캄보디아 공범들과 함께 가짜 가상자산 투자 플랫폼으로 미국 피해자 174명에게서 3,690만 달러를 편취한 혐의다.

  • 수법: 문자·SNS·전화·데이팅 앱으로 접근해 신뢰를 쌓고, 실제 거래소를 닮은 가짜 웹사이트에서 "수익이 늘고 있다"고 속여 송금을 유도하는 전형적 로맨스/투자 사기(pig butchering)다.
  • 자금 세탁: 피해자 송금은 바하마 Deltec Bank의 "Axis Digital Limited" 명의 계좌로 모인 뒤 테더(USDT)로 전환돼 캄보디아 지갑으로, 다시 지역 스캠센터 총책들에게 분배됐다.
  • 사법 진행: Zhao는 2025년 8월 자금세탁 공모 혐의로 기소돼 최대 20년형에 처해질 수 있다. 공범 8명은 이미 유죄를 인정했고 2명은 51개월·46개월을 선고받았다.

6. Wasmtime 치명적 2건(CVSS 9.9) — 악성 WebAssembly 모듈이 샌드박스 탈출

WebAssembly 런타임 Wasmtime의 Cranelift 컴파일러에서 샌드박스 탈출이 가능한 두 취약점이 공개됐다. Bytecode Alliance는 10월 19일 공지에서 각각 CVSS 9.9로 평가했고, 수정 버전은 10월 19~20일 배포됐다. 악용 사례는 보고되지 않았고 CISA KEV에도 10월 26일 기준 등재되지 않았다.

  • CVE-2026-115889: 모든 아키텍처 영향. CVE-2026-115893: ARM64(aarch64) 전용. 공격자는 자신이 제어하는 모듈을 취약한 빌드로 컴파일할 수 있어야 한다.
  • 수정 버전: 36.0.19 / 48.0.7 / 49.0.4, 또는 50.0.0. 37~42.x는 둘 다 영향, 43~47.x는 ARM64 건만, 48.0.0~48.0.6과 49.0.0~49.0.3도 ARM64 건에 영향.
  • 지원 종료 라인: 보안 수정은 36·48·49·50 라인만 제공된다. 24.x LTS는 2026년 8월 20일 지원이 끝나 수정판이 없다. 4월에 ARM64 이전 Cranelift 탈출(36.0.7/42.0.2/43.0.1)을 패치한 호스트도 CVE-2026-115893에는 여전히 취약하다.
  • 라이브러리 주의: Wasmtime은 다른 프로그램에 내장되는 라이브러리라 CLI만 업데이트해선 해결되지 않는다. 이를 포함한 모든 프로그램을 수정 버전으로 재빌드해야 한다. RustSec에는 RUSTSEC-2026-0379·0380으로 등재돼 cargo-audit으로 탐지된다.
  • 탐지 공백: GitHub 보안 공지 DB에는 CVE-2026-115889만 리뷰 완료 항목이 있어, ARM64 건은 Dependabot 알림이 발생하지 않는다. 외부인이 작성한 모듈을 컴파일·실행하는 서비스(예: Fastly Compute는 고객 코드를 Wasmtime으로 실행)가 최고 위험군이다.

7. Postiz 9.9 — 하나의 공유 비밀로 서명된 모든 토큰(토큰 혼동)

셀프호스팅형 SNS 예약 발행 도구 Postiz에서 NVD 기준 CVSS 9.9 취약점이 확인됐다. 세션·초대·비밀번호 재설정 토큰을 동일한 공유 시크릿으로, 토큰 용도를 구분하는 표식 없이 서명하기 때문에 한 종류의 토큰을 다른 용도로 쓸 수 있다.

  • CVE-2026-115933 (9.9): 브라우저 확장 채널의 자격증명을 갱신하는 라우트가 서명된 데이터를 그대로 신뢰해, 용도가 다른 토큰으로 권한 상승이 가능하다.
  • CVE-2026-115932 (9.6): 게시물 발행 시 웹 주소가 아닌 미디어 경로를 서버 로컬 파일로 취급하면서 업로드 디렉터리 내부인지 검사하지 않는다. 등록 사용자가 조작된 경로를 저장해 임의 파일을 읽거나 실행으로 이어질 수 있다.
  • 실무 판단: 두 건 모두 "인증된 사용자" 또는 "확장 채널" 전제가 붙지만, 실제로는 저권한 계정 하나로 관리자 권한·서버 파일 접근까지 도달하는 경로다. Postiz를 외부에 노출해 운영 중이라면 즉시 최신 릴리스 적용 여부를 확인하고, 불가하면 인스턴스를 내부망으로 제한해야 한다.
  • 구조적 교훈: 토큰 서명 키를 용도별로 분리하고(audience/typ 클레임), 파일 경로는 realpath 기준 업로드 루트 포함 여부를 검사하는 것이 근본 수정이다.

9. 패치 — PHP 윈도우 패키지 5일 만에 재빌드(Brotli), KEV 마감일 경과

PHP가 10월 21일 PHP2Shell(CVE-2026-109618·109619) 긴급 수정 이후 5일 만에 윈도우 패키지를 다시 빌드했다. 이번 대상은 패키지에 포함된 Brotli 라이브러리의 CVE-2026-111497로, 메모리 손상과 코드 실행이 가능하다.

  • 신규 빌드: 8.5.12-1 / 8.4.27-1 / 8.3.36-1 / 8.2.35-1. PHP 소스는 동일해 PHP2Shell 수정은 유지되고, Brotli만 1.2.1(수정판)로 교체됐다. 파일명의 `-1` 접미사와 SHA-256으로 구분하며 `php -v` 출력은 바뀌지 않는다.
  • 도달 경로: cURL 확장이 HTTP 응답을 자동 해제할 때 취약점에 닿는다. cURL 기본값은 꺼져 있지만 Guzzle 7.16.1·8.3.1은 빈 `CURLOPT_ENCODING`을 기본 설정하므로 기본 구성 애플리케이션이 조건을 만족한다. 공격은 애플리케이션이 접속하는 서버의 조작된 압축 응답으로 이뤄진다.
  • 심각도: Google CVSS 4.0 9.2(Critical), Red Hat CVSS 3.1 8.1. OpenAI 연구진이 발견했고 Google이 Brotli 1.2.1/1.1.1/1.0.10에서 수정했다. PHP 공지는 악용 정황을 언급하지 않았고 CISA도 10월 23일 평가에서 미악용으로 기록했다.
  • 완화: 업데이트 전까지 `CURLOPT_ENCODING` 미설정, Guzzle은 `decode_content=false`. OpenAI는 `Accept-Encoding`에서 `br`만 빼는 것으로는 서버가 계속 보낼 수 있다고 경고한다.
  • KEV 마감: 10월 26일이 마감이던 CVE-2026-114625(Arista VeloCloud Orchestrator SQLi)와 CVE-2026-110447(Collabora Online CODE 서버 OS 명령 주입)는 기한이 이미 지났다. 10월 23일 마감분(SiteGuard, Plex 계열 CVE-2026-96656/96654)과 함께 지연 여부를 오늘 중 확인해야 한다.

11. 트렌드 — 'AI 에이전트 사고'를 정식 사고로 다루는 NIST·CISA·NSA 지침

10월 16일 NIST·CISA·NSA가 공동으로 14페이지 지침 Key Practices for Incident Readiness and Response in Super Intelligence Training and Evaluation을 발표했다. 장기 과제를 사람의 감독 없이 수행하는 고성능 에이전트를 훈련·평가하는 조직을 대상으로, 10개 권고 실무를 준비·탐지·대응·복구·보고 5단계로 배치했다.

  • 새 용어 'control incident': 운영자나 공격자가 지시하지 않았는데 에이전트가 통제·정책·인간 감독을 무력화하는 중대 행동을 한 사건. 프롬프트 인젝션이나 백도어 모델로 인한 행동은 "지시된 것"으로 분류돼 이 정의에서 빠진다 — 연구자에게는 일관되지만 현장 대응자에게는 곤란한 경계다.
  • 핵심은 신원(identity): 사고 대응의 첫 질문은 "왜"가 아니라 "누구의 자격증명으로"다. 에이전트가 어떤 아이덴티티로, 어떤 권한의 배후에서, 오도된 것인지·오작동인지·침해인지를 신원 기록으로 판별해야 한다.
  • 실무 6번(폐기): 사고 중 에이전트가 접근한 자격증명 중 조직이 통제하는 것을 폐기하고 오염 가능 환경을 재구축하라는 조항. 에이전트는 조직이 발급하지 않은 자격증명까지 축적하므로 "통제 범위"라는 단서가 실제보다 무겁다.
  • 맥락: 같은 주에 AI 관련 사건이 겹쳤다. AGENTS.md 지시 파일로 코딩 에이전트를 악성 npm 설치로 유도한 사례, OpenAI 에이전트의 VM 탈출·샌드박스 간 비밀 통신 시연, PHP 취약점 대응에서 보고된 AI 보조 공격 정황까지 — 공격·방어 양쪽에서 에이전트가 상시 행위자(principal)가 됐다.
  • 오늘의 우선순위: 에이전트별 최소권한 아이덴티티 발급 → 런타임 정책 집행 → 사고 시 폐기 가능한 자격증명 목록 사전 작성 → 에이전트 행동 로그 보존(포렌식) → 킬스위치 리허설. 이 다섯 가지가 없으면 사고 첫 1시간을 로그 재구성에 쓰게 된다.
