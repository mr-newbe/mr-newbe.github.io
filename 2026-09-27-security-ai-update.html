1. Lunex 스틸러 — AMD 취약 커널 드라이버로 보안 모니터링을 '눈멀게' 하고 브라우저 자격증명을 훔친다

우크라이나 정상 기업 사이트를 침해해 가짜 Cloudflare 검증(ClickFix)으로 유포되던 'Psychedelic Stealer'가 실은 Lunex라는 이름의 구독형 악성코드 서비스(MaaS) 플랫폼의 일부라는 사실이 Ontinue 분석으로 드러났다. 공격 체인은 4단계이며, 스틸러 투입 이전에 합법적이지만 취약한 커널 드라이버로 보안 제품을 무력화하는 단계가 들어간다.

  • 공격 방식: LunexLoader가 CMSTPLUA COM 객체로 UAC를 우회하고 → AMD Radeon Software의 취약 커널 드라이버 PDFWKRNL.sys(CVE-2023-20598)를 이용한 BYOVD(bring your own vulnerable driver)로 권한 상승 → 보안 프로세스를 '종료'하지 않고 PDB 기반 커널 콜백을 0으로 덮어 살아 있지만 보이지 않게 만든 뒤 → 정보 탈취 페이로드를 내려받는다.
  • 핵심 우회: 연구팀의 검증 테스트에서 HVCI와 현재 Microsoft 취약 드라이버 차단 목록(Vulnerable Driver Blocklist) 어느 것도 이 PDFWKRNL.sys 변종의 로드를 막지 못했다. 드라이버 해시는 2026년 3월부터 LOLDrivers 프로젝트에 등재돼 있었는데도 그렇다.
  • 수익 모델: 기능이 자격증명 탈취를 넘어 브랜드 사칭·피싱 페이지 생성까지 확장돼 있다. 스틸러가 '구독 상품'이 되는 흐름이 계속 확인된다.
  • 시사점: EDR 무력화의 표준이 '프로세스 죽이기'(요란함)에서 '커널 콜백 제로화'(조용함)로 이동했다. EDR 프로세스가 살아 있다는 사실은 더 이상 정상 동작의 증거가 아니다.

2. Oracle PeopleSoft 결함(CVE-2026-35273) 대량 재확산 — WAF를 우회해 웹셸을 심는다

Google이 Oracle PeopleSoft의 알려진 결함 CVE-2026-35273(CVSS 9.8, 무인증 RCE)에 대한 재차 대량 익스플로잇을 경고했다. ShinyHunters 연계 조직(추적명 UNC6240)의 캠페인으로, 교육·정부·기술 등 여러 산업이 표적이 됐다.

  • WAF 우회 기법: 요청 경로를 /PSEMHUB/ 대신 /%50SEMHUB/로 보낸다. 대부분의 WAF·리버스 프록시 규칙이 URL 디코딩 전의 리터럴 경로와 매칭되는 반면, PeopleSoft 애플리케이션 서버는 디코딩 후 취약 서블릿으로 라우팅한다는 비대칭을 노린다.
  • 침해 후 행위: JSP 웹셸 배치 → MeshCentral 에이전트 등 원격 접속 도구로 지속성 확보 → SSH 횡적 이동 → 알려진 사용자명/비밀번호 조합으로 내부의 다른 PeopleSoft 서버에 접속(루트 또는 NT Authority\SYSTEM으로 실행된 명령도 확인) → HR·급여·학생 기록 테이블에 대한 대량 쿼리·내보내기.
  • 위협 모델: UNC6240은 데이터 탈취 후 유출 사이트에서 공개를 위협하는 데이터 탈취 갈취형 패턴이 확립돼 있다. 초기 공격 당시 Mandiant는 100개 이상 조직에 통보를 진행했다.
  • 대응: 패치 적용 + 모든 퍼센트 인코딩 변형을 차단하도록 WAF 룰 수정, PSEMHUB.war 디렉터리 내 JSP 웹셸 점검, 애플리케이션 서비스 계정이 읽을 수 있는 자격증명 전면 교체.

3. SharePoint RCE·MikroTik RouterOS 결함, CISA KEV 등재 — '실제 익스플로잇' 확인

CISA가 금요일(9/25) 실제 익스플로잇 증거를 근거로 Microsoft SharePoint와 MikroTik RouterOS 결함 2건을 KEV 카탈로그에 추가했다. 지난주 이 게시물에서 '패치 시한'으로만 언급했던 항목들이 이제 익스플로잇 상세와 함께 확정됐다.

  • CVE-2026-65660 (CVSS 8.8, SharePoint 코드 인젝션): Microsoft는 최초에 '스푸핑' 취약점으로 분류했다가 이후 네트워크를 통한 코드 실행으로 권고를 정정했다. 이미 별도 항목으로 다룬 바 있는데, 실제 익스플로잇이 관측되면서 등급이 사실상 격상된 셈이다.
  • CVE-2026-67279 (MikroTik RouterOS): 무인증 클라이언트가 세션 채널을 열고 exec 요청을 보낼 수 있다. Polish CERT가 공개한 익스플로잇 체인 MikroTrick의 일부로, RouterOS 로그인 프로세스의 인자 주입 결함 CVE-2026-86060과 연계해 사용된다.
  • 체인 결과: \"두 취약점을 결합하면 관리 콘솔에 대한 완전한 무인증 접근이 가능하다\" — CVE-2026-67279가 세션 채널을 열고, CVE-2026-86060이 공격자 제어 정책 마스크로 로그인을 공급한다. 비밀번호나 SSH 키가 필요 없다.
  • 시사점: 라우터(엣지 장비)와 협업 서버가 각각 '무인증 관리자 장악'과 '네트워크 코드 실행'으로 같은 주에 KEV에 오른 것은, 경계 장비가 여전히 가장 수익성 높은 진입점이라는 뜻이다.

4. Elementor CSRF 결함(CVSS 8.8) — 관리자가 링크를 한 번 클릭하면 사이트가 넘어간다

1,000만 개 이상 WordPress 사이트에서 활성화된 Elementor Website Builder 플러그인에 CVSS 8.8의 CSRF 결함이 발견됐다. 아직 CVE 번호는 부여되지 않았다. Patchstack이 공개했고, 취약점은 4.3.0과 4.3.1 두 버전에만 영향을 준다(WordPress.org 통계상 이 두 버전만 200만 개 이상 사이트에 설치됨).

  • 근본 원인: Editor Events 모듈이 요청 URI에 elementor/v1/events/ 문자열이 어디에든 나타나면 쿠키 인증 REST API 요청에 대한 CSRF 보호를 건너뛴다. 검증 없이 신뢰할 수 없는 경로 조각 하나로 우회되는 전형적인 '부분 문자열 매칭' 설계 실수다.
  • 공격 방식: 로그인한 관리자가 조작된 링크를 열면 그 계정이 허용된 모든 REST API 동작을 대신 수행한다. 기본 설치 상태라면 /wp-json/wp/v2/users에 _method=POST&roles[]=administrator를 붙여 공격자용 관리자 계정이 하나 더 생성된다.
  • 영향: 4.3.0 이전 버전들은 해당 URI 패턴을 REST 라우트로 등록하지 않아 영향받지 않는다. 즉 신기능 도입이 만든 회귀다.
  • 대응: 4.3.2 이상으로 즉시 업데이트. 업데이트 전이라면 관리자 세션 상태에서 신뢰할 수 없는 링크를 열지 않는 것만으로도 실질적 위험을 줄일 수 있다.

8. [트렌드] 커널 드라이버가 EDR 무력화의 표준 부품이 됐다 — BYOVD와 스틸러의 MaaS 구독화

오늘 1번 항목의 AMD PDFWKRNL.sys 사례는 이번 주 표본에서 두 번째 BYOVD 확인 건이다. 개별 악성코드의 기법이 아니라 재사용 가능한 부품으로 굳어지고 있다는 신호라 따로 정리한다.

  • 기법의 위치 변화: BYOVD는 원래 랜섬웨어의 최종 단계(백신 죽이기)에서 쓰였다. Lunex에서는 스틸러 투입 전처리로 내려왔다. 즉 커널 드라이버 악용이 '고급 기법'에서 '기본 절차'로 이동했다.
  • 방어 도구의 한계: HVCI와 Microsoft 취약 드라이버 차단 목록이 이 변종을 막지 못했다는 검증 결과가 나왔다. 드라이버 해시가 LOLDrivers에 등재된 지 6개월이 지났는데도 실효 차단이 안 된다는 것은, 목록 기반 방어가 해시 변종·서명 위조 속도를 따라가지 못한다는 뜻이다.
  • 조용함이 목표: 프로세스를 종료하면 이벤트가 남지만, PDB 기반으로 커널 콜백을 0으로 덮으면 보안 제품이 살아 있는 채로 아무것도 못 본다. 텔레메트리 공백 자체를 탐지 신호로 삼아야 하는 이유다.
  • 수익 구조: Lunex는 자격증명 탈취 + 브랜드 사칭·피싱 페이지 생성까지 묶어 구독형으로 판다. ClickFix 유포망(지난주 게시물에서 1만 7천 개 URL·3천 개 활성으로 집계된 그 인프라)과 결합하면 '악성코드 + 유포 + 피싱 페이지'가 한 사업자가 제공하는 패키지가 된다.
