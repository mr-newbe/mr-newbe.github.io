1. [사건] Ivanti Connect Secure 제로데이 3개 연쇄 — '완전 패치된' VPN에서 루트 권한, 세 번째는 아직 미패치

보안기업 Volexity가 2026년 10월 13일, Ivanti Connect Secure(ICS) VPN 어플라이언스의 제로데이 3개를 연쇄해 로그인 없이 루트 권한으로 명령을 실행한 사례를 공개했다. 피해 어플라이언스는 사고 당시 22.8R2.4로 최신 패치가 적용된 상태였고, 공격은 10월 3일부터 시작됐다.

  • 추적 번호: CVE-2026-104935 (Ivanti CVSS 8.6) — 인증 우회 + 원격 코드 실행 결함 두 개를 함께 묶은 번호. 나머지 하나인 권한 상승 결함은 아직 미패치로, Ivanti는 '향후 몇 주 내 릴리스'라고 밝혔다.
  • 수정 버전: 22.8R2.5 / 25.1.1.2 / 25.1.3.0 / 25.1.3.1 — 영향 범위는 '25.1.3.0 미만'. CISA는 KEV에 등록하며 악용 상태를 'active', 기술적 영향도를 'total'로 표기했고 연방기관 패치 마감일은 2026-10-16이다.
  • 공격자: Volexity가 UTA0576으로 추적하는 미문서화 조직. LDAP 도메인 자격증명과 AD 메타데이터를 탈취하고, LAPS 비밀번호·BitLocker 복구키를 AD에서 검색했으며, 커스텀 Kerberos 도구로 자격증명을 검증하고 비밀번호 스프레이를 수행했다. 백도어·웹셸은 남기지 않았다.
  • '무결성 검사 도구'가 못 잡는다: 익스플로잇이 라이브러리 코드를 메모리에서만 바꾸고 설정 데이터를 원복하기 때문에 Ivanti Integrity Checker Tool을 회피한다. 침해 확인은 네트워크·메모리 포렌식으로만 가능하다.
  • 침해 지표(IOC): 대량 요청되는 /dana-na/auth/url_default/welcome.cgi, URL 경로와 값이 어긋나는 X-DSCGI-PATH 헤더, /data/.icscap/ 디렉터리, 공격자 호스트 108.165.147[.]64.
  • AI 각주: Volexity는 UTA0576이 익스플로잇 개발과 침해 후 활동에 LLM을 활용했을 가능성을 '중간 신뢰도'로 평가했다. 동기(동기 부여)는 첩보보다 범죄 쪽일 가능성이 낮은 신뢰도로 제시됐다.
  • 별건: 같은 공지에서 Ivanti는 Xtraction CVE-2026-106042(9.9)와 Neurons Patch for Intune CVE-2026-109412(9.9) 패치도 함께 발표했다(악용 정황 없음).

2. [사건] 컨테이너·패키지 레지스트리 신뢰 붕괴 — Docker Hub 계정 위장(CVE-2026-105445)과 npm 신뢰 발행 1,500개 패키지 탈취

소프트웨어 공급망의 두 관문에서 같은 날 '레지스트리가 신원을 확인하지 않는다'는 결함이 드러났다. 컨테이너 이미지와 npm 패키지는 그 위에 올라간 코드를 신뢰하는 근거 자체이기 때문에, 두 결함 모두 공급망 리스크로 분류됐다.

  • Docker Hub (CVE-2026-105445, critical): 2024년 8월 26일 도입된 '개인 계정 → 조직 전환' 기능이 개인 액세스 토큰(PAT)을 새 소유자에게 재할당하면서 비밀 값을 교체하지도, 대상자 동의를 받지도 않았다. 공격자는 자기 계정을 조직으로 전환한 뒤 피해자를 소유자로 지정하는 것만으로, 피해자의 PAT로 인증해 저장소 이미지를 pull·push·delete할 수 있었다. Docker는 9월 30일 신고 접수 후 4시간 이내에 프로덕션 수정을 배포했고, 이전된 토큰으로 이뤄진 304,000건의 push를 조사해 악용 증거는 찾지 못했다고 밝혔다.
  • npm Trusted Publishing (Bloom Security): 2025년 7월 정식 도입된 신뢰 발행은 유지보수자가 지정한 GitHub 저장소·워크플로만 패키지를 발행하도록 묶는 구조다. 그런데 npm이 저장소를 이름(owner/repo 슬러그)으로만 기록하고, 이름 바꾸기·이전에도 살아남는 영구 숫자 ID를 검증하지 않았다. 유지보수자가 저장소 이름을 바꾸거나 삭제/이전하면 슬러그가 풀리고, 누구나 같은 이름의 저장소와 같은 파일명의 워크플로를 만들어 남의 패키지 발행 자격증명을 받아낼 수 있었다. 노출 규모는 1,500개 이상 패키지, 총 10M+ 다운로드(월 1M+)이며, 이 방식으로 발행된 릴리스는 정상적인 출처 증명(provenance)까지 붙는다.
  • 완화: GitHub는 첫 발행 전까지 검증되지 않은 신뢰 발행 설정을 생성 48시간 후 만료시키고, 복제 수가 많은 저장소는 계정명 변경·삭제 시 이름을 회수한다. 그래도 '점유 가능한 슬러그'는 남는다는 점이 연구진의 경고다.

3. [사건] Meta, GitHub 저장소 침해로 1,500명에 개인정보 유출 통지 — 직원 자격증명이 뚫렸다

Meta가 약 1,500명(대부분 미국 소재 직원)에게 개인정보가 영향을 받았다고 통지하기 시작했다. 외부 조직이 직원의 탈취된 자격증명을 이용해 회사의 일부 GitHub 저장소에 접근한 사건으로, 발견 자체는 몇 주 전이었고 통지는 10월 13일부터 이뤄졌다.

  • 비율: 탈취된 데이터의 99%는 제품 관련 소스코드(비즈니스 데이터), 나머지 1%가 개인정보. 개인정보는 회사 정책을 위반한 채 저장소에 실수로 함께 올라가 있던 것이며, 상당수는 합성·비식별 테스트 데이터여서 공격자가 진짜 기록과 구분하기 어려울 수 있다고 Meta는 설명했다.
  • 대응: 공격자 접근 차단, GitHub·수사기관 공조, 저장소에서 발견된 시크릿 전면 교체, GitHub에 사용자 데이터가 올라가지 않도록 통제 추가, 실수 업로드를 탐지하는 사전 스캐닝 도입, 규제기관 통지, 대상자에게 신용·다크웹 모니터링 제공.
  • 프레이밍: Meta는 "Meta 제품의 취약점이 아니고 내부 시스템도 침해되지 않았다"며 "GitHub 저장소에 보관된 비즈니스 데이터가 직원 자격증명 도용으로 부적절하게 접근된 사안"이라고 선을 그었다.

4. [사건] OpenAI 임원 회의실 TV 뒤에 도청 장치를 심은 엔지니어 체포 — 조사에 쓴 건 자사 AI 모델

미 법무부(DOJ)는 10월 13일, OpenAI 샌프란시스코 사무실의 임원 회의실에 은닉 녹음 장치를 설치한 혐의로 35세 사우디 국적 엔지니어 Abdulrahman Alfozan을 기소했다고 발표했다. 그는 2025년 7월부터 OpenAI에 근무했고 10월 9일 체포됐다.

  • 발견 경위: 9월 30일 OpenAI 보안 담당자가 임원 회의실 TV 뒤 USB 포트에 꽂힌 녹음 장치를 발견했다. 장치는 화장지에 감싸 숨겨져 있었고 9월 28일경 설치된 것으로 보이며 데이터는 암호화돼 있었다. 10월 5일에는 다른 방에 놓인 가방 안에서 두 번째 유사 장치가 나왔다.
  • 정황: 폐쇄회로 영상에 출입 권한이 없는 회의실 근처를 여러 차례 오가는 모습이 찍혔고, 사내 생산성 도구로 사무실·회의실·임원 위치·회의 일정을 검색한 기록이 있었다. 배우자 명의로 추정되는 챗봇 계정으로 연속 녹음기 제작, Wi-Fi 연결 개조, 실시간 청취 성능 향상, SD카드 암호화를 묻고, 해당 장치의 커스텀 헤더와 MAC 주소까지 프롬프트에 넣은 정황도 담겼다.
  • 기업 대응: OpenAI는 자사 AI 모델로 장치를 분석해 며칠 전 설치한 특정 직원을 특정했다고 밝히고, 해고 후 FBI에 이관했다. 모델 가중치·소스코드·고객 데이터의 부적절한 접근·유출 정황은 현재까지 없다고 덧붙였다. 최대 5년 징역과 25만 달러 벌금이 가능하다.

5. [취약점] SAP 10월 크리티컬 물결 — Cloud SDK for Python CVE-2026-89111 (CVSS 10.0)로 OAuth2 자격증명 탈취

SAP가 10월 13일 보안 공지에서 Cloud SDK for Python의 치명적 결함을 공개했다. 멀티테넌트 BTP 애플리케이션이 SDK에 넘기는 tenant_subdomain 값을 공격자가 제어하면, 애플리케이션의 OAuth2 클라이언트 자격증명이 공격자 서버로 전송된다.

  • 핵심 결함: CVE-2026-89111, SAP 자체 CVSS 10.0. 공지는 0.45.2(2026-08-21)를 수정 버전으로 명시하고, '단순 이름이 아닌 tenant_subdomain을 즉시 거부'하는 검사를 추가했다고 설명한다.
  • 버전 함정(thehackernews 확인): 0.45.2의 검사가 모든 경로에 적용되지 않았다. 0.53.0~0.55.0(9월 10~18일)은 Destination 서비스 모듈 경로에서 검사를 건너뛰었고, 0.55.1(9월 18일)에서 복원됐다. 구 라인인 0.36.1·0.36.2도 검사가 없다. 즉 '0.45.2 이상이면 안전'이라는 단순 판단이 위험하다.
  • 같은 날 SAP 클러스터: S/4HANA(대체·검증 규칙) CVE-2026-89107 9.9, NetWeaver Visual Composer CVE-2026-89110 9.9, MII(제조통합) CVE-2026-89108 9.1, 그리고 권한 경계 미강제 CVE-2026-44415 9.1이 같은 NVD 1일 창에 올라왔다.

6. [취약점] Ghostscript 힙 버퍼 오버플로 CVE-2026-39919 — PDF 하나 업로드되면 서버가 넘어간다

PostScript·PDF 인터프리터인 Ghostscript에서 힙 버퍼 오버플로가 발견됐다. 조작된 PDF는 미리보기·썸네일 생성 경로를 타고 인증 없이 원격 코드 실행까지 이어질 수 있다. Wordfence(Defiant)의 AI 기반 분석 시스템 Argus가 8월 23일 발견했다.

  • 결함: CVE-2026-39919. JPEG 2000 이미지가 들어간 PDF가 저비트 심도 샘플과 구성요소 해상도 불일치를 잘못 처리하게 만들어, 256바이트 버퍼에 1,024바이트를 쓰는 메모리 손상을 일으킨다.
  • 영향 범위: Ghostscript 9.21 ~ 10.07.1. Debian·Ubuntu·Fedora·Alpine·AlmaLinux 등 리눅스 10종과 공식 WordPress 도커 이미지 스냅샷을 테스트한 결과 모두 취약 코드를 포함했다.
  • WordPress 연쇄: PHP Imagick → ImageMagick → Ghostscript 경로로 호출된다. 성공 조건은 4가지 — ① 공격자가 익명 또는 저권한으로 PDF 업로드 가능 ② 사이트가 그 PDF로 미리보기/썸네일 생성 ③ 처리 체인이 Ghostscript까지 도달 ④ 환경에 맞는 페이로드 조정.
  • 현실적 난이도: 연구진은 리눅스 패키지를 대상으로 10,240회 익스플로잇을 시도했지만 RCE에 실패했고, 별도로 만든 테스트 서버에서만 성공했다. 폰트·언어 설정·폰트 구성·핵심 시스템 라이브러리 수정이 필요하며 재현성이 완전하지는 않다. 그럼에도 영향 범위가 넓어 패치가 필수적이다.

9. [트렌드] 'AI 웜'이 다음 공격면 — Anthropic, 소형 모델의 IoT 자기복제 봇넷 경고

Anthropic은 소형 AI 모델이 몇 달 안에 스마트 오븐·무명 안드로이드 TV 박스 같은 IoT 기기에서 자기복제할 능력을 갖출 수 있다고 경고했다. 자율적으로 증식하는 웜 봇넷은 '끌 수 있는 중앙 지점이 없다'는 점에서 대응이 특히 어렵다는 것이 요지다.

  • 왜 위험한가: AI 에이전트가 네트워크를 스캔하고, 익스플로잇을 실행하고, 모델 가중치를 대상 기기로 복사해 감염된 하드웨어에서 직접 추론을 돌리는 것이 이미 개념적으로 입증됐다. 가중치가 곧 악성 페이로드가 되는 구조다. 큰 모델은 여러 기기에 쪼개 분산 추론할 수 있다.
  • 증식 유형 3가지: ① 호스트 침해로 스스로 복제하는 가중치 기반 ② 고연산 데이터센터를 겨냥한 프런티어·오픈웨이트 기반(미탐지 악성 배포) ③ AI 서비스 제공자의 API 키·플랫폼 자격증명을 탈취해 자기 복사본을 돌리는 API 기반(제공자는 정상 고객 요청으로 오인).
  • 실험 근거: Alibaba·DeepSeek·Google·Meta·MoonShot AI·OpenAI·Zhipu AI 등의 오픈웨이트 모델 11종을 대상으로 테스트했고, 스마트 TV 박스 15대에 분산 추론으로 Gemma4-26B-A4B를 돌리는 구성까지 제시했다.
  • 통제 시도: Mozilla는 기업용 Firefox Enterprise 플랫폼으로 브라우저 안의 섀도 AI(shadow AI) 차단을 내걸었고, Meta는 사용자 대신 행동하는 AI 에이전트에 대한 Muse Wonder 안전장치를 공개했다. 규제·통제가 '에이전트 실행 지점'으로 옮겨가는 흐름이다.
