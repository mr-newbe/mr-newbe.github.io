왜 이 논문인가 — "망을 끊었으니 안전하다"의 마지막 구멍

에어갭(air-gap)은 보안의 마지막 카드입니다. 원자력·발전 제어망, 국방, 금융 망분리 PC, 제조 OT — "인터넷이 없다"는 한 줄로 위협 모델의 절반을 잘라냅니다. 그래서 지난 10년간 연구자들은 그 카드를 계속 뒤집어 왔습니다. CPU 부하로 열을 만들고(BitWhisper), 자기장을 흘리고(MAGNETO), 내장 스피커를 초음파로 울리고(MOSQUITO), USB 데이터 버스의 전자기 방사를 잡았습니다(USBee).

고려대학교의 Hyeongjun Choi·Ji Hyuk Jung·Ji Won Yoon이 10월 20일 올린 SPECTER는 그 계보에서 한 칸을 비워둔 자리를 채웁니다. 신호를 싣는 곳이 데이터 선(D+/D−, SuperSpeed 페어)도, USB 데이터 전송(payload)도 아닙니다. 호스트가 USB 전원 관리·장치 상태를 바꾸는 그 동작 자체입니다.

핵심 문장은 이겁니다. "유출할 데이터를 USB 데이터 전송 안에 넣지 않는다." USB 트래픽을 전수 감시하는 DLP도, USB 데이터 캡처 기반 탐지기도, 원리적으로 볼 것이 없습니다 — 관찰 대상은 충전 표시등이 켜졌다 꺼졌다 하는 패턴입니다.

위협 모델 — 이미 뚫린 호스트, 남은 것은 '빼내기'뿐

  • 전제: 망분리·에어갭 환경의 호스트에서 이미 root(Linux) 또는 Administrator(Windows) 권한을 얻은 상태. 초기 침투·권한 상승·지속성은 논문 범위 밖입니다(감염 매체, 공급망, 내부자).
  • 환경 조건: 네트워크 egress는 없거나 강하게 제한되지만, USB 충전이나 주변기기 연결은 허용되는 곳. 실제로 대부분의 망분리 PC가 그렇습니다 — 개인 스마트폰 충전, USB 마우스, 허브.
  • 목표: 대용량 파일이 아닙니다. 짧고 값비싼 비밀 — 암호화 키, 자격증명, 인증 토큰. 저자들이 명시적으로 "short secrets"라고 못 박습니다.
  • 은닉성에 대한 정직한 구분: 논문은 "전송 능력"과 "그 동작을 들키지 않는 능력"을 분리합니다. 제어 동작은 USB 알림, 충전 표시, LED 변화, 주변기기 순단을 일으킬 수 있습니다. 따라서 공격자는 아무도 보지 않는 시간(야간 무인 운영 등)이라는 전송 기회를 필요로 합니다.

메커니즘 — 5초에 1비트, '전원 상태'를 스위치로 쓴다

송신기는 두 플랫폼에서 각각 다른 프리미티브를 씁니다. 둘 다 관리자 권한이 필요한, 그러나 지극히 정상적인 OS 기능입니다.

플랫폼제어 수단동작
Ubuntu 22.04sysfs 전원 관리 속성power/control = on(활성) / auto(커널이 유휴 장치 서스펜드 허용) · iOS 분기는 autosuspend_delay_ms를 2000 ↔ 0으로 함께 변경
Windows 10DevCon 장치 상태 명령devcon disable "<HWID>" / devcon enable "<HWID>" — enable을 두 번 호출해야 상태가 안정적으로 복구됨(실측)
  • 상태 기반 부호화(충전·주변기기 경로): 비트 1 = 활성 상태, 비트 0 = 비활성 상태. 같은 비트가 연속되면 상태를 유지합니다.
  • 이벤트 기반 부호화(RF 경로): 심볼 구간 안에서 USB 상태 변경이 한 번 일어나면 1, 없으면 0. 버스트의 유무만 봅니다.
  • 심볼 간격: Linux 스마트폰 분기 5초, Windows 분기 1초 대기. 이 값이 그대로 비트레이트 상한을 만듭니다 — 5초면 0.2 bit/s, 1초면 1.0 bit/s.
  • 패킷 구조(프레이밍 사용 시): 프리앰블 101011 → 페이로드 길이 헤더 → 페이로드 → CRC → 트레일러(1). RF 경로는 짧은 프리앰블 101. ACK도, 재전송도 없습니다 — 단방향, 손실 감수.
  • 중요한 뉘앙스: power/control=auto는 "VBUS를 물리적으로 뽑았다"는 뜻이 아닙니다. 실제 관찰 가능한 변화는 호스트 컨트롤러·허브·드라이버·연결된 장치의 조합에 달려 있고, 논문도 이 점을 반복해서 못 박습니다. 즉 이 채널은 "USB 전력 규격의 결함"이 아니라 "전원 상태를 바꾸는 OS 기능이 만들어내는 관찰 가능한 부수 효과"입니다.

수신 경로 세 갈래 — 폰, 눈, 그리고 SDR

  • ① 충전 상태 수신기 (스마트폰): 감염 호스트에 충전을 위해 연결된 폰이 수신기입니다. Android 구현은 일반 사용자 앱이 1초 간격으로 배터리 상태를 6회 샘플링해 비트를 해독합니다 — root도, 펌웨어 수정도, OS 수정도 필요 없습니다. iOS는 화면의 충전 표시를 사람이 육안으로 읽는 방식(실험실 조건).
  • ② 주변기기 상태 수신기 (눈/카메라): 순정 USB 마우스·웹캠·허브의 겉으로 보이는 변화를 관찰합니다. 악성코드도, 변조 펌웨어도 필요 없습니다. 대신 시선(line of sight)이 필요합니다 — 옆자리 사람, 복도 CCTV.
  • ③ 근접 RF 수신기 (SDR): HackRF One + LF-R 400 루프 안테나를 USB 케이블에 직접 접촉시켜, 약 5 MHz 부근의 스위칭성 버스트를 관찰합니다. 샘플링 2.6 MS/s, STFT 8192 샘플, 0주파수 빈의 크기를 정규화해 시간축 트레이스로 만듭니다.

실측 결과 — 표 두 줄이 이 논문의 전부다

N/O = 해당 조합에서 사용 가능한 채널을 얻지 못함. Ubuntu 데스크톱에서는 테스트한 모든 주변기기가 실패했습니다 — 즉 이 채널은 "호스트 + 장치 + 수신 경로의 조합"에 극단적으로 의존합니다. 저자들이 이 사실을 숨기지 않고 표에 그대로 남긴 점이 오히려 신뢰를 높입니다.

  • 1.0 bit/s가 실전에서 무슨 뜻인가: 256비트(AES-256 키)를 보내는 데 약 4분 16초. 0.2 bit/s라면 약 21분입니다. 느립니다. 그러나 "야간에 아무도 없는 사무실"이라는 시간 예산에서는 충분합니다.
  • RF 경로의 실증: 6비트 시퀀스 110101과 48비트 페이로드 모두, 전송 시퀀스와 복호 시퀀스가 일치했습니다. 단 — 케이블에 안테나를 밀착시킨 조건이고, 짧은 노이즈 버스트가 섞인 사례도 있었습니다.
  • 채널 비교(Table 1)에서 SPECTER의 자리: USBee 160~640 bit/s(USB 데이터 버스 RF), 스피커 10~166 bit/s, PowerHammer 10/1000 bit/s, CovertPower 최대 10 bit/s. SPECTER는 0.2~1.0 bit/s로 이들 중 가장 느리지만, 표에서 부하 변조(load modulation)도, USB 데이터 부호화도 하지 않는 유일한 항목입니다. 느린 대신 데이터 경로에 아무 흔적을 남기지 않는다는 것이 이 논문의 거래입니다.

어디까지 믿어야 하나 — 저자들이 스스로 깎은 주장

이 논문은 최근 유행하는 "AI가 다 뚫었다"류와 정반대의 태도로 쓰였습니다. 실험실 규모의 사실만 남기고 나머지를 명시적으로 비워둡니다.

  • 비트 오류율(BER)·패킷 오류율·실효 처리량을 측정하지 않았습니다. 관찰된 예시에서 오류가 없었다는 사실은 "채널 전체의 오류율이 낮다"는 증거가 아니라고 직접 씁니다.
  • 거리·각도·환경 견고성 미평가: RF는 안테나를 케이블에 접촉한 구성만 측정. "접촉 프로브 조건"이라는 단서를 붙입니다.
  • 재현성의 경계: 통제된 실험실, 연구자 소유 장치, 선택된 소수의 호스트·주변기기. 다른 컨트롤러/드라이버/허브로 일반화되지 않을 수 있음.
  • 탐지 가능성은 구성 의존: 어떤 조합에서는 충전 표시가 보이고 화면이 깜빡였고, 완충 상태에서는 아무 표시도 없었습니다. 후자를 "일반적으로 은닉성이 높다"로 확대 해석하지 말라고 선을 긋습니다.
  • 방어 평가 없음: 탐지기·속도 제한 정책·임계값을 검증하지 않았습니다. 제안은 "후보 방어"일 뿐입니다.

방어 — USB '데이터' 감시로는 안 잡힌다

  • USB 전원 관리·장치 상태 이벤트를 보안 텔레메트리로 승격. 논문의 1순위 제안입니다. 같은 장치에 대한 enable/disable/suspend/resume의 반복을 감사하고, 애플리케이션 활동·충전 상태 관찰과 상관 분석합니다.
  • 정상 동작과의 구분이 과제: 절전, 재연결, 드라이버 재설정도 같은 이벤트를 만듭니다. 그래서 "이벤트 1회"가 아니라 주기성·반복성·시간 규칙성을 특징(feature)으로 삼아야 합니다.
  • 정책 계층: 소프트웨어에 의한 USB 상태 변경 제한, 미사용 포트 비활성, 장치 허용목록, 민감 호스트 주변의 개인 스마트폰 반입 제한.
  • 역설 — 그리고 가장 중요한 문장: "장치 연결을 허용하는 것만으로는 이 채널을 막지 못한다." 공격은 순정 마우스로도 성립하기 때문입니다. 또한 root 권한을 이미 내준 상태에서는 호스트 기반 감시 자체를 신뢰할 수 없습니다. 즉 이 방어는 침투 이후가 아니라 침투 이전의 통제(매체 통제, 권한 최소화)와 함께 놓여야 의미가 있습니다.

교육용 PoC — 채널을 '만들지' 않고 '탐지'하는 쪽을 짜본다

아래 코드는 실제 하드웨어를 제어하지 않습니다. 로컬 로그 시뮬레이션입니다. (1) 상태 기반 부호화로 비트열이 어떤 이벤트 시퀀스가 되는지 만들고, (2) 그 시퀀스를 방어자 입장에서 "주기적 상태 변경" 패턴으로 탐지합니다. 목적은 탐지 규칙의 취약점을 이해하는 것입니다 — 임계값을 조금만 올리면 공격은 그대로 두고 오탐만 사라집니다.

import statistics

# 1) 상태 기반 부호화: bit1 = 활성(on), bit0 = 비활성(auto)
def encode(bits, period=5.0):
    t, events = 0.0, []
    state = None
    for b in bits:
        new = "on" if b == 1 else "auto"
        if new != state:                    # 상태가 바뀔 때만 실제 이벤트 발생
            events.append((round(t, 1), new))
            state = new
        t += period
    return events

secret = [int(c) for c in "10110011"]        # 교육용 8비트
ev = encode(secret, period=5.0)
print(ev)

# 2) 방어자 측 휴리스틱: '같은 장치의 상태 변경 간격이 규칙적인가'
def detect(events, min_events=5, cv_threshold=0.15):
    if len(events) < min_events:
        return "PASS (이벤트 부족)"
    gaps = [b[0] - a[0] for a, b in zip(events, events[1:])]
    cv = statistics.pstdev(gaps) / statistics.mean(gaps)   # 변동계수
    return ("ALERT: 주기적 USB 상태 변경 (간격 CV=%.2f)" % cv) if cv < cv_threshold else "PASS"

print(detect(ev))
print(detect([(0,"auto"),(37,"on"),(51,"auto"),(180,"on"),(181,"auto")]))  # 정상 재연결
  • 연속된 같은 비트는 이벤트를 만들지 않습니다. 10110011은 8비트지만 실제 상태 변화는 5회입니다 — 방어자는 "이벤트 개수 ≠ 비트 개수"라는 사실을 먼저 알아야 합니다.
  • 탐지기의 진짜 약점은 임계값입니다. cv_threshold를 0.05로 조이면 정상 절전 패턴까지 잡고, 0.3으로 풀면 공격이 통과합니다. 논문이 "탐지기를 검증하지 않았다"고 말한 이유가 여기 있습니다.
  • 실습 과제: 정상 트래픽(절전·재연결·도킹/언도킹) 로그를 섞어 오탐률을 재보세요. 그리고 비트 0을 '이벤트 없음'으로 보내는 RF 방식으로 바꾸면 이 탐지기가 통째로 무력화된다는 것도 확인해 보세요.

그래서 무엇이 남는가

  • "데이터 경로를 감시한다"는 보안 가정이 좁다. USB는 데이터 선과 전원 선, 그리고 상태 기계로 이루어집니다. 우리는 앞의 둘은 봤지만 세 번째는 텔레메트리로 취급하지 않았습니다. 이 논문의 실제 기여는 속도(0.2~1.0 bit/s)가 아니라 관찰 대상의 재정의입니다.
  • 속도가 느린 채널도 '키'에는 충분히 빠르다. 1 bit/s로 4분이면 AES-256 키 하나입니다. 에어갭 유출 연구에서 비트레이트는 "파일 유출" 기준으로 평가되지만, 위협은 비밀 하나로 끝나는 경우가 많습니다.
  • 토폴로지가 곧 공격면이다. Ubuntu 데스크톱에서는 주변기기 경로가 전부 실패하고 Windows 노트북에서만 성공했습니다. 같은 "USB"라도 호스트 컨트롤러·허브·드라이버에 따라 결과가 갈립니다 — 자산 관리 문서에 포트 토폴로지가 들어가야 하는 이유입니다.
  • 한국 실무 관점: 망분리 PC에 개인 스마트폰을 충전용으로 꽂는 관행, 무인 야간 운영되는 제어망 단말, "USB 데이터만 막으면 된다"는 매체 통제 정책 — 이 세 가지가 이 논문의 직접적인 표적입니다. 충전 허용 = 관찰 가능한 상태 변화 노출입니다.
  • 연구 윤리: 모든 실험은 연구자 소유 장치, 격리된 실험실, 네트워크 비연결. 아티팩트는 MIT로 공개됐지만 송신기는 장치 식별자를 명시적으로 설정해야만 동작하도록 안전장치를 뒀습니다.
