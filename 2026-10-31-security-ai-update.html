1. Cursor 마켓플레이스의 '진짜' Claude Code 확장이 위·변조됐다 — SSH 백도어·역터널

Anthropic 공식 Claude Code VS Code 확장이 Cursor 마켓플레이스를 통해 위·변조된 채 배포됐다. 문제의 버전은 2.1.313으로, 가짜 확장이 아니라 정품 확장 ID(anthropic.claude-code)를 그대로 사용한 '정상 업데이트' 형태였다. Cursor는 10월 29일 약 11시간 노출됐고 영향 사용자는 최대 5,000명이라고 밝혔다. 현재 악성 버전은 제거됐고 Anthropic은 2.1.314를 Open VSX·마이크로소프트 마켓플레이스에 배포했다.

  • 페이로드: 정품 JS 번들 앞에 66줄 로더가 삽입됐다. VS Code 시작 및 웹뷰가 열릴 때 동작해 ~/.ssh/authorized_keys에 공격자 키를 추가한다. 키 이름은 "svc-telemetry"로 위장했다.
  • 지속성·통신: SSH 활성화를 시도한 뒤 134.209.82[.]225로 역터널을 열고, 예약 작업·crontab·LaunchAgent로 지속성을 심는다. 정찰 데이터는 134.209.82[.]225:8099/beacon으로 암호화되지 않은 HTTP로 전송된다.
  • 수집 항목: 공인 IP, 호스트명·로컬 계정, OS·CPU 아키텍처, 홈·작업 디렉터리, git config --global user.email, 그리고 이름에 KEY·TOKEN·SECRET·PASS·AWS·GCP가 들어간 최대 40개 환경변수의 '이름'. 값은 초기 비콘에 담기지 않지만, 이름만으로 어떤 클라우드·CI·자격증명 체계가 붙어 있는지 드러난다.
  • 핵심 교훈: Cursor의 "Anthropic이 만든 버전이 아니다"라는 해명은 초점이 빗나간다. 침해 지점은 정품 게시자 신원과 정품 확장 ID였고, 그래서 사용자는 검증할 방법이 없었다. macOS·Windows에서는 SSH 서비스 활성화에 관리자 권한이 필요해 터널 로그인까지 이어지지 않은 경우가 많지만, 공격자 키 등록·지속성·정찰 전송은 권한 없이도 성공한다.
  • 즉시 조치: Claude Code를 Cursor에서 설치했다면 ~/.ssh/authorized_keys의 svc-telemetry 항목 삭제, 확장 버전 확인(2.1.314 이상), 예약 작업·crontab·LaunchAgent에 낯선 항목 점검, 환경변수에 있던 토큰 전부 로테이션.

2. Trezor 지갑에서 '휴대폰 회선으로 시드 전송' 하드웨어 임플란트 발견

Trezor가 CryptoBilis에서 판매된 Trezor Safe 5 한 대에서 추가 회로 기판이 발견됐다고 경고했다. 인도네시아 사용자가 토코페디아(Tokopedia)를 통해 8월에 구매한 제품으로, 기판은 메인보드와 화면 사이에 들어가 셀룰러 모듈과 안테나를 갖췄다. 화면을 읽어 복구 시드(recovery phrase)를 빼내고, 기기가 전원에 연결될 때마다 외부로 전송하는 구조다.

  • 경고 범위: Trezor는 아직 기기를 직접 검사하지 못했지만, 실험실 확인을 기다리는 동안 구매자를 방치할 수 없다며 2026년 3월 이후 CryptoBilis가 공급한 모든 Trezor(토코페디아 등 하위 판매처 포함) 구매자에게 즉시 자금 이동을 권고했다.
  • 중요한 함정: 기존 시드를 다른 기기에 복원하는 것으로는 해결되지 않는다. 변조된 지갑이 이미 시드를 전송했을 수 있기 때문이다. 반드시 새 지갑 + 새 시드로 옮겨야 하며, 아직 설정하지 않은 기기는 설정하지 말고 기존 시드를 절대 입력하면 안 된다.
  • Ledger 연쇄: Trezor는 10월 9일 동남아 공식 리셀러 CryptoBilis를 해지했다. 그 전에 Ledger가 CryptoBilis 구매자들의 자산 유실을 조사하면서 시작됐고, Ledger는 한 피해자 지갑에서 설정 단계의 시드를 가로채는 무단 하드웨어 임플란트를 확인했다고 밝혔다.
  • 싱가포르 경찰 권고: 10월 28일 싱가포르 경찰은 일부 소매점에서 판매된 Ledger 지갑에 악성 하드웨어 부품이 들어 있었다고 발표했다. 9월 10일 이후 최소 2건이 신고됐다.
  • 사용자 점검의 한계: Trezor는 사용자가 자체적으로 임플란트를 판별할 수 없으며, 무게를 재거나 기기를 열어보지 말라고 당부했다. 피해자는 무게 차이를 눈치챘지만 무게 차이는 다른 원인으로도 생긴다.
  • 추가 위험: Trezor는 이 사건을 악용한 가짜 이메일·우편·전화 피싱을 예상한다고 밝혔다. 지원센터를 사칭해 시드를 요구하는 연락은 100% 사기다.

3. 플로리다 교육부 침해 — 재정지원 신청자 490만 명, 주민번호 포함

미국 플로리다주 교육부(FDOE)가 학자금·재정지원 웹사이트 FloridaStudentFinancialAidSG.org에 대한 무단 침해를 공지했다. 영향 범위는 약 490만 명이며, 유출 항목에 사회보장번호(SSN)가 포함된다. FDOE는 10월 19일 침해를 인지했고 10월 29일 공식 발표했다.

  • 기관 설명: "범죄적 무단 접근"으로 규정하고 있으며, 재정지원 지급 지연이나 장학금·보조금·학자금 대출 자격에는 영향이 없다고 밝혔다. 그러나 SSN 유출은 수년 후까지 재사용되는 신원 사기 원료이므로 기관의 '서비스 정상' 안내와 별개로 개인 조치가 필요하다.
  • 플로리다 연쇄: 앞서 플로리다 당국은 운전면허 정보 유출 사건도 확인했다. 주(州) 단위 시스템이 연속으로 뚫리면서 '주 행정망 = 단일 실패점'이라는 구조적 문제가 드러났다.
  • 피해자 조치: ① 3대 신용평가사 신용동결(credit freeze) ② IRS 신분보호 PIN 발급(세금 환급 사기 차단) ③ 플로리다 실업수당 사기 신청 모니터링 ④ FDOE가 안내한 무료 신용모니터링 등록. 신청 이력이 있다면 본인 정보가 포함됐다고 가정하는 편이 안전하다.
  • 맥락: 같은 주에 미국 국토안보부(DHS) 직원 4만여 명 정보 노출, 법무법인 Baker McKenzie·Troutman 침해 등 연방·민간 대형 유출이 겹쳤다. 10월 하순은 '유출 신고 폭주' 구간이었다.

4. 코펜하겐대 침해 — 52만 5,000명 주민번호, 직원·학생 2만 명 카드 PIN까지

덴마크 코펜하겐대학교는 침해자가 테스트 환경에 접근해 재학생·졸업생·교직원 약 52만 5,000명의 개인정보를 확보했다고 밝혔다. 침해는 10월 20일 탐지 후 차단됐으며, 공격자와 동기는 아직 확인되지 않았다.

  • 유출 항목: 이름, 전화번호, 개인 이메일, 그리고 상당수에 대해 덴마크 주민등록번호(CPR). CPR은 덴마크에서 금융·의료·정부 서비스 전반의 신원 키로 쓰여 비밀번호 재설정 공격의 기반이 된다.
  • 가장 심각한 항목: 교직원·학생 약 2만 명의 신분증 카드 PIN이 유출돼 전원 재발급됐다. PIN은 물리 출입·프린터·건물 접근에 쓰이므로, 재발급 전 구간이 물리 보안 공백이 된다.
  • 구조적 교훈: '테스트 환경'이 운영 데이터의 사본을 들고 있으면 그것은 더 이상 테스트 환경이 아니다. 익명화·마스킹 없이 운영 데이터를 복제한 스테이징은 보안 등급이 가장 낮은 곳에 가장 민감한 데이터를 두는 구성이다.

5. 미 연방선거위원회(FEC), 전자신고 시스템 침해 시도로 중간선거 직전 오프라인

미국 연방선거위원회(FEC)가 전자신고 시스템에 대한 침해 시도 이후 시스템을 내렸다. 로이터가 입수한 내부 메일에 따르면 이 조치는 11월 3일 중간선거를 일주일 앞둔 시점이었고, 정치 단체들은 24시간·48시간 긴급 지출 신고를 제출할 수 없게 됐다. 과거 신고 내역은 계속 검색 가능했고 시스템은 10월 28일 복구됐다.

  • 왜 중요한가: 24·48시간 신고는 선거 직전 막판 지출의 실시간 추적 장치다. 이 창구가 며칠 닫히면 유권자가 후보별 막판 자금 흐름을 볼 수 있는 시간이 그만큼 사라진다.
  • 공격 성격: 현재까지 확인된 것은 '침해 시도'이며 데이터 유출이나 표 집계 시스템 침해는 보고되지 않았다. 미국 선거 인프라는 투표기(집계)와 행정·신고 시스템(공개)이 분리돼 있어, 신고 시스템 장애가 곧 투표 무결성 훼손은 아니다.
  • 실무 시사점: 선거·공공 마감일이 걸린 시스템은 '의심 시 즉시 차단' 런북과 오프라인 대체 제출 경로를 함께 준비해야 한다. 가용성을 지키려고 침해 의심 시스템을 켜두는 선택은 대개 더 큰 비용으로 돌아온다.

6. Drupal Commerce Core CVE-2026-118539 — 실제 악용 중, 4만 2,000개 사이트가 영향권

Drupal 보안팀이 Commerce Core 모듈의 권한 누락(access bypass) 취약점 CVE-2026-118539가 실제 공격에 악용 중이라고 경고했다. 인증 없이 악용 가능하며, 영향 버전은 0.0.0 ~ 2.41과 3.0.0 ~ 3.3.13이다.

  • 패치: 3.x 계열은 Commerce Core 3.3.13으로, 구 버전 계열은 8.x-2.41로 즉시 업그레이드해야 한다. Drupal은 패치와 함께 주문(orders) 데이터의 불일치 감사를 권고했다 — 이미 침해가 발생했을 수 있다는 뜻이다.
  • 영향 규모: Commerce Core는 4만 2,000개 이상 웹사이트가 사용하는 커뮤니티 모듈로, 포춘500 기업과 연구 대학 다수가 포함된다. Drupal은 이 취약점을 "highly critical"로 분류했다. NVD에는 아직 CVSS 점수가 없다(N/A).
  • 공격 표면: "모듈이 특정 라우트와 엔티티 필드를 충분히 보호하지 못해 접근 우회가 발생하며, 판매자의 재정적 영향으로 이어질 수 있다"는 설명대로 주문·결제·할인 로직이 직접 표적이다. 즉 가용성 사고가 아니라 매출 사고다.
  • Drupal 연쇄 이력: 5월 SQL 인젝션 CVE-2026-9082(CISA KEV 등재, 연방기관 3일 내 패치 명령), 2주 전 원격 코드 실행 CVE-2026-108097·108099 긴급 패치에 이어 또 한 번 실사용 악용이다. CISA가 지난 수년간 Drupal 취약점을 5건 KEV에 올렸고 그중 2건은 랜섬웨어 조직이 악용했다.
  • 점검: drush pm:list --filter=commerce --status=enabled로 사용 여부 확인 → 즉시 업그레이드 → 최근 주문 로그에서 비정상 상태 변경·가격 0원 주문·비정상 계정 생성 탐색. 커머스 사이트는 WAF에 /checkout/*, /cart/* 비정상 접근 임시 차단 룰을 병행하는 편이 안전하다.

7. jackson-databind CVE-2026-110879 (CVSS 9.8) — 직전 패치를 우회하는 두 번째 탈출구

자바 생태계의 사실상 표준 JSON 라이브러리 jackson-databind에 CVSS 9.8 취약점 CVE-2026-110879가 공개됐다. 핵심은 직전 취약점(CVE-2026-54512) 수정을 우회한다는 점이다. 앞선 패치는 다형성 역직렬화의 PolymorphicTypeValidator(PTV)가 제네릭 인자까지 검증하도록 고쳤는데, 이번 건은 그 검증이 배열 요소 타입과 중첩 제네릭에서 여전히 비어 있음을 찌른다.

  • 공격 원리: 타입 ID 문자열에 <가 들어 있으면 컨테이너의 원시 클래스 이름만 PTV로 검사하고, <...> 안의 클래스는 검증 없이 Class.forName()으로 로드·인스턴스화한다. 즉 java.util.ArrayList만 허용된 설정에서 java.util.ArrayList<com.evil.Gadget>를 보내면 컨테이너는 통과, 가젯은 실행된다.
  • 영향 버전 → 수정 버전: 2.10.0~2.18.11 → 2.18.12 / 2.19.0~2.21.7 → 2.21.8 / 2.22.0~2.22.3 → 2.22.4 / 3.0.0~3.1.7 → 3.1.8 / 3.2.0~3.2.3 → 3.2.4.
  • 노출 경로: Jackson 3.x 기본 JsonMapper의 애노테이션 기반 클래스명 다형성, 2.x·3.x의 enableDefaultTyping 설정, 그리고 그 기본 타이핑을 외부에 노출하는 프레임워크 연동(Spring·Kafka 등) 전부. 벡터는 AV:N/AC:L/PR:N/UI:N — 네트워크에서 인증 없이 단일 요청으로 도달 가능하다.
  • 2차 방어: 버전 업그레이드만으로 끝내지 말 것. ① 다형성 타이핑이 정말 필요한 엔드포인트인지 재검토 ② BasicPolymorphicTypeValidator 허용 목록을 중첩 타입까지 닫는 커스텀 검증기로 교체 ③ 역직렬화를 수행하는 서비스의 아웃바운드 이그레스 제한(가젯 체인의 최종 단계는 대개 외부 연결이다) ④ 최근 몇 주간 두 번 연속 우회가 나왔으므로 Jackson 보안 공지 구독을 필수로.

10. Cloudflare Workers AI, KV 캐시 교차 테넌트 유출 — SGLang 0.5.22 이상으로

Cloudflare가 자사 Workers AI에서 다른 고객의 요청 데이터가 응답에 섞여 나온 사고를 공개했다. 기간은 8월 27일 ~ 9월 9일, 모델은 GLM 5.3, 해당 응답은 155건이며 모두 68만 1,280 토큰을 넘는 초장문 프롬프트였다.

  • 원인 2가지의 결합: ① 설정 불일치로 모델의 KV 캐시가 광고된 컨텍스트 윈도보다 작게 잡혀 있었고 ② 추론 엔진 SGLang의 버그로 길이 초과 요청이 이전 세션이 남긴 캐시를 읽을 수 있었다. 즉 '메모리 재사용 최적화'가 '다른 고객 데이터 열람'이 됐다.
  • 대응: Knostic의 Gadi Evron이 HackerOne으로 제보했고 Cloudflare가 수정했다. 의도적 악용 정황은 없었다고 밝혔다. SGLang 운영자는 0.5.22 이상으로 올려야 한다.
  • 실무 교훈(셀프호스팅 LLM): vLLM·SGLang 같은 멀티테넌트 서빙에서 캐시는 곧 메모리 공유다. ① max_model_len과 KV 캐시 크기를 설정 검증 단계에서 강제 일치 ② 테넌트별 캐시 격리 옵션 확인 ③ 초장문 입력은 별도 큐·별도 워커로 분리 ④ 업그레이드 노트에서 캐시·격리 관련 수정을 최우선으로 읽기.
  • 왜 이 사고가 중요한가: 클라우드 LLM의 유출 사고는 대개 '프롬프트 인젝션'으로 설명되지만, 이번 건은 모델도 프롬프트도 아닌 인프라 계층의 결함이었다. AI 서비스의 데이터 경계는 앱이 아니라 추론 엔진과 캐시 설정에 있다.

11. 트렌드 ①: 'AI 봇' 32종을 갈아입은 스캐너가 .env·SSH 키를 훑는다

Cequence는 단일 공격자가 OpenAI·Anthropic·메타·퍼플렉시티의 크롤러·어시스턴트를 사칭한 약 32개의 AI 봇 아이덴티티를 순환하며 웹사이트를 스캔하는 활동을 추적했다. 표적은 .env 파일, 클라우드 자격증명, 개인 SSH 키처럼 비밀이 들어 있기로 유명한 경로다.

  • 규모: 최소 9월 말부터 대형 클라우드 제공자에서 동작했고, 하루에 300개 이상의 IP를 사용했다. 10월의 어느 하루에는 AI 봇 트래픽이 관측된 Cequence 보호 조직의 48%에 도달했다.
  • 가장 위험한 신호: 일부 조직에서는 'AI 봇'으로 라벨된 트래픽의 80% 이상이 이 사칭 주체였다. 즉 User-Agent 기반 허용 목록은 이미 무의미하다.
  • 방어: ① AI 봇 허용은 User-Agent가 아니라 게시된 IP 대역/역DNS 검증으로 ② WAF에서 /.env, /.git/config, /.aws/credentials, /id_rsa 요청을 차단(404 위장 아님, 차단) ③ 저장소 전체 시크릿 스캔과 카나리 .env(가짜 키 유출 감지) 병행 ④ 스캔이 곧 정찰이므로, 스캔을 받은 호스트의 아웃바운드 로그를 함께 본다.
  • 연결점: 오늘 1번(Cursor 확장 변조)과 같은 흐름이다. AI 도구의 '신뢰 표식'(게시자·봇 이름·모델명)이 위조 가능한 값이 되면서, 신뢰 판단의 근거가 브랜드에서 검증 가능한 신호로 옮겨가고 있다.

12. 트렌드 ②: AI가 랜섬웨어·C2·회색시장 도구의 '운영 인력'이 됐다

이번 주 발표된 세 건은 AI가 공격의 보조 도구를 넘어 실행 주체가 됐음을 보여준다.

  • Aur0ra 랜섬웨어(Gold Ogre): Sophos에 따르면 이 그룹은 Cursor로 오케스트레이션한 AI 에이전트에 네트워크 탐색, 자격증명 공격, 측면 이동을 맡겼다. 사람의 개입은 제한적이었고, 운영자들은 침해를 "승인된 레드팀 활동"으로 서술해 가드레일을 우회했다.
  • NIK C2(Cisco Talos): AI가 통합된 신규 C2 프레임워크. Windows 임플란트가 자격증명 탈취, 키스트로크 스트리밍, 화면 잠금형 랜섬웨어 배포까지 수행한다.
  • Codex·Claude Code '릴레이' 회색시장(Symantec·Carbon Black): 중국 본토 중심 12개 조직에서 관측됐다. 정품 Codex·Claude Code CLI를 설치한 뒤 모든 요청을 샌드박스가 꺼진 서드파티 서버로 라우팅하도록 재구성하는 서비스다. 정품 도구를 쓰기 때문에 탐지가 어렵고, 코드·프롬프트가 전부 제3자에게 흘러간다.
  • 공통 패턴: ① 정품·정식 채널을 그대로 사용(1번 Cursor 사건과 동일) ② 가드레일을 '정당한 작업'으로 우회 ③ 사람은 방향만 정하고 실행은 에이전트가 담당. 방어 관점에서는 에이전트가 쓰는 자격증명의 권한 최소화와 에이전트 아웃바운드 목적지 고정이 가장 효과적인 통제가 된다.
  • 개인 실무 체크: 코딩 에이전트(Codex·Claude Code·Cursor) 실행 환경에서 ① ~/.ssh·~/.aws·.env를 에이전트 작업 디렉터리에서 분리 ② 에이전트 전용 API 키 사용·주기적 로테이션 ③ 에이전트가 설치한 확장·플러그인의 게시자와 버전 고정(pin) ④ 샌드박스/--sandbox 옵션을 끄는 설정 금지.
